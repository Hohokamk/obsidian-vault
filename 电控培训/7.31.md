## 3. 核心机制设计要点说明

在编写代码或配置此系统时，需要特别关注以下关键逻辑：

### ① CPU 抢占（Preemption）机制

- FreeRTOS 开启 `#define configUSE_PREEMPTION 1`。
    
- **高优先级抢占**：`Motor_PID_Task` (Prio 5) 处于 `vTaskDelay(10)` 阻塞状态时，CPU 让给低优先级的 `LED_Water_Task` (Prio 1) 运行。10 ms 定时时间一到，`Motor_PID_Task` 立即**抢占** CPU，流水灯任务被迫暂停，直到 PID 计算结束。
    

### ② 任务挂起（Suspend）与恢复（Resume）

- **场景应用**：当状态机（FSM）检测到 CAN 通信超时或电机过载（`SYSTEM_ERROR` 状态）时：
    
    - 调用 `vTaskSuspend(xMotorTaskHandle)` 立即暂停电机计算与 PWM 控制。
        
    - 调用 `vTaskSuspend(xLEDTaskHandle)` 暂停流水灯，改为亮红灯告警。
        
- 当接收到串口修复指令或故障排除后：
    
    - 调用 `vTaskResume(xMotorTaskHandle)` 恢复任务，任务从当时挂起的代码断点继续向下执行。
        

### ③ CAN 通信与 PID 控制闭环

- **中断接收**：CAN 接收中断触发，将编码器反馈数据写入 `CAN_Rx_Queue` 并释放信号量。
    
- **周期控制**：`Motor_PID_Task` 被 10 ms 周期唤醒，从队列获取最新的转速反馈，运行 PID 算法计算出新的 PWM 控制量，并通过 CAN 发送给电调/驱动器。
    

### ④ 打印 TaskList 数据

在 FreeRTOS 中使用 `vTaskList()` 打印任务状态，需要在 `FreeRTOSConfig.h` 中使能以下宏：

C

```
#define configUSE_TRACE_FACILITY          1
#define configUSE_STATS_FORMATTING_FUNCTIONS 1
```

当系统收到打印指令时，输出格式如下（清晰展示各任务状态、抢占优先级和栈深度）：

Plaintext

```
Task Name       State   Prio    Stack   Num
-------------------------------------------
Motor_PID       R       5       128     1   (R: Ready/Running)
FSM_Task        B       4       256     2   (B: Blocked)
CAN_Task        B       3       256     3
USART_Task      B       2       512     4
LED_Water       B       1       128     5
Sys_Monitor     B       1       512     6
```

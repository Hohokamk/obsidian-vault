## 今天的核心：从误差到电机，中间有五道工序

### 第一道：算误差（口径要对齐）

```cpp
const float perr = xuc.aim_pitch_target - imu_pantile.GetAnglePitch() * DEG2RAD;   // RC.cpp:150
```

目标值 `aim_pitch_target` 是 rad（协议规定下行直接给 rad），而 `GetAnglePitch()` 返回 deg，所以乘 `DEG2RAD` 换算。这就是协议文档里“单位全用 rad”的理由：换算只在边缘发生一次，闭环内部全是 rad。忘了这一乘，误差会被放大 57.3 倍。

### 第二道：死区

```cpp
const float DB = 0.3f * PI / 180.f;    // RC.cpp:137，0.3 度
if (fabsf(perr) > DB) ...
```

误差不够大就一动不动，防止目标附近的来回抖。

### 第三道：小步逼近（外环）

```cpp
ctrl.pantile.mark_pitch += KP * perr;   // KP = 0.25，RC.cpp:144,152
```

每一步只走误差的 25%，不是一步到位。为什么不敢大步：执行器自己还有位置环（M6020 POS 的 Kp=5），外环只做小步逼近就够（`RC.cpp:141-143` 注释）。一路链上有三层：外环小步、限位、电机内环。

### 第四道：单位换算（yaw 这条链）

M6020 的位置环吃编码值，所以误差要换成编码增量：

```text
误差 rad -> 乘 KY(0.25) -> 乘 RAD2CNT(8192/2π) -> 加到 setangle
```

`RC.cpp:139` 的 `RAD2CNT = 8192.f / (2.f * PI)` 就是 rad 到编码值的换算系数。

### 第五道：取最短路径

```cpp
const float yerr = XUC::WrapPi(xuc.aim_yaw_target - imu_pantile.GetAngleYaw() * DEG2RAD);  // RC.cpp:157
```

目标在加减 π 边界时，直接相减会得到接近 2π 的“绕远路”误差，`WrapPi` 把它压回负 π 到 π，云台永远走近路。

### 摩擦轮和开火是另一套逻辑

`RC.cpp:161-163`：摩擦轮和拨弹只看许可位（`openRub`、`auto_shoot`），不做角度闭环——到速判据在 `control.cpp` 的拨弹保护里，和云台解耦。

### 这套结构的通用名字

外环（角度闭环，慢、粗、5 ms 一拍）+ 内环（电机位置环，快、细）就是伺服系统的标准双环结构。今天在哨兵代码里看到的每一行，对应的是通用模式，换到任何一个伺服项目都成立。

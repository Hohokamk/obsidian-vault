# 王同学大创项目三周突击学习计划

> **目标**：在开学前掌握项目所需的 Python 上位机控制、自动化测试与阵列仿真核心技能，能够独立跑通“配置 -> 控制 -> 仿真”的最小闭环。  
> **原则**：急用先学，以战代练，坚决不学无关技术（如前端、复杂C++）。  
> **每日投入建议**：3~4 小时（保持手感比单次熬夜更重要）。

---

## 🟢 阶段一：生存技能与数据基石（第 1 周）
**阶段目标**：搭建开发环境，掌握 Python 基础与 NumPy 矩阵操作，理解项目的“唯一配置源” YAML。

### Day 1：环境搭建与 Python 极速入门
- [x] 安装 Python 3.12 与 VS Code（或 PyCharm），配置好环境变量。
- [x] 学习 Python 基础语法：变量、数据类型（列表、字典）、`if` 判断、`for/while` 循环。
- [ ] 学习 Python 函数定义（`def`）与文件读写（`open`）。
> 💡 **分析指点**：不要看几十集的视频！直接找“Python 3 小时速成”类教程，只学基础语法。字典（dict）和列表（list）是你以后处理配置和矩阵最常用的数据结构，必须熟练。

### Day 2：YAML 配置文件与“唯一配置源”概念
- [ ] 学习 YAML 语法（缩进、键值对、列表）。
- [ ] 安装 `pyyaml` 库（`pip install pyyaml`）。
- [ ] 编写 `array_config.yaml`，定义基础的 `rows: 8`, `cols: 8`, `channels: 64`。
- [ ] 写一个 Python 脚本，读取该 YAML 文件并打印出内容。
> 💡 **分析指点**：这是你整个软件架构的基石。理解“改一处，全链路同步”的思想。以后你的代码里绝对不能出现硬编码的 `16` 或 `256`，必须从 YAML 里读。

### Day 3：NumPy 矩阵基础（替代 Matlab）
- [x] 安装 `numpy` 库。
- [x] 学习 NumPy 核心操作：创建二维数组（`np.zeros`, `np.ones`, `np.array`）。
- [x] 学习矩阵的索引、切片（取某一行/某一列）、形状变换（`reshape`）。
- [ ] 练习：用 NumPy 生成一个 8x8 的棋盘格矩阵（0和1交替）。
> 💡 **分析指点**：你的 16x16 LED 状态本质上就是一个 0/1 矩阵。NumPy 是 Python 科学计算的灵魂，它的矩阵操作比原生 Python 列表快几十倍，且语法和 Matlab 非常像。

### Day 4：NumPy 进阶与位操作基础
- [x] 学习 NumPy 的广播机制与基础数学运算（加减乘除、三角函数）。
- [ ] 理解二进制与十六进制：什么是 Bit（位）和 Byte（字节）。
- [ ] 练习：将 8x8 的 0/1 矩阵，按每 8 个 bit 打包成 1 个 byte（共 8 个字节）。
> 💡 **分析指点**：单片机不认 0/1 矩阵，它只认字节流。把矩阵“压扁”成字节是上位机最核心的逻辑之一，今天必须搞懂位运算（`<<`, `>>`, `|`, `&`）。

### Day 5：复习与代码重构
- [ ] 将前 4 天的代码整合：读取 YAML -> 生成 8x8 棋盘格矩阵 -> 打包成 8 个字节 -> 打印十六进制结果。
- [ ] 学习使用 Git 基础命令：`git init`, `git add`, `git commit`，将代码提交到本地仓库。
> 💡 **分析指点**：第一天的小闭环完成了！这个脚本就是你未来上位机的雏形。开始用 Git 管理代码，养成好习惯，防止改崩了无法回退。

### Day 6：阅读 Starter Code（资源包代码）
- [ ] 解压并阅读资料包中的 `starter_code/code/config/array_config.yaml`。
- [ ] 阅读 `starter_code/code/host/protocol.py`（只看结构，不求全懂）。
- [ ] 尝试运行资料包里的 `pytest` 测试，确保环境无误。
> 💡 **分析指点**：不要自己从零造轮子！看看前辈/资料包是怎么写配置的。对比自己写的 YAML，找出差距并优化自己的配置文件。

### Day 7：阶段一总结与休息
- [ ] 整理本周学习笔记，记录遇到的坑和解决方法。
- [ ] 休息，调整状态。
> 💡 **分析指点**：第一周最痛苦，因为要从零建立编程思维。能坚持下来，你已经超越了 50% 的队友。

## 🟡 阶段二：核心控制与协议打通（第 2 周）
**阶段目标**：掌握串口通信，理解二进制协议，开发出能发送指令的命令行上位机（CLI）。

### Day 8：串口通信基础（PySerial）
- [ ] 安装 `pyserial` 库。
- [ ] 学习如何列出电脑可用串口（`serial.tools.list_ports`）。
- [ ] 学习打开串口、设置波特率（如 115200）、发送字符串、读取返回值。
- [ ] 如果有条件，用 USB 转 TTL 模块短接 TX/RX，自发自收测试。
> 💡 **分析指点**：这是 PC 和单片机“对话”的唯一桥梁。重点理解“阻塞与非阻塞读取”、“超时设置”，否则你的程序会卡死。

### Day 9：深入二进制协议设计
- [ ] 仔细阅读资料包中的 `docs/06_Python上位机_协议与测试代码.md`。
- [ ] 理解帧结构：帧头（SOF `A5 5A`）、命令字、序列号、长度、Payload、CRC16、帧尾。
- [ ] 学习 Python 的 `struct` 库，练习将整数打包成小端字节流（`struct.pack('<H', 1024)`）。
> 💡 **分析指点**：串口发的是字节流，不是字符串。协议设计是重中之重，必须和杨同学对齐。CRC 校验是为了防止传输丢包，不用自己手写算法，用现成的库或资料包里的代码。

### Day 10：实现协议编码与解码（Protocol 层）
- [ ] 抄写并理解资料包中的 `protocol.py` 核心逻辑。
- [ ] 实现 `encode_frame` 函数：输入命令和 Payload，输出完整的字节帧。
- [ ] 实现 `decode_frame` 函数：输入字节流，解析出命令和 Payload。
- [ ] 编写测试用例：编码后再解码，看是否和原数据一致。
>  **分析指点**：把协议封装成独立的模块，不要和串口发送逻辑混在一起。这样以后改协议，不用动串口代码。

### Day 11：开发命令行上位机（CLI）
- [ ] 学习 Python 的 `argparse` 库（用于解析命令行参数）。
- [ ] 编写 `arrayctl.py` 脚本，支持 `--port COM3 ping` 等命令。
- [ ] 实现 `PING` 命令：发送心跳帧，等待并打印 ACK。
> 💡 **分析指点**：不需要写图形界面（GUI）！命令行工具开发快、易调试、方便后期写成自动化脚本。评委看到你能用命令行精准控制硬件，反而觉得你更专业。

### Day 12：实现核心控制命令
- [ ] 在 CLI 中增加 `off`（全灭）和 `one --row 3 --col 5`（点亮指定坐标）命令。
- [ ] 实现坐标到物理通道号的映射逻辑（结合 YAML 配置）。
- [ ] 实现 `checker`（棋盘格）和 `random`（随机图案）命令。
> 💡 **分析指点**：这就是你“做工具”的核心体现。把抽象的“点亮第3行第5列”转化为底层的“发送特定字节”。

### Day 13：Dry-run 模式与离线调试
- [ ] 为 CLI 增加 `--dry-run` 参数。
- [ ] 实现不连接串口时，也能在屏幕上打印出将要发送的十六进制帧。
- [ ] 用 `--dry-run` 测试各种图案的生成是否正确。
> 💡 **分析指点**：这是极其重要的工程习惯！在硬件没焊好、或者硬件出问题时，你能通过 dry-run 证明“我的软件没问题，是硬件的锅”。

### Day 14：阶段二总结与联调准备
- [ ] 整理协议文档，准备开学后和杨同学进行第一次“软硬件联调”。
- [ ] 休息。
>  **分析指点**：第二周结束，你已经拥有了一个可用的控制工具。开学后，只要杨同学的板子能跑，你的代码就能直接控灯。

## 🟠 阶段三：仿真可视化与自动化测试（第 3 周）
**阶段目标**：掌握阵列因子仿真，画出方向图；学会写自动化测试脚本，为项目增加“亮点”。

### Day 15：Matplotlib 基础与极坐标绘图
- [ ] 安装 `matplotlib` 库。
- [ ] 学习基础绘图：折线图、散点图。
- [ ] **重点**：学习极坐标绘图（`projection='polar'`），画出一个简单的雷达图。
> 💡 **分析指点**：天线方向图通常用极坐标表示。Matplotlib 是 Python 最强大的绘图库，学会它，你的答辩 PPT 会非常漂亮。

### Day 16：阵列因子（Array Factor）数学模型
- [ ] 阅读资料包 `docs/09_阵列因子_PIN二极管与天线拓展.md`。
- [ ] 理解阵列因子公式：$AF = \sum w_{mn} e^{j\phi}$。
- [ ] 抄写并运行资料包中的 `simulation/array_factor.py` 和 `demo.py`。
> 💡 **分析指点**：不要试图从头推导公式！先把它当成“黑盒”：输入 0/1 矩阵，输出方向图。跑通代码后，再慢慢理解里面的数学含义。

### Day 17：仿真与控制的联动
- [ ] 修改仿真代码，使其能直接读取你的 `array_config.yaml`。
- [ ] 实现流程：CLI 生成图案 -> 保存为 `.npy` 文件 -> 仿真代码读取 `.npy` -> 画出方向图。
> 💡 **分析指点**：打通“控制”与“仿真”的任督二脉。证明你的 LED 亮灭状态，可以直接用于天线波束的理论计算。

### Day 18：自动化测试基础（pytest）
- [ ] 安装 `pytest` 库。
- [ ] 学习 pytest 基础：如何写测试函数（`test_xxx.py`），如何使用 `assert`。
- [ ] 为你的 `protocol.py` 和 `patterns.py` 编写单元测试。
> 💡 **分析指点**：大创评委非常看重“工程规范性”。有单元测试的项目，在评委眼里就是“正规军”。

### Day 19：压力测试脚本（Stress Test）
- [ ] 编写 `stress_test.py` 脚本。
- [ ] 实现功能：循环发送 1000 次随机图案，统计成功/失败次数，计算平均耗时。
- [ ] 将测试结果保存为 CSV 文件。
> 💡 **分析指点**：这是你“自动化测试”的核心交付物。开学后，用这个脚本跑杨同学的板子，跑出一张漂亮的“10万次无故障”图表，直接放进结题报告。

### Day 20：OpenCV 视觉核验入门（可选/拓展）
- [ ] 安装 `opencv-python` 库。
- [ ] 学习读取图片、转灰度图、二值化（`cv2.threshold`）。
- [ ] 尝试拍一张 LED 灯的照片，用代码提取出哪些灯是亮的。
> 💡 **分析指点**：视觉识别是项目的“加分项”。如果时间不够，只需实现“把图片转黑白”即可，复杂的轮廓检测开学后再说。

### Day 21：总复习与开学准备
- [ ] 将所有代码整理到 Git 仓库，写好 `README.md`（说明如何运行你的工具）。
- [ ] 列出开学后第一周需要和杨、林同学对接的“问题清单”（如：确认串口波特率、确认物理接线等）。
- [ ] 庆祝自己完成了三周的高强度突击！
> 💡 **分析指点**：代码能跑很重要，但“别人能跑你的代码”更重要。写好文档，是你作为“可复现负责人”的最终体现。

## 🚀 开学后的衔接建议

1. **第一周核心任务**：拿着你的 CLI 工具，去点亮杨同学板子上的**第一颗 LED**。只要第一颗亮了，后面的 255 颗就只是循环问题。
2. **沟通策略**：不要等代码全写完再找他们。Day 9 写完协议后，就立刻找杨同学确认帧格式；Day 16 跑通仿真后，就找林同学讨论天线参数。
3. **心态管理**：联调时一定会遇到“灯不亮”、“串口没反应”等崩溃情况。**记住：90% 的硬件问题最后发现是软件配置错了，90% 的软件问题最后发现是线没接好。** 保持耐心，逐层排查。

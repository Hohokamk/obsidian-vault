## 三、看懂整个项目的"最小知识集"

项目大纲里有很多内容，但**你作为计算机专业成员**，真正需要看懂的核心逻辑只有这一条链：

```
需求指标 → 配置定义 → 上位机命令 → 串口帧 → MCU解析 → SPI/DMA → 驱动芯片 → LED亮灭
         ↑___________________________________________________________↓
                              回读/视觉核验（你做的测试）
```

以及另一条独立链：

```
LED通断状态(0/1矩阵) → 阵列几何参数 → 阵列因子公式 → 方向图计算 → 可视化
                                                ↓
                                          优化算法搜索最优状态
```

**你只需要懂这些概念，不需要会设计硬件**：

| 概念 | 你需要懂到什么程度 |
|------|-----------------|
| SPI | 知道是"串行外设接口"，MCU 用它把数据发给驱动芯片，比 GPIO 快 |
| DMA | 知道是"直接内存访问"，MCU 不用 CPU 干预就能传数据，刷新更快 |
| 锁存(Latch) | 知道是"先传数据，再统一更新输出"，避免 LED 逐个亮灭的闪烁 |
| 移位寄存器 | 知道是"串进并出"的器件，MCU 用少量引脚控制多路输出 |
| 驱动芯片 | 知道它接收 SPI 数据，输出电流点亮 LED，有恒流/非恒流之分 |
| 阵列因子 | 知道公式 $AF = \sum_{m,n} I_{mn} e^{j(kx_{mn}\sin\theta\cos\phi + \dots)}$，会写代码算 |
| 方向图 | 知道是"天线在不同方向的辐射强度"，你的仿真要画出这个图 |

**你不需要会**：PCB 布局、电源完整性分析、阻抗匹配、EMC 设计、模拟电路计算——这些是给队长的。

**关键公式**（先抄会用，再理解）：
```python
import numpy as np

def array_factor(N, M, d, theta, phi, I):
    """
    N,M: 阵列行数列数
    d: 单元间距（波长）
    theta, phi: 观察方向
    I: N×M 的激励幅度矩阵（LED亮=1，灭=0）
    """
    k = 2 * np.pi  # 波数
    AF = 0
    for m in range(N):
        for n in range(M):
            phase = k * d * (m * np.sin(theta) * np.cos(phi) + 
                             n * np.sin(theta) * np.sin(phi))
            AF += I[m, n] * np.exp(1j * phase)
    return np.abs(AF)
```

## 五、给你的 3 个务实建议

### 1. 先跑起来，再学理论

不要等"学完了再动手"。**第一周就买个 USB 转 TTL 模块，接个开发板，先让 PC 和 MCU 说上话**。很多通信知识是在调试中学会的，不是看书看会的。

### 2. 阵列因子先"抄公式、跑代码、看结果"，再推导

你不需要先精通电磁场理论才能写仿真。先把这个公式当成"黑箱函数"用：
- 输入：LED 亮灭矩阵（0/1）
- 输出：一个方向图
- 调参：改改阵列间距、改改 LED 图案，看看方向图怎么变

**直观理解建立起来后**，再回头看公式里每个符号的物理意义。

### 3. 主动向队长要"接口文档"而不是"教我做硬件"

你对硬件感兴趣，但边界要清楚。你可以问队长：
- ✅ "SPI 通信的时钟频率和数据格式是什么？"
- ✅ "驱动芯片的级联方式是怎样的？"
- ✅ "通道编号和物理位置的对应关系能给我一份吗？"
- ❌ "这个电阻为什么要选 10 k？"
- ❌ "PCB 布线有什么讲究？"

前三个问题帮你做上位机和配置管理，后两个问题队长的回答你现阶段也消化不了。

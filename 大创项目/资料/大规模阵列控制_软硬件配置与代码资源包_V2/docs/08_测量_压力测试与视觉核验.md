# 08 测量、压力测试与视觉核验

## 1. 测量的目的

本项目不能以“肉眼看起来能亮”作为结论。需要分别测量：

1. PC—MCU协议是否正确；
2. MCU—驱动链的串行数据是否正确；
3. 锁存时刻是否正确；
4. 物理输出是否与目标一致；
5. 电流是否一致；
6. 供电是否稳定；
7. 器件是否过热；
8. 异常后是否安全。

每类错误要分别计数。

## 3. 测试层级

## 3.1 第1层：协议

指标：

- 总发送帧；
- ACK；
- CRC错误；
- 超时；
- 序列号错误；
- 平均与最大往返时间。

工具：

- Python压力测试；
- MCU计数器；
- 串口抓包。

## 3.2 第2层：串行链

指标：

- 发送bit数；
- SER_OUT旧帧是否一致；
- 位错误数；
- 错误发生在何种链长、频率和阻尼。

工具：

- 逻辑分析仪；
- MCU全双工回读。

## 3.3 第3层：锁存和输出

指标：

- 移位期间输出不变；
- RCK后输出改变；
- 输出建立时间；
- 毛刺；
- 多代表通道延迟差。

工具：

- 示波器；
- 电阻负载；
- LED视觉。

## 3.4 第4层：电流、供电和热

指标：

- 通道电流；
- CV；
- 模块压降；
- 全关→全开瞬态；
- 温升；
- MCU复位。

## 6. 示波器实验

## 6.1 SRCK信号完整性

测点：

- MCU引脚后；
- 阻尼后；
- 第一颗驱动；
- 最后一颗驱动；
- 最后一个模块。

记录：

- 高低电平；
- 上升/下降时间；
- 过冲；
- 欠冲；
- 振铃；
- 是否单调穿过门限。

比较：

```text
0 Ω
22 Ω
33 Ω
47 Ω
68 Ω
100 Ω
```

## 6.2 锁存

测：

- SRCK最后一个边沿；
- RCK；
- 代表性DRAIN；
- LED/电阻输出节点。

确认：

- 最后一位已移出；
- RCK满足建立保持；
- 输出只在RCK后变化。

## 6.3 供电瞬态

CH1：VLOAD入口；  
CH2：最远模块VLOAD；  
CH3：MCU 3.3 V；  
CH4：RCK或图案切换脉冲。

图案：

```text
全关→全开
棋盘格→反棋盘格
随机25%→随机75%
```

测：

- 瞬态最低电压；
- 恢复时间；
- 纹波；
- 3.3 V是否跌落；
- 是否复位。

## 7. 电流一致性

### 7.1 为什么不直接靠LED亮度

LED的正向电压、发光效率和相机响应均有差异。亮度不等于电流。

驱动比较阶段优先使用：

```text
VLOAD → 精密电阻/统一负载 → DRAIN
```

通过电阻压降：

\[
I=\frac{V_R}{R}
\]

### 7.2 采样计划

基础：

- 每颗驱动器至少测DRAIN0和DRAIN7；
- 8颗共16点；
- 加板近端/远端；
- 加最高和最低电流通道。

挑战：

- 设计模拟多路开关或采样板；
- 自动扫描全部64或256路。

### 7.3 指标

\[
\bar I=\frac{1}{n}\sum I_i
\]

\[
\sigma_I=
\sqrt{\frac{1}{n-1}\sum(I_i-\bar I)^2}
\]

\[
CV=\frac{\sigma_I}{\bar I}\times100\%
\]

同时报告：

- 最大值；
- 最小值；
- 最大相对偏差；
- 通道位置；
- 温度；
- 电源；
- 负载。

## 8.3 错误类别

```text
host_timeout
bad_ack_sequence
device_bad_crc
device_busy
spi_dma_error
spi_timeout
serial_readback_bit_error
physical_output_error
mcu_reset

```

## 8.4 零错误怎样解释

有限测试中零错误不代表绝对可靠。若独立事件近似成立，零错误的95%上界可粗略取：

\[
p_{95}\approx\frac{3}{N}
\]

10万帧零错误约只能说明：

\[
p_{95}\approx3\times10^{-5}
\]

报告应写“在给定测试条件下未观测到错误”。

## 10. LED视觉核验

## 10.1 视觉测试定位

视觉系统用于自动检查“目标状态和LED亮灭是否一致”。它不能替代：

- 电流测量；
- 串行回读；
- 时钟波形；
- RF响应。

## 10.2 固定相机

要求：

- 相机和阵列固定；
- 避免自动曝光；
- 避免自动白平衡；
- 遮挡环境光；
- 阵列平面尽量正对；
- 每个LED有明确ROI；
- 保存原图而非只保存识别结果。

## 10.3 简单标定

最简单：

1. 全亮拍图；
2. 人工点击四角LED中心；
3. 透视变换为规则矩形；
4. 均匀划分16×16 ROI；
5. 每个ROI计算灰度/颜色亮度；
6. 用全关和全亮建立阈值。

更稳健：

- 每块64路模块四角加视觉标记；
- 使用ArUco；
- 每次自动寻找模块；
- 处理轻微移动和旋转。

OpenCV ArUco：

<https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html>

## 10.4 判断

每个ROI：

```python
score = ROI内高亮像素均值或高分位数
state = score > threshold
```

不要只取单个中心像素。

阈值可按：

```text
threshold = (off_mean + on_mean) / 2
```

也可以每个LED单独标定阈值，以补偿亮度差异。

## 10.5 视觉误差

分类：

- 目标1、识别0：漏亮；
- 目标0、识别1：误亮；
- 遮挡；
- 过曝；
- 反光；
- 相邻LED串光；
- ROI错位。

视觉脚本应保存：

- 原图；
- 矫正图；
- ROI叠加图；
- 目标矩阵；
- 识别矩阵；
- 差异矩阵；
- 错误坐标。

## 10.6 视觉回归

每次PCB重新装配：

1. 全关；
2. 全亮；
3. 逐点；
4. 棋盘格；
5. 1000随机图案；
6. 统计每个通道错误频率；
7. 与SER_OUT结果交叉分析。

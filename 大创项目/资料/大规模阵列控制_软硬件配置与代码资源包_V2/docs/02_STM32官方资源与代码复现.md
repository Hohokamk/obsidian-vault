### 2.1 UART_Printf

代码：

<https://github.com/STMicroelectronics/STM32CubeG4/tree/v1.6.3/Projects/NUCLEO-G474RE/Examples/UART/UART_Printf>

项目用途：

- 验证板载ST-LINK虚拟串口；
- 学习`printf`重定向；
- 验证PC串口工具；
- 后续输出版本、错误码和测量日志。

官方例程默认串口参数未必与本项目协议一致。先原样运行，再改成：

```text
921600 baud
8 data bits
no parity
1 stop bit
no flow control
```

修改前先保存“官方原样可运行”的提交。

#### 操作步骤

1. 打开`STM32CubeIDE`目录中的工程；
2. 编译；
3. 连接Nucleo的ST-LINK USB；
4. 下载；
5. 在设备管理器寻找虚拟COM；
6. 用串口终端打开官方默认参数；
7. 确认输出；
8. 修改为8N1；
9. 再用Python读取；
10. 提交`firmware: verify official UART_Printf example`。

#### Python快速验证

```python
import serial

with serial.Serial("COM5", 115200, timeout=1) as ser:
    print(ser.readline())
```

Linux端口通常为`/dev/ttyACM0`。

### 2.2 SPI轮询Master

代码：

<https://github.com/STMicroelectronics/STM32CubeG4/tree/v1.6.3/Projects/NUCLEO-G474RE/Examples/SPI/SPI_FullDuplex_ComPolling_Master>

用途：

- 学习SPI初始化；
- 看懂主机数据发送；
- 确认CPOL、CPHA和数据宽度；
- 在使用DMA前建立可观察的最小闭环。

官方例程面向两块开发板全双工通信。驱动移位寄存器时只需要：

- 主机；
- MOSI；
- SCK；
- 不需要从机NSS；
- MISO仅用于可选SER_OUT回读；
- RCK/OE/CLR是独立GPIO。

#### 改造顺序

1. 原样跑通双板示例，条件不足时至少编译和阅读；
2. 删除从机握手逻辑；
3. 配置`Master`, `8-bit`, `MSB first`；
4. SPI频率先设100 kHz～1 MHz；
5. `HAL_SPI_Transmit()`发送1字节；
6. 发送完成后GPIO产生RCK脉冲；
7. 接入TLC6C598；
8. 用逻辑分析仪验证8个时钟和1个锁存脉冲。

### 2.3 SPI DMA Master

代码：

<https://github.com/STMicroelectronics/STM32CubeG4/tree/v1.6.3/Projects/NUCLEO-G474RE/Examples/SPI/SPI_FullDuplex_ComDMA_Master>

这是本项目最重要的官方代码参考。

#### 不要整套照搬

官方例程解决的是“两块板通过SPI全双工DMA交换数据”。本项目需要的是：

```text
内存帧
→ SPI TX DMA
→ 等待SPI末位真正发出
→ RCK锁存
→ 输出切换
```

需要保留：

- SPI初始化；
- DMA初始化；
- `HAL_SPI_TransmitReceive_DMA`或TX DMA结构；
- DMA完成回调；
- 错误回调；
- 缓冲区；
- 超时和状态。

需要删除或替换：

- 第二块板；
- 双向握手；
- 数据比较LED；
- 无关接收流程；
- 官方按钮触发逻辑。

#### 建议改造成TX-only

```c
HAL_StatusTypeDef array_send_dma(uint8_t *data, uint16_t len)
{
    if (tx_busy) {
        return HAL_BUSY;
    }

    tx_busy = true;
    dma_done = false;
    return HAL_SPI_Transmit_DMA(&hspi1, data, len);
}
```

回调中不要立刻锁存：

```c
void HAL_SPI_TxCpltCallback(SPI_HandleTypeDef *hspi)
{
    if (hspi == &hspi1) {
        dma_done = true;
    }
}
```

主循环或状态机：

```c
if (dma_done && spi_really_finished()) {
    latch_pulse();
    tx_busy = false;
}
```

原因：

DMA完成表示最后一个字节已搬到SPI外设，不一定表示最后一位已从引脚发出。必须按所选G4 SPI实例和HAL版本核对`EOT/TXC/BSY`。

官方应用笔记：

<https://www.st.com/resource/en/application_note/an5543-guidelines-for-enhanced-spi-communication-on-stm32-mcus-and-mpus-stmicroelectronics.pdf>

重点阅读：

- SPI版本差异；
- DMA完成事件；
- `BSY`、`TXC`和`EOT`；
- FIFO；
- 数据宽度；
- 关闭SPI前的结束序列；
- 错误标志。

### 2.5 TIM_PWMOutput

代码：

<https://github.com/STMicroelectronics/STM32CubeG4/tree/v1.6.3/Projects/NUCLEO-G474RE/Examples/TIM/TIM_PWMOutput>

用途：

- PWM拓展；
- 产生稳定刷新触发；
- 用定时器定期启动状态更新；
- TLC5940拓展时产生GSCLK。

核心二值路线不要求每通道PWM，但定时器可用于：

```text
定时器更新事件
→ 选择下一帧
→ SPI DMA
→ 完成后锁存
```

不要在定时器中断里等待DMA或调用长时间阻塞函数。

## 3. CubeMX项目配置建议

## 3.1 GPIO

选择GPIO：

- `RCK/LATCH`：推挽输出，默认低；
- `G/OE`：推挽输出，软件默认高，但硬件还要外部上拉；
- `CLR`：推挽输出，按芯片低有效，正常工作保持高；
- `STATUS_LED`：调试；
- `SER_OUT_READ`：可选输入。

安全初始化顺序：

```c
OE_HIGH();       // 先关输出
LATCH_LOW();
CLR_LOW();       // 清除
delay_us(1);
CLR_HIGH();
```

先配置GPIO输出初值，再启用SPI和DMA。

## 3.2 SPI

基础配置：

```text
Mode: Master
Direction: 2 Lines或1 Line TX
Data Size: 8 Bits
Clock Polarity/Phase: 按TLC6C598上升沿采样要求选择
NSS: Software
First Bit: MSB或LSB，由统一映射决定
Baud Rate: 初始100 kHz～1 MHz
CRC: Disable
DMA TX: Enable
```

TLC6C598在SRCK上升沿装载数据。常见配置可从`CPOL=0, CPHA=0`开始，但必须用逻辑分析仪确认数据在上升沿前稳定。

## 3.3 DMA

- Direction：Memory to Peripheral；
- Mode：Normal；
- Peripheral increment：Disable；
- Memory increment：Enable；
- Data width：Byte；
- Priority：Medium/High；
- 中断：Transfer complete和Error；
- 不使用Circular模式发送独立帧。

## 3.4 UART

- 8N1；
- 初始115200，协议稳定后可升至921600；
- 接收推荐DMA+IDLE或中断环形缓冲；
- 初学阶段可先使用阻塞接收短命令；
- 不能在接收中断内解析大帧和等待SPI。

## 3.5 定时器

基础阶段不强制。需要固定帧率时：

- 定时器只设置“请求下一帧”标志；
- 主循环检查系统是否空闲；
- SPI DMA完成后再锁存；
- 若上一帧未完成，统计`missed_deadline`，不要覆盖正在发送的缓冲。

## 5. STM32学习验收

每名学生至少能回答：

1. DMA完成为什么不一定能立即锁存？
2. `RCK`为什么不能用SPI的NSS直接替代？
3. OE为什么需要外部上拉？
4. 32 B如何表示256个二值通道？
5. 双缓冲如何防止半帧数据？
6. SPI位序怎样影响第一个物理输出？
7. UART CRC正确为什么不能证明LED输出正确？
8. 发生SPI错误时输出应保持旧状态还是关闭？

杨同学必须能在调试器里查看：

- SPI状态寄存器；
- DMA剩余计数；
- TX缓冲；
- 系统状态机；
- 错误计数。

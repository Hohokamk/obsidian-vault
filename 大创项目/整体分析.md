## 三、特别注意的 5 件事

### ⚠️ 1. 配置是"唯一真相源"

这是项目大纲反复强调的：

> "以单一配置源统一硬件编号、固件映射、上位机和仿真"

**你的责任**：设计一个 `array_config.yaml`，格式大概这样：

```yaml
array:
  size: [16, 16]          # 阵列规模
  total_channels: 256
  mapping:                 # 逻辑坐标 → 物理通道号
    [0,0]: 0               # (行,列) : SPI链号*64 + 芯片号*16 + 位号
    [0,1]: 1
    # ...
  geometry:                # 物理间距（用于仿真）
    dx: 0.5                # 波长
    dy: 0.5
  electrical:
    vcc: 5.0
    current_per_channel: 0.02  # 20mA
```

然后写 Python 脚本，从这个文件自动生成：
- C 语言头文件（给队长固件用）
- PCB 丝印编号表（给 EDA 用）
- 测试图案坐标（给自动测试用）
- 仿真阵列几何（给阵列因子用）

**好处**：改一处，全链路同步，避免"人工编号抄错"的低级错误

---

### ⚠️ 2. 不要承诺"AI 全自动设计 PCB"

老师说的是：
> "利用软件和 AI 专长，开展 EDA 电子设计辅助软件的自动化运行和调试"

注意是**"自动化运行和调试"**（跑检查、出报告、生成文件），**不是"AI 自动设计电路"**。

大纲明确警告：
> "不将 AI 自动完成 PCB 设计列为硬性任务"

**你的写法**："基于 KiCad CLI 和 Python 实现设计规则自动检查与生产文件批量生成"

---

### ⚠️ 3. 软硬件接口要"文档先行"

你和队长的协作点是：
- 串口协议帧格式
- 通道编号规则
- 固件回读机制（用于测试验证）

**建议**：第一周就和队长约定协议文档，格式示例：

```
帧格式：[HEAD][CMD][LEN][DATA...][CRC][TAIL]
HEAD: 0xAA
CMD:  0x01=写整帧, 0x02=写单点, 0x03=读状态, 0x04=预设模式
LEN:  数据字节数
CRC:  CRC-8
TAIL: 0x55
```

---

### ⚠️ 4. 阵列仿真≠真实天线

大纲反复强调：
> "LED 状态不等同于真实电磁响应"

你的仿真做的是**理想模型**（把 LED 通断当成幅度权重 0 或 1），未来真实天线需要：
- 单元幅相响应（复数，不是 0/1）
- 互耦效应
- 馈电网络损耗

**你的写法**："建立理想阵列因子模型，将硬件状态文件作为输入；未来可通过全波仿真或实测数据替换为真实单元响应"

---

### ⚠️ 5. 利用你的"硬件兴趣"但守住边界

你对硬件感兴趣是好事，可以：
- ✅ 主动学习 KiCad，帮团队做自动化
- ✅ 读 MCU 数据手册，理解 SPI/DMA 时序
- ✅ 参与硬件测试，用逻辑分析仪抓波形
- ❌ **不要试图替代队长做硬件设计**（原理图、PCB 布局、电源设计）
- ❌ **不要承诺做 FPGA**（大纲说了"单片机更符合成本培养目标"）

你的独特价值是**"用软件能力解决硬件团队的重复劳动和验证问题"**。

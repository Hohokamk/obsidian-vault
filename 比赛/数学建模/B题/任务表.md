## 0. 三分钟读懂这个项目

### 0.1 题目一句话
半径 1800 m 的圆形场地里藏着 **10–16 个**无线电干扰源（频道从 1–20 中互不重复取），
机器狗从圆心 `(0,0)` 出发，只能用测向机（**示向度误差 ±1°**）判断"信号来自哪个方向"，
用激光枪在 **≤20 m** 内清除。目标：**全部清除，且平均定位清除时间越小越好**。

### 0.2 评分核心
```
平均定位清除时间 = 定位清除总时间（虚拟秒） / 被清除干扰源个数
```
- 必须**全部清除**，漏一个就是任务失败；
- 分母是清除数，所以"少清一个但总时间短"是幻觉，不能换分；
- 正式测试 **问题 3 三次 + 问题 4 三次**，中止也消耗一次机会。

### 0.3 时间账本（虚拟秒，全题命根子）

| 动作 | 指令 | 虚拟耗时 | 备注 |
|---|---|---|---|
| 移动 | 无独立指令，由 `position` 推断 | 距离 / 5（m/s） | **1000 m = 200 s，占总成本 85%+** |
| 切换频道 | 无独立指令 | 1 s | 仅 `/measure` 且与当前频道不同时收 |
| 检测 | `POST /measure` | 5 s | `direction`/`near`/`no_signal` 都是 5 s |
| 清除成功 | `POST /clear` | 5 s | 3 s 光学定位 + 2 s 激光 |
| 清除落空 | `POST /clear` | 3 s | 只花光学定位 |
| 进入 / 退出 | `POST /enter` `/exit` | 0 s | 不推进虚拟时钟 |

**必背换算**：走 1000 m = 200 s；一个点扫完 20 个频道 = 20×5+19×1 = **119 s**；
清除一个源只要 5 s。→ **走路最贵、开枪最便宜**。

### 0.4 三个胜负手
1. **侦察与抓捕必须同一趟路**。绝不能先跑一圈"找"，再跑一圈"打"，那等于把路程走两遍。
2. **乐观清除 + 廉价补枪**。落空只花 3 s，重新交会要几百秒；不要为"保证一发命中"过度测量。
3. **正式测试机会不可逆**。所有调参必须在影子模拟器 + 演练测试里做完，正式测试只做验证。

### 0.7 红线（踩一条就白干）

- 现实墙钟：`/enter` 起 **最多 20 分钟**，且 25 分钟窗口与它取较早者；必须用响应里的 `remaining_real_duration_s`，不许硬编码 1200。
- 虚拟时钟上限 360000 s（100 h），实际不构成约束。
- **串行**请求，不得并发；每个新动作用**新的 `request_id`**，仅网络超时重试同一动作时才复用。
- 必须**同时**校验 HTTP 状态码与 `accepted`。`accepted=false` 时 `virtual_time_s=0`，动作没生效。
- **未知字段 → HTTP 200 + `accepted=false`**，字段名必须逐字照抄附件 2。
- 日志 < 2 MB，否则无法上传；禁止高频轮询 / 重试风暴。
- 时间一律以响应里的 `virtual_time_s` 为准，不要自己累加。
- 坐标每分量绝对值 ≤ 2,000,000，且不得为 NaN / ±Inf。
- 同一账号不能两台设备同时登录 → **指定唯一测试机**；本机与服务器时间差 >60 s 不能开新测试。
- `/clear` 不切换测向机频道、不计切换耗时；`/measure` 同点同频道重测**误差完全相同，零信息增益**。

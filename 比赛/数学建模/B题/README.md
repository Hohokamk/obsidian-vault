## 0. 一页速览（TL;DR）

**这道题是什么**：一只机器狗从半径 1800 m 圆形场地的圆心出发，拿着只能测方向的测向机
（示向度误差 ±1°）和一把只能在 20 m 内打响的激光枪，去找出并清掉 10–16 个藏在场地里、
频道互不相同（1–20 中取，每频道至多 1 个）的干扰源。狗速 5 m/s，检测一次 5 s，换频道 1 s，
清除成功 5 s、落空 3 s。

**评分核心**：`平均定位清除时间 = 定位清除总时间 / 被清除干扰源个数`，越小越好，
且必须**全部清除**。所以这不是"找得到就行"，而是**在移动成本占 85% 的前提下做全局路径与
信息获取的联合优化**。

**三个决定成败的判断**

1. **移动是唯一的真成本**。走 1000 m = 200 s，而在一个点把 20 个频道全扫一遍只要 119 s。
   所以"侦察"和"抓捕"必须共用同一趟路程，绝不能先跑一圈侦察、再跑一圈抓人。
2. **开枪便宜，走路贵**。clear 落空只花 3 s，而重新做一次交会定位要花几百秒。
   所以策略应是"乐观清除 + 廉价局部补枪"，而不是不惜代价追求"保证一发命中"。
3. **正式测试只有 3+3 次，且"中止"也算用掉一次**。所有调试必须在本地影子模拟器 + 演练测试
   里完成。正式测试前代码冻结。

## 2. 赛题解析

### 2.1 一句话讲清题目

在一个半径 1800 m 的圆形场地里藏着若干个干扰源，每个源占一个独立频道、有一个**未知的**
有效接收半径（1000–1500 m）。机器狗从圆心出发，只能：走直线、在某个点对某个频道测一次方向
（拿到 ±1° 误差的示向度）、在某个点对某个频道开一枪（20 m 内必中，20 m 外必空）。
要把所有源清光，虚拟时间越短越好。

### 2.2 四问的递进关系

| 问 | 本质 | 输出 |
|---|---|---|
| Q1 | 纯几何：n 个 ±1° 楔形求交 → 凸多边形的直径；并回答"直径圆能否覆盖该区域" | 算法 + 是/否结论 + 反例 |
| Q2 | 单目标最优交会：已知一条视线，第二个检测点怎么选、候选区域长什么样 | 选点策略 + 候选区域（解析刻画 + 图） |
| Q3 | 全局运筹：源数未知（10–16）、全向，从原点出发边搜边清 | 策略 + 算法 + 模拟器实测数据（表1） |
| Q4 | Q3 升级：混入定向源（覆盖角 = 定向方向 ±90°），信号可能"背后没有" | 策略 + 算法 + 模拟器实测数据（表1） |

Q1/Q2 是 Q3/Q4 的"零件"：Q1 给出定位区域怎么算，Q2 给出定位一步该怎么走。
Q3/Q4 才是真正的分数大头（要跑模拟器、要填表、要交日志）。

### 2.3 规则总表（务必逐条写进论文"模型假设"）

**场地与目标**

- 场地：圆域，半径 1800 m，圆心为坐标原点；x 轴正东，y 轴正北；角度为 x 轴正向逆时针，范围 [0°, 360°)。
- 干扰源个数：10–16，**具体未知**；正式测试任何界面都不显示真值（演练测试结束后会显示）。
- 频道：1–20，每个源的频道互不相同且不变 → **每个频道至多 1 个源**（这条极其重要，可用于剪枝）。
- 不同源的信号互不影响。
- 有效接收半径 R_eff ∈ [1000, 1500] m，**每个源不同且不可读取**。
- 全向源：360° 均匀辐射。定向源：定向方向两侧各 90°（含）内有信号，之外**完全无信号**。
- 场强只随距离衰减，与角度无关（在覆盖角内）。

**测向机与机器狗**

- 示向度 = 检测点指向干扰源的真实方位角 + 误差；误差 ∈ [−1°, +1°]，返回保留 2 位小数。
- **同一地点电磁环境固定 → 重复检测误差完全一样，原地重测毫无信息增益。**
  不同地点、不同电磁环境下误差才呈统计规律。
- 移动中不能检测，必须停下。
- 检测点可以超出目标区域（场地外也能测）。
- 坐标分量绝对值 ≤ 2,000,000 m（防数值异常）。
- 测向机与所有源视为同一平面（忽略高度差）。

**三种检测返回**

| 返回 | 含义 | 耗时 |
|---|---|---|
| `direction` + 示向度 | 收到信号，给方向 | 5 s |
| `near` | 距离 ≤ 5 m 且在覆盖角内，信号过强测不出方向，但**可直接清除** | 5 s |
| `no_signal` | 该频道无未清除源 / 超出接收距离 / 在定向覆盖角之外 | 5 s |

**清除（光学精确定位 + 激光）**

- 只有距离 ≤ 20 m 才能精确定位并清除；命中即清除，同一源只能被清除一次。
- **成败只与距离有关，与信号覆盖角无关** → Q4 里从"背面"照样能打死，难的只是发现与定位。
- `/clear` 的 channel 参数只用于指定目标，**不会切换测向机频道、不产生切换耗时**。
- 第二次对同一源 clear 返回"未发现"。

### 2.4 时间账本（虚拟秒）

| 动作 | 是否有独立指令 | 指令 | 耗时 |
|---|---|---|---|
| 开始 | 有 | `POST /enter` | 0 |
| 结束 | 有 | `POST /exit` | 0（任意位置均可退出） |
| 移动 | **无** | 由 `/measure`、`/clear` 的 `position` 推断 | 直线距离 / 5 |
| 切换频道 | **无** | 由 `/measure` 的 `channel` 推断 | 1（仅当与上一次被接受的 measure 频道不同） |
| 检测 | 有 | `POST /measure` | 5（三种返回都是 5） |
| 精确定位+清除 | 有 | `POST /clear` | 未发现 3；成功 5（= 光学 3 + 激光 2） |

**几个必背的换算**

- 走 1000 m = 200 s；走 100 m = 20 s。
- 一个点扫完 20 个频道 = 20×5 + 19×1 = **119 s**（比走 600 m 还便宜）。
- 一次成功清除的"动作成本"仅 5 s，落空 3 s → **开枪几乎免费，走路才贵**。

### 2.5 两个时钟，别搞混

| 时钟 | 是什么 | 约束 | 谁在看 |
|---|---|---|---|
| **虚拟时间** | 上面时间账本累加出来的"任务耗时" | 上限 100 小时（形同不存在） | **评分用**（定位清除总时间） |
| **程序运行时间** | `/enter` 到测试结束的真实墙钟时间 | **最长 20 分钟**，且受 25 分钟窗口限制，以先到者为准 | 表1 的"程序运行时间"列 |

含义：虚拟时间可以几千秒（≈ 虚拟世界里跑了一个多小时），但你的程序必须在**真实 20 分钟内**
把所有 HTTP 请求发完。所以客户端要轻：每步决策别做大优化，重计算放到 `/enter` 之前预计算。
另外 `/enter` 的响应会返回本次实际剩余程序运行时间，**必须用它，不要硬编码 1200 秒**
（晚于窗口开始 5 分钟进入时可用时间不足 20 分钟）。

### 2.6 通信协议要点（最容易白白丢分的地方）

- 接口：`POST http://127.0.0.1:2026`，端口可在模拟器空闲时修改。
- 必填：`arena_id: "default"`、`robot_id`（= **当前登录参赛队号**）、`request_id`。
- **每个新动作必须用新的 `request_id`**；只有网络中断后重试同一个动作时，才复用原请求内容和原 `request_id`。
- **串行**：逐次等待响应，不得并发发送不同动作。
- **双重校验**：既要看 HTTP 状态码，也要看响应体里的 `accepted`。
  `accepted = false` 时 `virtual_time_s` 为 0，动作没有生效——若不检查就会算错时间账本。
- **未知字段会导致 200 + `accepted = false`**：字段名必须严格照抄附件2。
- 日志：加密行为日志需 < 2 MB 才能上传 → **不要写高频轮询/重试风暴**。
- 5 秒倒计时期间、非测试期间、测试结束后接口未开放，连接失败属正常现象。
- 全程需联网；本机与服务器时间相差 > 60 s 不能启动新测试。

**符号约定**（论文统一使用）

| 符号 | 含义 |
|---|---|
| $G$ | 干扰源真实位置 |
| $S_i=(x_i,y_i)$ | 第 $i$ 个检测点 |

## 4. 分问题建模方案

### 4.1 问题 1：定位区域直径算法 + 覆盖性

**建模**

每个检测点给出的不是一个方向，而是一个**楔形**：真实方位角落在 $[\beta_i-1°, \beta_i+1°]$，
所以 $G$ 必在以 $S_i$ 为顶点、张角 2° 的凸锥内。凸锥 = 2 个半平面之交。
n 个检测点 → 2n 个半平面 → 定位区域 $\Omega$ 是**凸多边形**（题目图2 的红色四边形就是 n=2 的情形）。

**算法（三步）**

1. 构造 2n 个半平面 $a_k x + b_k y \le c_k$（用叉积符号判定左右侧，注意角度回绕）。
2. 半平面交求 $\Omega$：n 小用顶点枚举 + 可行性筛选 $O(n^2)$；要写得漂亮用
   排序增量法 / 双端队列 $O(n\log n)$（论文里给复杂度分析）。
3. 直径 $D$ = 凸多边形最远顶点对：暴力 $O(m^2)$，或**旋转卡壳** $O(m)$（推荐写进论文，加分点）。

**无界情形的处理（必须写进假设）**

若两条示向度近乎平行（$\theta_{\rm eff}\to 0$），$\Omega$ 会无界，直径不存在。
处理：用场地圆域（半径 1800 m）或一个大裁剪框截断，并声明"干扰源必位于目标区域内"这一先验。

**覆盖性问题：答案是"不一定"**

已用 `B题/scripts/geom_probe.py` 数值验证（结论见附录 C）：

- 对称构型（$R_1=R_2$）下，$R_{\rm mec}/(D/2) = 1.000000$，直径圆**恰好**覆盖，零余量。
- 随机非对称构型 40000 组中，**约 1.10% 覆盖失败**，最大超出量仅 **0.0586%**，
  且失败样本的有效交会角全部落在 **[88°, 90°]**。
- 具体反例（真实源在原点）：
  $S_1=(-454.826, 190.678)$，$S_2=(193.374, 460.468)$，$\theta = 90.035°$，
  $\Omega$ 的四个顶点为 $(-11.449,-4.367),(4.787,-11.509),(11.290,4.764),(-4.628,11.113)$，
  $D = 24.5031$ m，$D/2 = 12.2515$ m，而最小包围圆半径 $R_{\rm mec}=12.2587$ m > $D/2$。

**机理解释（论文里就这么讲）**

$\theta_{\rm eff}=90°$ 且 $R_1=R_2$ 时，$\Omega$ 是矩形，对角线即直径，四顶点共圆，
直径圆"刚好"覆盖，没有任何余量。一旦 $R_1\ne R_2$，矩形被剪切成一般四边形，
最小包围圆改由**三个**顶点决定（外接圆），半径二阶小量地超过 $D/2$。
$\theta_{\rm eff}$ 远离 90° 时，$\Omega$ 趋近平行四边形，长对角线所对的角 > 90°，
其余顶点严格落在圆内，覆盖有余量。

**工程结论（给 Q2/Q3 用）**

- 要"保证覆盖"，别用 $D/2$，直接算**最小包围圆**（Welzl 随机增量，期望 $O(m)$），
  以它的圆心作为清除点，半径 ≤ 20 m 就能一枪清掉。
- 兜底理论：**Jung 定理** —— 平面内直径为 $D$ 的凸集必能被半径 $D/\sqrt3\approx0.577D$ 的圆覆盖
  （等边三角形取等）。我们实测 $R_{\rm mec}/D \le 0.5003$，远优于该保守界。

### 4.2 问题 2：第二个检测点怎么选

**已知**：$S_1$ 与示向度 $\beta_1$。**未知**：源的真实距离 $R=|S_1G|$ 与 $R_{\rm eff}$。

**质量指标（已数值验证的经验公式）**

$$D \approx \frac{2R\tan\delta}{\sin(\theta_{\rm eff}/2)},\qquad
  R_{\rm mec}\approx \frac{R\tan\delta}{\sin(\theta_{\rm eff}/2)},\qquad \delta=1°$$

$R=1000$ m 时的对照表（`geom_probe.py` 输出，误差 < 1%）：

| $\theta$ | 30° | 45° | 60° | 75° | 90° |
|---|---|---|---|---|---|
| $D$（m） | 135.5 | 91.4 | 69.9 | 57.4 | 49.4 |
| $R_{\rm mec}$（m） | 67.7 | 45.7 | 34.9 | 28.7 | 24.7 |

**两条直觉**

1. $\theta$ 越接近 90° 越好。顺着视线往前跑（$\theta\to0$）是**最差**选择，$D\to\infty$；
   在 $S_1$ 与 $G$ 连线的延长线上取点（$\theta\to180°$）同样糟糕。
2. $R$ 越小越好，但 $R$ 是未知的，所以策略必须**自适应**。

**候选区域的解析刻画**

固定假设的 $G$（沿 $\beta_1$ 距离 $R$），使 $\angle S_1GS_2 = 90°$ 的 $S_2$ 轨迹是
**以 $S_1G$ 为直径的圆**（Thales 圆）。叠加约束后，候选区域为：

$$\mathcal{C}(R)=\Big\{S_2:\ \theta_{\rm eff}\ge\theta_{\min},\quad |S_2G|\le 1000\ \text{（最保守的 }R_{\rm eff}\text{）},\quad |S_2G|>5\Big\}$$

即"Thales 圆附近的一条月牙形带"，再与"以 $G$ 为心、半径 1000 m 的圆盘"求交。
由于 $R$ 未知，最终候选区域是 $\bigcup_R \mathcal{C}(R)$ 沿射线的族，论文里画成
"以 $S_1$ 为起点沿 $\beta_1$ 展开的扇形带 + 若干条 Thales 圆"的图。

**一次性清除的判据**

要求 $R_{\rm mec}\le 20$ m（这样以最小包围圆圆心开一枪必中）：

$$\frac{R}{\sin(\theta_{\rm eff}/2)} \le \frac{20}{\tan 1°} \approx 1146\ \text{m}$$

$\theta=90°$ 时需 $R\le 810$ m；$\theta=60°$ 时需 $R\le 573$ m。

**推荐策略（自适应两步走）**

1. 在 $S_1$ 拿到 $\beta_1$ 后，**横向**移动到一个使 $\theta_{\rm eff}$ 尽量接近 90° 的点 $S_2$
   （同时尽量缩短 $R$）。移动本身要计入成本，所以选点要在"几何好"与"路程短"之间权衡
   —— 论文里给出带权目标函数并做灵敏度分析。
2. 拿到 $\beta_2$ 后立即反解 $R$ 与 $\Omega$：
   - 若 $R_{\rm mec}\le20$ m → 直奔最小包围圆圆心，一枪清除；
   - 若不够 → 沿 $\Omega$ 长轴方向再逼近一次（缩短 $R$ 比换角度更划算），或补第三点。
3. 逼近到 5 m 内会返回 `near`（不给方向），此时**直接清除**，不要再测。

### 4.3 问题 3：全向源的全局搜索—定位—清除

**问题本质**：这是一个 **"带信息获取的覆盖搜索 + 滚动旅行商"** 复合运筹问题
（Search-and-Clear TSP with imperfect detection）。两个子问题耦合：
走的路既是"侦察"也是"转场"。

**先算清楚下界，定个目标**

- 每个频道至少要在其覆盖范围内被测到一次 → 20 个频道 × 5 s = 100 s 检测 + 19 s 切换 ≈ **119 s 的硬性检测开销**（若能集中在同一点扫完）。
- 但一个站点最多覆盖半径 $R_{\rm eff}\ge1000$ m 的圆盘，而场地半径 1800 m，
  面积比 $(1000/1800)^2\approx31\%$ → **单站不可能保证发现所有源**，需要多站覆盖。
- 用半径 1000 m 的圆盘覆盖半径 1800 m 的圆盘，站点数约需 5–7 个（影子模拟器里做覆盖设计验证）。
- 13 个源在半径 1800 圆盘内的 TSP 路程下界约 8200 m ≈ 1640 s。
- **目标：平均定位清除时间 ≤ 150–200 s/个**（对应 13 个源总虚拟时间 ≈ 2000–2600 s）。

**频道状态机**（每频道独立，这是剪枝的核心）

| 状态 | 含义 | 可用信息 |
|---|---|---|
| `UNKNOWN` | 从未测到有信号 | — |
| `SEEN` | 拿到 ≥1 条示向度 | 楔形半平面 |
| `FIXED` | 定位区域 $R_{\rm mec}\le20$ m | 可清除的目标点 |
| `CLEARED` | 已清除 | **该频道永久移出扫描列表**（每频道至多 1 个源） |
| `EXCLUDED` | 已证明该频道在**整个场地**无源 | 移出扫描列表 |

`EXCLUDED` 的判定（全向源）：若若干检测点覆盖了整个场地（每点半径 $\ge1000$ m 的圆盘并集 ⊇ 场地），
且这些点对该频道全部返回 `no_signal`，则该频道无源。这让后期每站的扫描频道数不断下降，
是节省 119 s/站 的关键。

**狗状态机**

```
SCAN（巡航扫描）
  ├─ 到达预设站点，按"未 CLEARED / 未 EXCLUDED"频道列表顺序逐个 measure
  ├─ 收到 direction → 该频道进 SEEN，记下楔形约束
  ├─ 收到 near      → 立刻 clear（免费命中）
  └─ 某频道达到 FIXED → 进入 TRACK
TRACK（交会定位）
  ├─ 按 Q2 策略选第二/第三检测点（横向机动，θ_eff→90°，兼顾路程）
  └─ 每测一次更新半平面集合，重算 Ω 与最小包围圆
APPROACH（逼近）
  └─ 走到最小包围圆圆心（或 Ω 内使 R_mec ≤ 20 m 的点）
CLEAR（清除）
  ├─ success → 频道置 CLEARED，触发全局路径重排
  └─ no_target_in_range（3 s）→ 局部廉价重试：在 Ω 内做小螺旋/网格补枪
                                 （补枪只要 3 s，重新交会要几百秒）
```

**路径规划：滚动重排（Rolling TSP）**

- 巡航站点集合用**圆盘覆盖设计**预先算好（例如中心 + 正六边形环的构型），保证
  半径 1000 m 圆盘并集覆盖场地。
- 站点访问顺序 + 已定位目标点用**最近邻构造 + 2-opt 改进**。
- **每清除一个源、每新定位一个源，就重排一次剩余路线**（滚动时域）。
  这是本题最重要的工程决策：静态 TSP 一定吃亏。

**终止条件**

所有 20 个频道都进入 `CLEARED` 或 `EXCLUDED` → 调用 `/exit`。
因为正式测试不告诉总数，**只能靠覆盖完备性来判定"清完了"**，这一点要在论文里明确论证。

### 4.4 问题 4：混入定向源

**难度升级在哪**

1. **发现难**：源可能整趟巡航都在"背面"，某频道反复 `no_signal`，无法区分
   "无源 / 太远 / 在背面"。
2. **交会难**：需要至少两个**都落在覆盖扇区内**的检测点才能交会；一个点在扇区内、
   另一个在扇区外时，第二条约束根本拿不到。
3. **排除难**：Q3 里"覆盖 + 全 no_signal ⟹ 该频道无源"的判据失效，
   必须升级为**三点包围排除准则**：若某频道在 3 个均在接收半径内的检测点上都返回 `no_signal`，
   且源可能位置（圆盘）被这 3 点构成的几何关系排除掉所有朝向可能，则该频道无源。
   （需要在论文里给出严格的几何论证与充分条件。）

**好消息（务必写进论文，这是本题的"钥匙"）**

附录2(8) 明确：**清除成败只与距离有关，与覆盖角无关**。
所以 Q4 的难度**纯粹在"发现与定位"**，一旦定位到 20 m 内，从背面照样一枪打死。
这意味着不需要为了"绕到正面"而额外跑路。

**定向源带来的额外信息（可以反向利用）**

在某点测到 `direction`，说明两件事：源在 $\beta\pm1°$ 楔形内，**且**该点位于源的定向扇区内
（即"源 → 该点"的方向与定向方向夹角 ≤ 90°）。这是一条关于 $(G, \phi)$ 的联合半平面约束。
多个检测点的这类约束叠加，可以反推定向方向 $\phi$ 的可行区间，进而预测"哪里还有信号"，
指导机动方向。

**信号突然丢失怎么办（追踪中断处理）**

- 不要沿原视线继续冲（很可能一路冲出扇区，越走越远）。
- 保留最后一次 `direction` 的楔形约束（它是硬信息，不因丢失而失效）。
- **横向机动**：沿垂直于最后视线的方向移动一段（例如 100–200 m），重新进入扇区的概率最大。
- 若连续 k 次 `no_signal`，退化为"圆环搜索"：以最后楔形与接收半径约束的交集区域为搜索域，
  按覆盖设计补测。

## 5. 工程实现方案

### 5.1 影子模拟器（`shadow/shadow_sim.py`）—— 最高性价比的投入

**为什么必须有**：正式测试只有 6 次机会，演练测试虽不限次数但要手工点、要联网、要等窗口。
调参需要跑几百局。影子模拟器复刻全部规则，本地无限次、可批量、可复现（固定随机种子）。

**必须复刻的规则**

- 随机生成 10–16 个源：频道从 1–20 中不放回抽取、位置在半径 1800 圆盘内均匀、
  $R_{\rm eff}\sim U[1000,1500]$、Q4 时随机若干定向源 + 定向方向 $\phi\sim U[0,360)$。
- 误差模型：每个 (源, 检测点) 组合绑定一个固定的 $[-1°,1°]$ 误差（同点重测不变），
  不同点独立。返回保留 2 位小数。
- 计时：移动 = 距离/5；切换频道 = 1（仅当与上一次被接受的 measure 频道不同）；
  measure = 5；clear = 5/3；enter/exit = 0。
- 返回：`direction` / `near`（≤5 m 且在扇区内）/ `no_signal`（无源、超距、或在扇区外）。
- 双重校验语义：未知字段 → HTTP 200 + `accepted=false` + `virtual_time_s=0`。
- 程序运行时间上限 20 分钟（真实墙钟）。

**批量跑分脚本**（`shadow/batch_run.py`）：固定 N 个种子跑 N 局，输出
清除率、平均定位清除时间、虚拟时间分解（移动/检测/切换/清除）、指令条数、
真实运行时间。**所有策略改动都用同一批种子做 A/B 对比。**

### 5.2 机器狗客户端骨架（`dog/`）

```
dog/
├── protocol.py    # HTTP+JSON：request_id 自增、双重校验、超时与同 id 重试
├── state.py       # 世界状态：频道状态机、楔形约束集、观测历史、时间账本
├── geometry.py    # 半平面交、凸多边形直径（旋转卡壳）、最小包围圆（Welzl）
├── planner_scan.py# Q3：覆盖设计 + 滚动 TSP + 狗状态机
├── planner_dir.py # Q4：定向源扩展（三点排除、扇区推断、丢失处理）
└── main.py        # 真模拟器入口：读 remaining_real_duration_s，全程守卫
```

**关键实现纪律**

- `planner` 与模拟器**完全解耦**：只吃"观测"，只吐"动作"。这样影子模拟器和真模拟器
  驱动同一个 planner，避免"本地好、真机崩"。
- 每次响应后**同时**更新两份时间：虚拟时间（用响应里的 `virtual_time_s`，别自己算）
  和真实剩余时间（用 `remaining_real_duration_s`）。
- 真实时间守卫：剩余 < 阈值（如 90 s）时切换到"保守收尾"模式——放弃未定位目标，
  优先清除已 `FIXED` 的，然后 `/exit`。宁可少清一个，不要超时被标记"超时退出"。
- JSONL 日志：每条指令一行，含 `request_id / action / position / channel / http_status /
  accepted / virtual_time_s / elapsed_real_s / result`。用于复盘、画论文图、核对时间账本。
- **绝不并发**，绝不复用 `request_id`（除网络重试）。

### 5.3 结果落盘规范

```
results/
├── q3_drill_<时间戳>_<种子>.jsonl
├── q3_formal_1.jsonl ... q3_formal_3.jsonl      ← 与测试案例编码一一对应
├── summary.csv    # 每局：案例编码/清除数/总数/总虚拟时间/平均/真实时间
└── figures/       # 论文用图（轨迹、定位区域、覆盖设计、时间分解）
```

表1 的四列必须能由 `summary.csv` 直接生成，**不要手抄**。

对，如果是**比赛现场直接用**，那我反而建议你**不要使用上一版那种超长总 Prompt**。

比赛现场最重要的是：

**快、稳、可控、能反复迭代。**

你不应该把大量时间花在“跟 AI 沟通格式”上，而应该让 AI 快速完成几个核心任务。

我建议你比赛时准备一个 **“数学建模 AI 作战 Prompt”**，然后配合 **7 个阶段 Prompt** 使用。

**比赛现场推荐工作流**

拿到题目

  ↓

① 快速拆题

  ↓

② 数据审查

  ↓

③ 模型候选

  ↓

④ 模型决策

  ↓

⑤ 数学建模 + 代码

  ↓

⑥ 结果 + 检验

  ↓

⑦ 红队审稿

  ↓

最终论文

其中最重要的是：

**不要让 AI 自己连续跑完整流程。**

每一步都让它停下来，你确认之后再进入下一步。

---

**① 第一阶段：快速拆题**

比赛刚拿到题目，直接把题目和附件给 AI，然后使用：

你现在是一名全国大学生数学建模竞赛资深建模专家。

我正在参加数学建模竞赛，下面是本题完整题目和附件信息。

【粘贴题目】

【附件说明/上传附件】

现在只进行“题目分析”，不要急着建立最终模型，不要写代码，不要编造数据。

请完成以下任务：

**1. 整体理解**

用简洁但专业的语言说明：

- 这道题研究的现实问题是什么？
- 数学上真正需要解决的问题是什么？
- 最终需要得到什么结果？

**2. 小问拆解**

建立表格：

|   |   |   |   |   |   |   |
|---|---|---|---|---|---|---|
|**小问**|**题目要求**|**数学本质**|**输入**|**输出**|**约束**|**与其他小问关系**|

判断每个小问属于：

- 优化
- 预测
- 评价
- 回归
- 分类
- 聚类
- 统计分析
- 机理建模
- 微分方程
- 图论
- 仿真
- 其他

并解释原因。

**3. 变量提取**

列出：

- 决策变量
- 状态变量
- 参数
- 输入变量
- 输出变量
- 约束条件
- 目标函数可能是什么

**4. 小问依赖关系**

用流程图或文字说明：

小问 1 → 小问 2 → 小问 3

明确哪些结果可以作为后续小问的输入。

**5. 关键难点**

指出本题最难的 3～5 个地方。

**6. 建模风险**

指出可能出现的：

- 数据不足
- 假设不合理
- 模型选择困难
- 样本量不足
- 数据泄漏
- 过拟合
- 结果无法验证
- 计算复杂度过高

**7. 建模路线**

最后给出一条推荐的整体路线：

题目 → 数据 → 小问 1 → 小问 2 → 小问 3 → 最终结论

注意：

不要现在确定最终模型。

如果题目信息不足，直接告诉我缺什么。

不要编造任何数据或结论。

**② 第二阶段：数据分析**

这一步非常关键。

特别是 CUMCM 比赛里，很多题最后不是模型不会，而是**数据没处理好**。

现在进入“数据审查阶段”。

请基于题目和我提供的附件，对所有数据进行系统检查。

不要建立最终模型。

**1. 数据概况**

给出：

- 数据量
- 行数
- 列数
- 变量类型
- 时间范围
- 单位
- 缺失情况

建立数据字典：

|   |   |   |   |   |   |
|---|---|---|---|---|---|
|**变量**|**含义**|**类型**|**单位**|**数据范围**|**缺失率**|

**2. 数据质量**

检查：

- 缺失值
- 重复值
- 异常值
- 极端值
- 单位问题
- 时间格式问题
- 分类编码问题

不要直接删除异常值。

对于每一个处理建议说明：

为什么这么处理？

**3. 数据关系**

根据题目需要分析：

- 相关性
- 共线性
- 趋势
- 周期性
- 时间依赖
- 空间关系
- 分布特征

**4. 数据泄漏**

如果涉及预测/机器学习：

重点检查：

- 训练集和测试集是否泄漏
- 是否使用未来数据预测过去
- 是否存在目标变量泄漏
- 时间序列是否应该采用时间顺序划分

**5. 数据预处理方案**

给出推荐方案：

|   |   |   |   |
|---|---|---|---|
|**问题**|**检测方法**|**推荐处理**|**原因**|

**6. 外部数据**

判断题目是否确实需要外部数据。

如果需要：

- 指出具体需要什么变量
- 推荐可靠数据来源
- 说明获取方法
- 不得编造真实数据

如果不需要外部数据，请明确说明：

当前题目可以仅依靠已有数据完成建模。

**7. 最终结论**

告诉我：

当前数据最适合哪些类型的模型？

暂时不要确定最终模型。

---

**③ 第三阶段：模型候选**

这时候再让 AI 开始想模型。

现在进入“模型设计阶段”。

基于前面的题目分析和数据分析，为每个小问提出 2～4 个候选模型。

注意：

不要为了创新而使用复杂模型。

**对每个小问分别输出：**

**方案 A：经典可靠方案**

说明：

- 模型名称
- 核心原理
- 为什么适合
- 数据要求
- 优点
- 缺点
- 创新空间
- 求解难度

**方案 B：改进方案**

说明：

- 相比经典模型改进在哪里
- 为什么需要改进
- 数学上如何体现
- 如何验证改进有效

**方案 C：创新方案**

只有在确实有必要时提供。

不要为了“高级”强行使用深度学习、强化学习、GNN、Transformer 等复杂模型。

**模型比较**

建立：

|   |   |   |   |   |   |   |   |
|---|---|---|---|---|---|---|---|
|**模型**|**适配性**|**创新性**|**可解释性**|**稳定性**|**数据要求**|**计算难度**|**推荐度**|

评分 1～10。

最后告诉我：

如果你是国赛一等奖评委，你最推荐哪一个？

并重点解释：

为什么选择它，而不是其他模型？

不要建立最终公式，不要写代码。

---

**④ 第四阶段：模型决策**

这一阶段最好由**你和 AI 一起决定**。

你把上一阶段结果看完之后，再问：

现在假设你是一名数学建模国赛一等奖评委。

请重新审查上一阶段提出的所有模型。

从以下角度判断：

1. 是否真正解决题目问题
2. 数学是否严谨
3. 数据是否支持
4. 参数是否可以估计
5. 算法是否可以实际运行
6. 结果是否容易验证
7. 是否具有合理创新
8. 是否适合在比赛时间内完成
9. 是否容易写成论文
10. 是否存在明显模型风险

然后给出：

**最终推荐方案**

对于每个小问明确：

最终模型 = ______

并给出：

选择理由 = ______

同时给出：

**备用方案**

如果最终模型出现以下问题：

- 数据不足
- 算法不收敛
- 模型效果差
- 假设无法成立

应该切换到什么模型？

最后给出：

整道题最终建模路线图。

现在暂时不要写代码。

**⑤ 第五阶段：建模 + Python**

这时候才开始让 AI 真正干活。

而且这一阶段最好**一问一问做**，不要三个小问一起生成。

现在开始解决第【X】问。

最终采用：

【填写最终模型】

请完成“数学模型 + Python 代码”的完整实现。

**第一部分：数学建模**

按照：

现实问题→ 数学抽象→ 模型假设→ 变量定义→ 参数定义→ 目标函数→ 约束条件→ 完整数学模型→ 求解方法

逐步建立。

要求：

1. 每个变量必须定义。
2. 每个参数必须说明。
3. 每个公式必须说明现实意义。
4. 核心公式必须给出推导过程。
5. 最终模型必须与题目要求对应。
6. 检查模型是否满足所有约束。

**第二部分：算法**

说明：

- 为什么选择该算法？
- 算法输入是什么？
- 算法输出是什么？
- 参数如何设置？
- 停止条件是什么？
- 是否存在局部最优？
- 是否需要多次运行？

**第三部分：Python 代码**

提供完整可运行代码。

要求：

- 使用清晰变量名
- 分模块组织
- 数据读取
- 数据预处理
- 模型计算
- 参数估计
- 模型求解
- 结果输出
- 可视化

代码必须与前面的数学公式一一对应。

请标注：

数学公式（X）对应代码中的哪一部分。

**第四部分：代码检查**

在输出代码后检查：

- 是否存在变量未定义
- 是否存在维度错误
- 是否存在数据类型错误
- 是否存在索引错误
- 是否存在算法参数问题
- 是否存在数据泄漏

如果当前环境可以实际运行代码，请实际运行。

如果不能运行：

必须明确告诉我：

“代码尚未实际运行。”

禁止虚构运行结果。

---

**⑥ 第六阶段：结果 + 模型检验**

这一阶段你把 AI **实际运行得到的结果**给它。

现在基于真实运行结果分析第【X】问。

以下是实际运行结果：

【粘贴结果】

请不要重新编造任何数值。

**1. 基础结果分析**

解释：

- 最优值/预测值
- 参数
- 误差
- 排名
- 趋势
- 最大值/最小值

并说明这些结果在题目背景中的实际含义。

**2. 约束检查**

逐项检查：

是否满足题目中的全部约束？

如果不满足：

必须明确指出。

**3. 模型效果**

根据模型类型选择合适指标。

不要机械使用 RMSE、R²等。

说明：

为什么选择这些指标。

**4. 敏感性分析**

选择最重要的参数进行：

- -20%
- -10%
- 原值
- +10%
- +20%

分析结果变化。

**5. 鲁棒性分析**

对输入数据进行合理扰动。

分析：

- 输出均值
- 标准差
- 最大偏差
- 稳定程度

**6. 与基准模型比较**

如果有经典模型/原始方案：

比较：

|   |   |   |   |
|---|---|---|---|
|**指标**|**基准模型**|**改进模型**|**提升**|

证明：

为什么改进模型更好。

如果改进模型没有明显优势：

必须诚实指出。

**7. 最终结论**

用数学结果支持现实意义。

禁止出现没有数据支撑的夸大结论。

**⑦ 第七阶段：红队审稿**

这是我最建议你在比赛现场保留的一步。

模型做完后，不要马上写论文。

先让 AI **攻击自己的模型**。

现在停止作为我的建模助手。

请切换身份：

你是一名极其严格的全国大学生数学建模竞赛一等奖评委。

请对当前完整建模方案进行“攻击性审查”。

不要帮助我证明模型正确。

你的任务是尽可能寻找问题。

重点检查：

**1. 题目理解**

有没有真正回答题目？

**2. 模型假设**

有没有：

- 过强假设
- 无依据假设
- 与题目冲突的假设

**3. 变量**

变量定义是否完整？

是否存在：

- 漏变量
- 冗余变量
- 变量含义不清

**4. 数学模型**

检查：

- 公式是否正确
- 目标函数是否合理
- 约束是否完整
- 量纲是否一致

**5. 数据**

检查：

- 样本量
- 异常值
- 缺失值
- 数据泄漏
- 共线性
- 数据是否支持模型

**6. 算法**

检查：

- 是否可以稳定求解
- 是否存在局部最优
- 是否对初值敏感
- 参数是否合理

**7. 结果**

检查：

- 是否过拟合
- 是否存在结果解释过度
- 是否存在无法解释的异常结果

**8. 模型检验**

检查：

检验方法是否真的能够证明模型有效？

**9. 创新性**

判断：

创新是否真正解决了问题？

而不是简单更换了模型名称。

**10. 论文风险**

预测评委最可能质疑的 5 个问题。

最终输出：

|   |   |   |   |
|---|---|---|---|
|**问题**|**严重程度**|**可能影响**|**修改建议**|

严重程度：

★★★★★ 致命问题★★★★ 严重问题★★★ 明显问题★★ 一般问题★ 轻微问题

最后告诉我：

如果只能修改 3 个地方，最应该修改哪 3 个？

**比赛现场最重要的一条**

你可以把整个比赛过程压缩成下面这张“作战卡”：

|**时间**|**AI 任务**|**你的任务**|
|---|---|---|
|0～1 h|拆题|理解题目|
|1～2 h|数据分析|判断数据是否可靠|
|2～3 h|模型候选|选模型|
|3～6 h|建模+代码|检查数学逻辑|
|6～12 h|跑实验|分析结果|
|12～18 h|检验+优化|判断模型是否成立|
|18～24 h|红队审查|推翻/修改模型|
|后期|论文素材|人工审核论文|

**不要让 AI 替你决定一切。**

你作为建模手，最应该把时间放在：

**为什么这样建模？**

**这个假设合理吗？**

**这个模型真的符合题目吗？**

**结果有没有实际意义？**

**如果评委质疑我，我怎么解释？**

而代码、公式整理、数据处理、画图、重复计算这些工作，则尽可能交给 AI。

另外，如果你比赛时打算用 **ChatGPT + Python + 本地文件**完成整个流程，我建议你提前把**“附件分析、Python 自动读取 Excel/CSV、自动画图、自动跑模型、自动生成结果表”**这一套工作流练熟。比赛现场会比单纯依赖 Prompt 稳定很多。

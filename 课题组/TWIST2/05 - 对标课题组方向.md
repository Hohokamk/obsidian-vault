# 对标课题组方向

上级：[[00 - TWIST2 总览]]

相关：[[论文]]、[[数据采集领域]]、[[预习作业]]

## 现有判断（整理自旧笔记）

- 人体数据来源分两类：真实物理世界采集 vs 世界模型生成。
- 物理采集分穿戴式设备与相机采集：ego 头戴设备适合 manipulation，但对 loco-manipulation 不完整（缺外部信息与自身移动信息）；UMI 夹爪、数据手套只能覆盖局部动作。
- 组内已有 IMU 动捕能力：Loose Inertial Poser（CVPR 2024，宽松外套 IMU 动捕）、TIC（SIGGRAPH 2025 最佳论文，动态 on-body IMU 标定）；同时关注 EgoHumanoid（RSS 2026）与 Nymeria（ECCV 2024）这类 ego 数据工作。
- 个人预习路线：先跑通 LIP/TIC 代码 -> 用 DIP-IMU/TotalCapture 复现姿态估计 -> 复现一个模块 -> 最后做一个"IMU 采集 + 同步 + 实时可视化"的小系统当投名状。

## TWIST2 的位置

TWIST2 正好落在组内两条线的交叉点：**IMU 类人体动捕** 与 **人形机器人数据采集**。

它给出的闭环：人体动捕（PICO IMU trackers）-> 在线重定向（GMR）-> 人形机器人全身执行（RL 追踪策略）-> 记录（RGB + 本体状态 + 动作 + 语言）。这补上了"ego 视频没有动作标签、数据手套没有腿"的空档，而且采的是 loco-manipulation 全身体验。

## 对照表

| 维度 | TWIST2 | 课题组现状/关注方向 |
| --- | --- | --- |
| 人体动捕 | PICO 4 Ultra + Motion Tracker（无基站，IMU 类方案，闭源硬件） | Loose Inertial Poser / TIC（自研 IMU，可更便宜、可开放） |
| 重定向 | GMR（独立开源，MuJoCo） | 尚无自有重定向管线，可作切入点 |
| 机器人执行 | Unitree G1 + 29 DoF RL 追踪器（ONNX） | 需先确认硬件可及性 |
| 视觉 | ZED Mini 双目 + 2-DoF 脖子 | 与 Nymeria/EgoHumanoid 的 ego 数据形成对照 |
| 数据格式 | RGB + state + action + 语言描述 | 与"多传感器同步 + 实时可视化"目标一致 |
| 部署 | ONNX 50 Hz，teacher-student + DAgger | 工程范式可直接借鉴 |

## 可结合的切入点

1. **自研 IMU 动捕替换 PICO**：用 LIP/TIC 的输出接 GMR，再驱动 G1 仿真。关键难点是 IMU 方案的全局根轨迹（漂移）与关节角精度；TWIST2 观测只用局部 root 速度 xy，可作为兼容设计参考。
2. **重定向质量评测**：GMR 论文标题即 "Retargeting Matters"。在 sim2sim 里量化"人体骨骼 -> G1 关键点误差 -> 策略跟踪误差 -> 失败模式"，不需要机器人，是成本最低的第一篇复现报告。
3. **采集格式与指标复刻**：照搬 `EpisodeWriter` 的数据结构，定义自己的评测指标（每 15 分钟 episode 数、成功率、端到端时延、跟踪误差），给自己的采集平台做 baseline。
4. **课程机制消融**：future-frame 观测、CMP 掩码、FALCON 式力课程在开源配置里都关着，正好适合做消融实验，与组内优化/学习背景匹配。
5. **平台迁移**：`deploy_real/robot_control/configs` 里已有 h1、h1_2、t1 的配置，但训练环境只实现了 G1；迁移需要 URDF、奖励、动作维度的适配，可作为长期工程项。

## 投名状建议（与预习作业衔接）

分三步，风险递增：

1. **跑通 + 评测（2-3 周）**：本机 sim2sim + 示例动作回放，记录 FPS、跟踪误差、失败模式，写一份复现报告。产出：能跑的系统 + 数据。
2. **接入自研动捕（1-2 月）**：公开 IMU 数据集或实时 IMU 套件 -> GMR -> G1 仿真，录一条 episode，量化"重定向误差 -> 策略误差"的传递，和 PICO 路线对比。产出：差异化 demo + 误差分析。
3. **小型采集系统**：IMU 多传感器同步 + 蓝牙 + 实时可视化 + 简版数据录制。产出：对组里直接有用的工具，也是预习作业里说的"多传感器同步 + 实时可视化"。

可选加分项：对 future-frame/CMP/力课程做仿真消融，写成小论文素材。

## 需要和导师确认的问题

- 组里能否用到 G1（或别的 29 DoF 人形）、PICO 4 Ultra、ZED、GPU 服务器？
- 目标场景是哪种 loco-manipulation（搬箱、开门、踢球、操作台）？
- 数据与投稿限制：AMASS/OMOMO 研究许可、机器人厂商数据协议？
- 路线选择：做"机器人无关的人体数据采集"还是"机器人执行数据"？
- 差异化定位：自研 IMU 动捕 + 开源重定向能否做得比 PICO 方案更便宜、更开放？

## 建议阅读顺序

TWIST2 论文 -> GMR 论文 + 仓库 -> TWIST1 -> iDP3 -> 组内 TIC / Loose Inertial Poser -> EgoHumanoid / Nymeria

> [!success] 一句话结论
> TWIST2 对课题组最大的价值不是那套 RL 控制器，而是"动捕 -> 重定向 -> 执行 -> 录制"的完整工程模板；它与组内 IMU 动捕能力互补，最小可行的切入点是先用公开数据把 GMR -> G1 仿真这条链路跑通并量化误差。

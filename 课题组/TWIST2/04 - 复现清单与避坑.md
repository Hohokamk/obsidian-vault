# 复现清单与避坑

上级：[[00 - TWIST2 总览]]

## 能复现到什么程度

| 手上的资源 | 能做的事 |
| --- | --- |
| 一块 NVIDIA GPU + Ubuntu（无机器人） | 环境搭建、sim2sim、离线动作回放、用示例数据训练、导出 ONNX |
| 加 PICO 4 Ultra + trackers | 在线遥操作（仿真里采数据）、重定向效果评估 |
| 加 Unitree G1（29 DoF） | sim2real、真机全身遥操作、真机数据采集 |
| 加 ZED Mini + 脖子硬件 | 第一人称视觉回传、视觉 + 状态 + 动作的完整 episode |

## 安装顺序

1. `conda create -n twist2 python=3.8`，从 NVIDIA 官网下载 IsaacGym 并 `pip install -e isaacgym/python`（不是 pip 包）。
2. 安装仓库内三个包：`rsl_rl`、`legged_gym`、`pose`（各自 `pip install -e .`）。
3. 安装依赖：numpy 1.23.0、mujoco、mujoco-python-viewer、redis[hiredis]、onnx/onnxruntime-gpu、customtkinter、pyttsx3、hydra-core、opencv-python、wandb、pyfqmr、flask、dill 等（README 有完整命令）。
4. Redis：`apt install redis-server`，改 `bind 0.0.0.0` + `protected-mode no`，重启服务。
5. 真机部署需要自编译 [YanjieZe/unitree_sdk2](https://github.com/YanjieZe/unitree_sdk2) 的 Python 绑定，把 `unitree_interface*.so` 拷进 conda 的 site-packages。
6. `conda create -n gmr python=3.10`，clone 并 `pip install -e GMR`，再装 `libstdcxx-ng`。
7. PICO 侧：头显装 XRoboToolkit client；PC 装 XRoboToolkit PC Service deb；编译 PC Service pybind（`XRoboToolkit-PC-Service-Pybind`）。
8. 数据（可选）：从作者的 Google Drive 下 TWIST2 dataset，解压后改 `legged_gym/motion_data_configs/twist2_dataset.yaml` 的 `root_path`。仓库自带 10 条示例动作，足以做验证。

## 最小验证路径（不需要机器人）

目标：在本机把"低层策略 + 离线动作回放"跑起来。

```bash
# 终端 A：跑低层控制器（MuJoCo + 提供的 ONNX）
bash sim2sim.sh

# 终端 B：跑动作服务器（默认发送站立姿态，可换成示例 pkl）
bash run_motion_server.sh
```

- 预期现象：MuJoCo 里机器人先站立不动（Redis 默认发 stand pose），终端打印策略 FPS（期望 50，笔记本常见 30-40）。
- 把 `run_motion_server.sh` 里的 `motion_file` 换到 `assets/example_motions/*.pkl`，机器人应开始走路。
- 这一步需要 `import isaacgym` 成功（script 顶部有依赖）、Redis 在跑、ONNX 路径正确；PICO、机器人、ZED 都不需要。

## 完整流程命令

```bash
bash train.sh 1021_twist2 cuda:0      # 训练（需要数据集；task = g1_stu_future）
bash to_onnx.sh <policy_path.pt>      # 导出 ONNX
bash eval.sh <exptid> cuda:0          # 仿真评估 + 录视频
bash run_motion_server.sh             # 离线动作流
bash teleop.sh                        # 在线 PICO 遥操作
bash sim2sim.sh                       # 低层：MuJoCo
bash sim2real.sh                      # 低层：真机（改网卡名）
bash data_record.sh                   # 30 Hz 录数据
bash gui.sh                           # 图形化入口（customtkinter）
```

## 已知坑（已核实）

> [!warning] 文档与仓库不同步
> `doc/TELEOP.md` 引用的 `docker_neck.sh`、`docker_zed.sh`、`teleop_motion_gen.sh`、`teleop_data_record.sh` **都不在仓库里**；`doc/TWIST2_NECK.md` 的 BOM 与组装教程也是空的。真机链路需要自己补。

1. **硬编码路径**：`twist2_dataset.yaml` 的 `root_path` 指向作者机器（`/home/yanjieze/...` 和 Amazon 内网路径）；`eval.sh` 里 motion_file 也是作者本地路径，用前必改。
2. **配置引用了不存在的文件**：`g1_mimic_distill_config.py` 里 `motion_file` 指向 `g1_omomo+mocap_static+amass_walk.yaml`，仓库里只有 `twist2_dataset.yaml`；训练默认 task 是 `g1_stu_future`，其 config 已指向 `twist2_dataset.yaml`，但做别的任务时要自己统一。
3. **上层代码未开源**：visuomotor policy（基于 iDP3）、机载 neck 与 ZED 推流代码在仓库外，README 明确说明还在整理。
4. **Redis 安全**：官方要求 `bind 0.0.0.0` + `protected-mode no`，局域网内等于无鉴权开放，实验网络要隔离。
5. **双环境切换**：`twist2`（py3.8）与 `gmr`（py3.10）不能合并；IsaacGym 还挑驱动/CUDA 版本。
6. **FPS 敏感**：策略按 50 Hz 训练，笔记本实测约 39 Hz 时跟踪会变差，采集前先测 FPS。
7. **数据版权**：AMASS、OMOMO 仅限研究用途；示例动作与 20k/25k ONNX ckpt 可直接用于测试。
8. **网卡名**：`sim2real.sh` 里 `net=eno1` 是作者机器，需替换成自己的接口名。
9. **Vault 里的克隆是临时的**：`C:\Users\Hohokam\AppData\Local\Temp\TWIST2_repo` 会被系统清理，建议把仓库挪到固定的代码目录（如 `D:\...\code\TWIST2`）。
10. **仿真与真机的控制频率口径不一致**：训练配置是 `dt=0.002`、`decimation=10`（50 Hz），真机 `control_dt=0.02`（50 Hz），但 `sim2sim.sh` 传 `--policy_frequency 100`，而 sim server 里 `sim_dt=0.001`，实际会以 100 Hz 跑策略；README 里打印的 Expected FPS 却是 50。复现时先核对这个参数，必要时把它改成 50 与训练一致，否则历史窗口覆盖的时间尺度会不同。

## 复现检查清单

- [ ] GPU 与驱动能满足 IsaacGym（先在官方示例里跑通）
- [ ] 仓库挪到固定目录，`git log` 确认版本
- [ ] Redis 可 ping 通，键能被 `redis-cli monitor` 观察到
- [ ] `sim2sim.sh` 能加载 ONNX 并打印 FPS
- [ ] 示例动作回放能让机器人走路
- [ ] （有硬件）`sim2real.sh` 网卡、默认姿态、急停键都验证过
- [ ] 数据录制能生成 `episode_xxxx/data.json` 与图片帧
- [ ] 记录环境版本与问题，方便回报给作者

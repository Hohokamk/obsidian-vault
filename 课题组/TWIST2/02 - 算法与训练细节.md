# 算法与训练细节

上级：[[00 - TWIST2 总览]]

## 任务定位

低层策略不是最终产品，而是**数据采集基础设施**：把高层（人 -> G1 重定向）产生的运动参考，稳定地跟踪到真机上。所以优化目标是全身运动跟踪精度 + 抗扰动鲁棒性，而不是任务成功率本身。

## 控制与动作空间

| 项 | 配置 |
| --- | --- |
| 动作维度 | 29（腿 12 + 腰 3 + 臂/腕 14） |
| 仿真步长 | `dt = 0.002`（500 Hz） |
| 控制抽取 | `decimation = 10` -> 策略 50 Hz |
| 动作缩放 | `action_scale = 0.5` |
| 刚度 | 髋 100、膝 150、腰 150、踝 40、肩/肘/腕 40 |
| 阻尼 | 髋 2、膝 4、腰 4、踝 2、肩/肘/腕 5 |
| 训练规模 | 4096 并行环境，`max_iterations` 约 1e6 |

## 观测结构（部署输入 1402 维）

单帧 127 维 = 35 维运动参考（mimic obs）+ 92 维本体感知（proprio）：

| 组成 | 维度 | 说明 |
| --- | --- | --- |
| root 速度 xy（机体坐标） | 2 | 替代原来的 xy 位置，便于 sim2real |
| root 高度 z | 1 | |
| roll / pitch | 2 | 不喂 yaw，避免绝对朝向依赖 |
| yaw 角速度 | 1 | |
| 目标关节角 | 29 | 来自重定向或动作库 |
| 角速度 | 3 | 乘 0.25 缩放 |
| roll / pitch | 2 | |
| 关节角偏差 | 29 | `(q - q_default) * 1.0` |
| 关节速度 | 29 | 乘 0.05 缩放，踝关节 4 个索引置零 |
| 上一帧动作 | 29 | |

历史与未来：

- 历史窗口 10 帧 + 当前帧 = **11 x 127 = 1397**
- 额外 "future token" **35** 维（开源配置 `TAR_MOTION_STEPS_FUTURE = [0]`，即当前帧运动参考的复制）
- 合计 **1402** 维，与 `server_low_level_g1_real.py` 中 `total_obs_size` 一致

> [!note] 论文里的"未来动作帧"机制
> 代码保留了看未来 10 帧（`[5,10,...,50]` 或 `[1..10]`）的开关与课程掩码（CMP）、FALCON 式力扰动课程，但**开源配置全部关掉**：`enable_force_curriculum = False`、`use_error_aware_sampling = False`、`motion_dr_enabled = False`。复现时不要误以为这些已生效。

## Teacher-Student 蒸馏

| 角色 | 观测 | 说明 |
| --- | --- | --- |
| Teacher（`g1_priv_mimic`） | 特权信息：未来 20 帧运动参考（步长 1..95，间隔 5）、9 个关键身体位置、接触掩码、base 线速度、root 高度、priv latent 63 维 | 只在仿真里训练，不部署 |
| Student | 本体感知 + 11 帧历史 + 35 维当前参考 | 通过 DAgger 模仿 teacher 动作 |

DAgger 关键超参（`G1MimicStuCfgDAgger`）：warm-up 100 iters；`dagger_coef` 从 0.2 退火到 0.1（60k 步）；actor 隐层 `[1024,1024,512,256]`。另有 DaggerPPO 变体（`ActorCriticTeleop` + `DaggerPPO`）。

PPO 侧（student RL 配置）：隐层 `[512,512,256,128]`，SiLU + LayerNorm，`obs_context_len = 11`，`motion_latent_dim = 128`，动作标准差分组 `[0.7]*12 + [0.4]*3 + [0.5]*14`（腿/腰/臂分开，符合不同抖动敏感度）。

## 域随机化（sim2real 关键）

| 项 | 范围 |
| --- | --- |
| 重力 | ±0.1，每 4 s 重采样 |
| 摩擦 | 0.1 - 2.0 |
| 基座质量 | ±3 kg |
| 质心 | ±0.05 m |
| 推力 | ≤1.0 m/s，每 4 s 随机推 |
| 电机强度 | 0.8 - 1.2x |
| 动作延迟 | 8 步 buffer（模拟通信/执行延迟） |
| 观测噪声 | dof_pos 0.01、dof_vel 0.1、lin/ang vel 0.1、gravity 0.05、imu 0.1；50k 步内逐渐加大 |

## ONNX 导出与部署

- `to_onnx.sh <policy.pt>` -> `legged_gym/scripts/save_onnx.py`，用 `HardwareStudentFutureNN` 包一层 `ActorFuture` + normalizer，导出约 3 MB ONNX。
- 部署端 `OnnxPolicyWrapper` 兼容 torch 调用签名，优先 `CUDAExecutionProvider`，失败回落 CPU。
- 真机侧细节：踝关节速度置零、可选 EMA 动作平滑（`--smooth_body 0.5`）、FPS 监控（期望 50 Hz，实测约 39 Hz）。

## 值得借鉴

1. "特权教师 -> 本体学生 -> ONNX" 是干净可复用的 sim2real 模板。
2. 观测里刻意去掉绝对 yaw、用局部速度，减少定位依赖。
3. 奖励对踝关节单独加倍平滑，说明接触冲击是主要抖动源。
4. 未来帧/力课程等机制留了扩展点但默认关闭，复现时可作为消融的出发点。

## 烧录 - 代码写入与存储
这就要用到烧录器（也叫仿真器/下载器）。我们通过电脑连接烧录器，再通过主控板上的SWD调试接口（位于板子背面），将电脑编译生成的二进制机器码（.bin或.hex文件），以电信号的形式写入到MCU内部的Flash存储器（闪存）中。这个Flash存储器就像是主控的「固态硬盘」，具有**电可擦非易失性**。这意味着一旦代码烧录成功，无论你给板子断电、上电多少次，代码都会牢牢保存在芯片内部。每次主控重新上电时，MCU的内核都会自动从Flash的起始地址读取代码并开始执行。因此，烧录器和SWD接口，就是连接我们虚拟代码与具身智能硬件的「桥梁」。

## 通信

### 通信协议
https://www.bilibili.com/video/BV1WmsZeWEFB?t=614.2

通信有以下几种模式：
![[Pasted image 20260708215159.png]]

#### UART 通用异步接收器/发送器
异步：发送方和接收方可以独立地接收或发送数据

#### I<sup>2</sup>C集成通路总线（同步通信）

核心特点：

- **两线制**：仅需两根信号线即可完成通信[](https://www.eet-china.com/mp/a329834.html)。
    
    - **SCL (串行时钟线)**：由主设备产生，用于同步数据传输。
    - **SDA (串行数据线)**：用于双向传输数据。
        
- **硬件简单**：总线上的设备通过**开漏（Open-Drain）** 输出连接到总线，因此必须在外部**添加上拉电阻**才能保证信号电平正常[](https://www.eet-china.com/mp/a7483.html)
    
- **主从结构**：通信由主设备（Master/Controller）发起并生成时钟，从设备（Slave/Target）响应[](https://docs.linuxkernel.org.cn/i2c/summary.html)。总线支持**多个主设备**和**多个从设备**[](https://www.eet-china.com/mp/a329834.html)[](https://www.techphant.cn/blog/104007.html)。
    
- **地址寻址**：每个从设备都有唯一的地址（通常为7位或10位），主设备通过地址来指定通信对象[](https://www.eet-china.com/mp/a329834.html)[](https://www.eet-china.com/mp/a21533.html)[](https://www.techphant.cn/blog/104007.html)。
    
- **半双工通信**：数据可以在两个方向上传送，但同一时刻只能单向传输[](https://www.eet-china.com/mp/a329834.html)
![[Pasted image 20260708221416.png]]

#### SPI 串行外设接口（更快的同步通信）
全双工、主从式接口，三线式或四线式
![[Pasted image 20260708221216.png]]

#### CAN通信（控制器局域网络Controller Area Network）
CAN通信是一种异步通信。只有CAN_H和CAN_L两条信号线。半双工，同一时刻只能有一个节点发送信号，其他节点只能接收。
![[Pasted image 20260708222624.png]]
![[Pasted image 20260708221950.png]]
单片机发送信号时，CAN收发器将普通信号转化为差分信号；单片机接收信号时，CAN收发器将差分信号转化成普通电平信号。
**差分信号**：
用CAN HIGH和CAN LOW两根线表示一个信号。
发送低电平，两根线的电压差更大，是显性电平，表示逻辑0。而如果给收发器发送高电平，两根线的电压差为0，是隐性电平，表示逻辑1。
两根线是双绞线缠绕，如果信号受到干扰，也是两根线的信号一起受到干扰，最后的压差保持不变，可以保证传输的信息不受干扰，因此CAN通信可以传输的距离很远。
![[Pasted image 20260708223054.png]]

#### USB接口
仅作为5V供电输入，暂不支持数据通信，无法读取/烧录数据。

### 通信接口区使用规范
通信Pin口操作不当易损毁控制链路，需严格遵守以下规范： 
**机械插拔规范（拒绝寸劲**）：4-Pin白座子为SMT贴装，焊盘抗剥离能力有限。插拔时需捏紧胶壳平行发力、顺卡槽垂直操作，严禁歪斜时猛拽，否则会直接拽落焊盘导致主控板报废。 
**严禁热插拔**：通电状态下插拔CAN/串口线会产生高压浪涌，易击穿收发器或主控引脚。务必断电后再进行接线与调试。

## 超级电容

超级电容分为控制板和电容组控制板，控制板也分上层控制板和下层功率板。电容组由 9 个电容组成，上限电压 24V，最多能储存能量 1980J。

![[Pasted image 20260709112309.png]]
![[Pasted image 20260709112319.png]]

超级电容可以看做**额外的供能单位**，可以将电源提供的多余功率储存，并在需要的时候提供更多的功率。例如：设步兵的上限功率是 50W，在平时的移动中，使用的功率只有 20W，则多余的 30W 用于给电容组充电，即将多余的能量先储存在电容组中。在需要时 （比如小陀螺高速旋转，快速移动），电容组就可以提供额外的功率，比如在高速小陀螺时，需要 90W 的功率，但电源提供的上限功率只有 50W，多余的 40W 就由超级电容提供。这样就可以实现机器人在短时间内大功率运行，也就是在短时间内跑的得更快，转得更快。此外超电还可以计算底盘功率，并反馈给主控。

用来表达你想将一些提交复制到当前所在的位置（HEAD）下面

而当你不知道提交记录的哈希值时，可以使用交互式rebase：

交互式变基就是指使用带参数 `--interactive`（或简写为 `-i`）的 `rebase` 命令

如果你在命令后增加了这个选项, Git 会打开一个用户界面，向你展示哪些提交即将被复制到变基目标的下方。它还会显示这些提交的哈希值和提交信息，这对于理清脉络非常有帮助。

git rebase -i HEAD~4
表示可选择head往上3个parent复制或丢弃并决定它们的顺序，然后把它们依此复制创建新的分支。

Git 的 tag 可以（在某种程度上 —— 因为标签可以被删除后重新在另外一个位置创建同名的标签）永久地将某个特定的提交命名为里程碑，然后就可以像分支一样引用了。更难得的是，它们并不会随着新的提交而移动。你也不能切换到某个标签上面进行修改提交，它就像是提交树上的一个锚点，标识了某个特定的位置。

git tag v1 C1
我们将这个标签命名为 `v1`，并且明确地让它指向提交记录 `C1`，如果你不指定提交记录，Git 会用 `HEAD` 所指向的位置。

由于标签在代码库中起着“锚点”的作用，Git 还为此专门设计了一个命令用来**描述**离你最近的锚点（也就是标签），它就是 `git describe`！Git Describe 能帮你在提交历史中移动了多次以后找到方向.

`git describe` 的​​语法是：

`git describe <ref>`

`<ref>` 可以是任何能被 Git 识别成提交记录的引用，如果你没有指定的话，Git 会使用你目前所在的位置（`HEAD`）。

它输出的结果是这样的：

`<tag>-<numCommits>-g<hash>`

`tag` 表示的是离 `ref` 最近的标签， `numCommits` 是表示这个 `ref` 与 `tag` 相差有多少个提交记录， `hash` 表示的是你所给定的 `ref` 所表示的提交记录哈希值的前几位。

当 `ref` 提交记录上有某个标签时，则只输出标签名称

==ln(link)创建链接文件==
ln -s ... ...
创建...的软链接文件...,不加-s默认创建...的硬链接文件...

>[!NOTE]
**软链接文件（符号链接文件）**:
指向目标文件的快捷方式(相当于间接访问),大小非常小.如果删除目标文件,软链接文件无法正常访问.软链接可以指向文件或者目录.
>
**硬链接文件**:
创建一个与原文件i节点相同的文件.删除原文件后,硬链接仍然可以正常访问.硬链接只能指向文件,不能指向目录.原文件和硬链接是同一个文件的不同名字.修改其中一个文件的内容,另一个文件的内容也会随之发生变化.
ls信息列表中数字代表硬链接数量.

e.g.
ln -s hello.txt link.txt
表示link.txt是link.txt -> hello.txt 的软链接文件

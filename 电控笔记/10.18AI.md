## 先说一个坑：`sample_time_us` 不是 IMU 的采样时刻

我核了 `xuc.cpp` 的取值链：

```
Decode():  frame_time_us = m_uart->GetRxTimeUs()
           ↑ m_uart 是 uart4 —— 上位机，不是 IMU
Encode():  t_us = frame_time_us
           PushRef(epoch, seq, t_us, yaw, pitch)
```

**所以上行 `0x01` 里的 `sample_time_us`，记的是「上位机那帧命令到达 MCU 的时刻」，不是「IMU 采样时刻」。**

代码里其实有注释承认了一半（底盘 IMU 那段），但云台那帧没写。

**这直接影响你理解 A 实验**：它不是"验证 µs 时基准不准"，而是"验证 µs 时基与 IMU 模块时钟的映射关系"。而**真正该回归的那对数据在 IMU 那条线上**：

| 变量 | 含义 | 在哪 |
|---|---|---|
| `imu_pantile.GetTimestamp()` | IMU 模块自己的 `system_time`（ms） | `xuc.cpp:163` 从 `p+8` 解出 |
| `uart2.rx_time_us` | 同一帧到达 MCU 的时刻（µs） | `usart.cpp` ISR 打的 |

**这两个都是现成的公开成员，watch 里直接能读，不需要改任何代码。**

## 步骤 1 · A 实验：IMU 时间戳回归（不用开电机）

**目的**：验证 MCU 的 µs 时基与 IMU 模块时钟的关系，确定延迟常数与残差。

**前置**：IMU 上电静置 30 秒（磁力计/滤波收敛）。

### 1.1 采数据

在调试器 watch 窗口加这四个：

```
uart2.rx_cnt              ← IMU 帧计数
imu_pantile.sample_ok     ← 已解码的姿态包计数
imu_pantile.GetTimestamp()   ← 模块 ms
uart2.rx_time_us          ← MCU µs
```

**采集循环**（重复 50 次以上，跨 2~3 分钟，这样时钟漂移才看得出来）：

1. **Halt**（暂停）
2. 读 `uart2.rx_cnt` 和 `imu_pantile.sample_ok`
3. **如果 `rx_cnt > sample_ok` ** → 说明有一帧到了但还没被 DecodeTask 解析 ⇒ **这次作废，重新 halt**
4. 记下 `GetTimestamp()` 和 `rx_time_us`
5. **Resume**，回到 1

> ⚠️ **第 3 步是必须的。** IMU 一帧约 7.1 ms（82 字节 @115200），而 DecodeTask 是 5 ms —— 有相当比例的时间点会停在"ISR 已打戳、任务还没解码"的窗口里，这时读到的两个值**不属于同一帧**，会算出 7 ms 量级的假残差。

### 1.2 算

用 Excel 或 Python：

```python
d_i = rx_time_us / 1000 - GetTimestamp()      # 两个都换算成 ms
```

然后把 `d_i` 按采集顺序画成折线：

| 现象            | 含义             | 判据                |
| ------------- | -------------- | ----------------- |
| **一条平直线**，无趋势 | 两个时钟同步，差一个常数延迟 | ✅ 通过              |
| 缓慢上升/下降       | 时钟漂移（晶振不同）     | 看总漂移量 < 2 ms 才算通过 |
| 上下抖动          | 打戳位置不一致        | 🔴 残差 > 2 ms，不通过  |

**残差 RMS** = 去掉线性趋势后的 `d_i` 标准差。**要求 ≤ 2 ms**（协议误差预算）。

### 1.3 参考值

`d_i` 应该稳定在某个正值上，大小 ≈ **一帧的传输时间**。因为 IDLE 中断在**最后一片字节落地**时才触发，而模块的 `system_time` 大概在帧生成早期打的 —— 差值约 7 ms。

**这个常数偏移本身无害**（会被 `PushRef` 和 `age_us` 一起消掉），**要盯的是它的抖动**。

## 步骤 2 · B 实验：轴与参考系（不用开电机）

### 2.1 判断 6 轴还是 9 轴

**代码里没有解磁力计**（`p+36~47` 未解析，`imu.h` 里也没有 mag 成员）。所以用**不通电的办法**：

> **断电重启 IMU，保持位置和朝向完全不变，等 2~3 分钟。**
>
> | 观察 | 结论 |
> |---|---|
> | yaw 收敛到某个值并稳住，反复重启**都指向同一方位** | ✅ 9 轴（磁力计在定航向） |
> | yaw 缓慢乱飘，每次重启都不一样 | 🔴 6 轴（纯陀螺积分，会漂） |
>
> 6 轴的话 yaw 闭环必须靠上位机持续修正，长期会积累误差。

### 2.2 单轴验证轴映射

**这是 B 实验的核心**，目的是抓"轴装反 / 读反"。

摆法：**云台所有电机都不上电**（可以拔 CAN 或用 `XUC_ALLOW_CONTROL=0` 的现状，云台本来就不动），只动 IMU：

| 步骤  | 手动动作           | watch 里看                   | 期望                    |
| --- | -------------- | -------------------------- | --------------------- |
| 1   | 水平静置           | `GetAngleRoll/Pitch/Yaw()` | roll≈0, pitch≈0       |
| 2   | 绕**竖直轴**转 90°  | `GetAngleYaw()`            | 变化 ≈ 90°              |
| 3   | 绕**枪管轴**转 90°  | `GetAnglePitch()`          | 变化 ≈ 90°              |
| 4   | 绕**水平横轴**转 90° | `GetAngleRoll()`           | 变化 ≈ 90°              |
| 5   | 任意单轴**匀速**转    | `GetGyroRoll/Pitch/Yaw()`  | **对应轴的 gyro 与角度变化同号** |

🔴 **第 5 步最关键。** gyro 符号错 ⇒ 角速度反馈反向 ⇒ 上位机做预测时方向反 ⇒ 系统性偏差。

⚠️ **这里有个历史坑**：`imu.cpp` 之前把 `roll` / `pitch` 和 gyro 的 X/Y 对调过，理由记的是"补偿 90° 安装"—— 后来确认那是**无依据的历史错位**，已按手册恢复。所以**这次实验的起点是干净的，但结论要重新拿**。

### 2.3 参考系一致性

IMU 装在**枪口**，M 6020 装在云台**根部**。两者的零点差 = 安装偏置。

这个偏置**不影响闭环**（因为 `ApplyAim` 里误差取的是 IMU 口径，不是编码器口径）—— 但**影响上位机**：它算出的绝对 yaw 和视觉里的地图对不上。

**做法**：云台静止，让上位机读 `0x01` 的 yaw 和视觉自己的 yaw，比对差值。**这个差值必须是个固定常数**（安装偏置），如果它一直变，说明参考系不稳。

### 3.1 验三个执行器的方向

**用遥控器，不用上位机**（摇杆可控、安全、能随时松手）：

| 档位         | 左拨码/右拨码 | 能测什么                      |
| ---------- | ------- | ------------------------- |
| `SPINNING` | 上 / 下   | 左摇杆 → 大 yaw(达妙)、pitch     |
| `FOLLOW`   | 中 / 上   | 左摇杆 → 小 yaw(M 6020)、pitch |
| `SEPARATE` | 中 / 下   | 左摇杆 → 小 yaw、pitch（底盘不跟随）  |

**逐个测，每个只动一个轴**：

| 测试        | 动作                        | 看什么                                             |
| --------- | ------------------------- | ----------------------------------------------- |
| 小 yaw 正方向 | `FOLLOW` 档，左摇杆**向右推满**    | 枪口应该**向右转**。**实际向左 ⇒ 符号反了**                     |
| pitch 抬   | `FOLLOW` 档，左摇杆**向上推满**    | 枪口应该**抬起**。**实际压下 ⇒ 符号反了**                      |
| 大 yaw     | `SPINNING` 档，右摇杆前后        | 达妙 yaw 应按 `yaw_lock_Kp` 软锁在原位，只随摇杆微调            |
| 摩擦轮       | `FIRE` 档（下/上）             | 两个轮子应**反向对转**（一推一拉），不是同向                        |
| 开火        | `FIRE` 档，右摇杆**前后**（ch[1]） | 拨盘应转动。**不转 ⇒ `supply_bullet` 那个死变量或 latch 没就绪** |

## 步骤 4 · 采集 yerr 分布（云台已能动）

现在闭环通了，可以采数据了。

**方法**：watch 里加

```
xuc.aim_yaw_target                  ← 绝对目标 (rad)

```

或者更省事：**直接看上位机日志**，让它把每帧的 `yerr` 画出来。

**三种工况都要采**：

| 工况 | 怎么造 | 看什么 |
|---|---|---|
| 静止靶 | 靶不动 | 误差应收敛到接近 0。**收敛不到 ⇒ 有静态偏置或死区太大** |
| 小幅移动 | 靶缓慢平移 | 误差应在 0.5~2° 波动 |
| 快速移动 | 靶快速/旋转 | 误差峰值多少、持续多久 |

**这一步的产出就是后面调参的依据。**

## 步骤 5 · 调参（顺序不能反）

### 5.1 先调 `LEAD_MAX`（速度旋钮）

⚠️ **但这一步的前提是那份"有界参考式"重构已经合进来了。** 你现在的工作区 `RC.cpp:159` 是裸累加 `y->setangle += KY * yerr * RAD2CNT;` —— 那套里没有 `LEAD_MAX`。

**如果重构还没合，这一步做不了**，先合结构。

合了之后：

| `LEAD_MAX` | 限速 | 什么时候用 |
|---|---|---|
| 22 | 29 °/s | 靶很慢 |
| **35** | **46 °/s** | **起点** |
| 60 | 79 °/s | 靶快速移动 |
| 100 | 132 °/s | 极限 |

**每次只改这一个值，改完烧录、跑一遍步骤 4 的三种工况。**

⚠️ **选错的代价不对称**：

- 选小 → 跟不上，误差一直下不来（**功能缺陷**）
- 选大 → 大误差区没事，小误差区震荡（**可以用 `KY` 压回来**）

**所以宁可从小往大试。**

### 5.2 再调 `KY`（只管收尾）

**保持 0.25 不动**，先跑一段时间。

只有当你确认 `LEAD_MAX` 已经调到"大误差区够快"之后，才看：

- 收敛太慢、最后一段拖泥带水 → `KY` 加到 0.3~0.4
- 小误差区抖动 → `KY` 减到 0.2

🔴 **注意有界式下 `KY` 的作用范围很窄**：`LEAD=35` 时限速门槛是 `35/(0.25×1303.8)` = **6.2°**。误差超过 6.2° 就已限速，`KY` 根本不起作用。**所以 `KY` 只影响最后 6° 以内的收敛过程。**

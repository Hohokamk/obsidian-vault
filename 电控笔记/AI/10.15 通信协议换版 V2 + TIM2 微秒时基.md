# 10.15 通信协议换版 V2 + TIM2 微秒时基

**简介**：今天干了两件独立的活。上午把上下位机通信层从「定长帧 + 增量累加」整体换成视觉的《协议 V2》精简版，**自瞄的控制语义因此发生根本变化** —— 从"把上位机的误差每次都加一遍"改成"收到命令时算一次绝对目标、之后每周期只做 IMU 闭环"。下午补了 TIM2 的 1 MHz 微秒自由计数器，为 `sample_time_us` 的误差界标定（A 实验）铺路。改动共 6 个文件，全工程逐 TU 编译零 error。

---

## 一、V2 协议落地

涉及 `xuc.h` / `xuc.cpp` / `RC.h` / `RC.cpp`。

### 1.1 帧格式：定长 → 变长 + type 分流

| | 改前 | 改后 |
|---|---|---|
| 帧头 | 单字节 `0xA5`（收）/ `0x5A`（发） | `A6 6A` + version + type + payload_len + sequence + boot_id（12 B） |
| 长度 | 固定 40 / 64 B | `14 + N`，最大负载 128 B |
| 有效性判据 | 单字节帧头 + 固定长度 | magic + version + type + len + CRC **四重自证** |

**这一步消除的是「改了帧长就 100% 丢帧、且查不出原因」这个坑** —— 旧版已经踩了两次（32 → 40 → 64，每次都要视觉同步改，都是断链级变更）。变长帧之后，加字段变成"注册一个新 type"，两端不用同时重排布局。

CRC 算法沿用现有 `CRC.h`，**零改动**（V2 用的 CRC-16/MCRF4XX 与现有实现逐位一致，已实测 `MCRF4XX("123456789") = 0x6F91`、线上字节 `91 6F`）。

### 1.2 实现的消息类型

| type | 消息 | 负载 | 频率 | 状态 |
|---|---|---:|---|---|
| `0x01` | GIMBAL_IMU | 32 | 上行 | 姿态 + gyro + 时间戳 + id + flags |
| `0x02` | CHASSIS_IMU | 20 | 上行 | 姿态（**无 gyro**）+ 时间戳 + id + flags |
| `0x10` | AIM_COMMAND | 24 | 下行 | 解析并重建目标，但**不执行** |
| `0x11` | NAV_COMMAND | 24 | 下行 | **已放行**（`XUC_ALLOW_NAV = 1`） |
| `0x81` | LINK_STATUS | 12 | 上行 10 Hz | state 位 + last_reject + aim_age |
| `0x03/0x20/0x21/0x30/0x31/0x80` | — | — | — | **不实现**，收到即静默跳过 |

砍掉的这些不是删了不能做，而是**元数据/低频类，对两人小队是净负担**。V2 §3.1 本身就规定「未知类型在长度合法且 CRC 正确时跳过」，所以不实现对上位机零改动。

带宽占用：上行约 2%、下行约 2%（921600 baud），非常空。

### 1.3 🔴 自瞄语义变了 —— 今天最重要的一处

|      | 改前                                       | 改后                                                                                                                                                   |
| ---- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 做法   | `mark_pitch += KP * xuc.pitch_diff`      | `HandleAim()` 收到新命令时算一次 `aim_yaw_target = WrapPi(ref.yaw + yaw_error)`（V2 §7.3）；`ApplyAim()` 每周期只做 `err = target − imu_pantile.GetAngle*()` 的 IMU 闭环 |
| 后果   | 同一份误差被 5 ms 周期**重复累加约 200 次/秒**，目标一路顶到限位 | 误差归零即自然停，**上位机重复发同一目标也不会跑飞**                                                                                                                         |
| 外环增益 | KP / KY = 0.5                            | 0.25（执行器自身已有位置环，外环只需小步逼近）                                                                                                                            |
| 误差源  | 上位机的 diff                                | **IMU**（这样安装偏置不会变成稳态误差）                                                                                                                              |

这就是 10-11 发现的 bug，**V2 §7.3 把修法写死了，方向完全一致**。本质区别是：`+=` 那份误差是过期的、会被重复使用的；现在每周期重算的误差是基于当前 IMU 的、误差为零就自然停。

### 1.4 结构拆分

- `RC::OnPC()` 瘦身为「模式守卫 + `ApplyNav()` + `ApplyAim()`」
- `RC.h` 删掉 `pc_timeout` / `last_rx_count` —— 改用上位机 `valid_for_ms` 租约
- 导航保留「限目标 → 限增量 → 下发」三级顺序（限幅对象是**目标**不是输出，所以 `prespeed` 天然不积压）
- 补 `imu.h` / `<algorithm>` 显式 include（之前靠间接引入）

### 1.5 首版是刻意的「只读联调版」

`XUC_ALLOW_CONTROL = 0` ⇒ `0x10` 会被完整解析、校验、重建目标，但**云台 / 摩擦轮 / 开火一个都不动**，`last_reject` 回 `NOT_ALLOWED`。整条「接受 / 拒绝」链路照常跑通，目标值可以在 watch 里观察。

`SAMPLE_TIME_VALID = 0`、`AXES_VERIFIED = 0`，`sample_time_us` 用 `DecodeTask` 时刻近似（对应 V2 的 `time_source = 2`）—— **不伪称采样时刻**，这是诚实且可诊断的做法。

做完 A 实验（时间戳）+ B 实验（单轴 / 参考系）后，**改一个宏就开许可**。

### 1.6 顺手修的真错误

本工程的 HAL **没有暴露 UID getter**（无 `HAL_GetUIDw0/1/2`，CMSIS 也没定义 `UID_BASE`）⇒ `boot_id` 改用 `HAL_GetTick() ^ 对象地址 ^ 常数` 再 xorshift32。同一次上电恒定、跨上电大概率不同、不持久化（V2 §3 只要求「不同」）。要严格持久化需用备份寄存器，前提是板上有 VBAT。

## 二、TIM2 1 MHz 微秒时钟源

涉及 `tim.h` / `tim.cpp`。

### 2.1 接口

```cpp
static constexpr uint32_t APB1_TIMER_HZ = 84000000u;

bool     TIM::UsInit(uint32_t tick_hz = 1000000u);
static uint32_t NowUs();                                   // 当前 µs
static uint32_t UsElapsed(uint32_t now, uint32_t last);    // 无符号差值，自动处理回绕
static int32_t  UsDiff(uint32_t now, uint32_t last);       // 带符号差值
```

顺带把 `TIM::Init()` 里硬编码的 `84000000` 提成 `APB1_TIMER_HZ` 常量（同一个时钟树，避免两处魔数）。

### 2.2 🔴 关键决策：绕开 HAL，寄存器直配

`HAL_TIM_Base_Init()` 会回调工程里已有的 `HAL_TIM_Base_MspInit()`，而那个函数最后一行是 `HAL_NVIC_EnableIRQ(TIM2_IRQn)`。**1 MHz 意味着每秒 100 万次溢出中断** —— 一开就把系统拖死。

所以 `UsInit()` 全程不碰 HAL、也不碰 NVIC：

```cpp
__HAL_RCC_TIM2_CLK_ENABLE();
TIM2->CR1 = 0;                 // 停计数 + 清所有控制位
TIM2->PSC = 83u;               // 84 MHz / 84 = 1 MHz
TIM2->ARR = 0xFFFFFFFFu;       // 32 位满量程
TIM2->CNT = 0;
TIM2->SR  = 0;
TIM2->CR1 = TIM_CR1_CEN;       // 只置 CEN；UEV/DIE 保持 0
```

附带好处：`phtim[1]` 保持 NULL ⇒ 原有的 `TIM2_IRQHandler`（`if (phtim[1])` 短路）永远不会被触发，中断向量表里那一格是死的。

### 2.3 数字（探针实算，非估值）

| 项 | 值 |
|---|---|
| PSC | **83**（84 = 2²×3×7，1 MHz 整除无余数） |
| 每计数 | **精确 1.000000 µs**，无累积量化误差 |
| 读数量化误差 | ≤ 1 µs（单条 `LDR`，天然原子） |
| ARR 满量程回绕 | **71.58 分钟** |

⚠️ **回绕 71.58 分钟必须记住**：用 `UsElapsed(now, last)` 的无符号减法，**不要比大小**。一局比赛不会撞上，但写代码时别顺手写 `if (now > last)`。

边界已测：`UsInit(0)` → false；`UsInit(1000)` → false（84e6 不能被 1000 整除，**非整除频率一律拒绝**，避免分频截断引入隐性误差）；`UsInit(2 MHz)` → PSC=41。

### 2.4 时钟树核对（`sysclk.h`）

```
HSE 25 MHz → PLL_M25 / N336 / P2  ⇒  SYSCLK 168 MHz
AHB = DIV1                          ⇒  HCLK   168 MHz
APB1 = DIV4                         ⇒  PCLK1   42 MHz
APB 分频 ≠ 1 时定时器时钟 ×2         ⇒  TIM2 输入 84 MHz
```

与 `delay.Init(168)`、`configCPU_CLOCK_HZ` 自洽。

### 2.5 调用方式（需改 `STM32F405.cpp`，待授权）

```cpp
timer.Init(BASE, TIM3, 1000).BaseInit();      // 现有：TIM3 @1kHz 给 CanTransimt 分频
if (!TIM::UsInit(1000000)) { /* 停机或降级 */ }   // 新增：TIM2 @1MHz
```

- **必须在 `SystemClockConfig()` 之后**（依赖 APB1 定时器时钟就绪，而它在 `main()` 里位于 `timer.Init` 之前）
- `UsInit()` 是 **static**，写 `TIM::UsInit(...)`

## 四、⚠️ 顺带发现：`imu.cpp` 的 CRC 是用户自己改的

`git diff` 显示用户把 `rxData[3] << 8 + rxData[2]` 改成了 `(rxData[3] << 8 ) + rxData[2]`。

**优先级确实修对了**（`<<` 现在先算），但两点建议：

1. **建议用 `|` 而不是 `+`** —— 在这个帧布局下数值等价（两字节不重叠），但官方表述是「低字节在前」，`|` 语义更准确，也避免日后有人改布局时静默出错
2. **同一行第 3 个参数 `rxData[5] << 8 + rxData[4]` 还没修** —— 那是 HI226 分支，虽然不用 HI226，但留着就是个 bug

原始 bug 的影响：0x91 帧时 `len` 算成 **0** ⇒ `Check()` 循环体一次都不跑 ⇒ 退化为「判断 `com` 是不是 0」⇒ **约 91% 的帧伪通过、9% 静默丢弃，实际根本没有 CRC 校验**。挡着的其实是帧头 `5A A5` + `rxData[6]==0x91` + 范围检查。

### A 实验：定 `sample_time_us` 的误差界

1. 静止连采 N 帧，记 `age = mcu_us − system_time_us`
2. 对 `system_time_us` vs `mcu_us` 做**线性回归**：斜率应 ≈ 1.0（两个晶振同源），截距 = 恒定延迟（可补偿）
3. **残差 RMS = 要的误差界**。理论下限 = 1 ms / √12 ≈ **0.289 ms**

| 结果 | 结论 |
|---|---|
| RMS ≪ 2 ms | `time_source = 3`、`SAMPLE_TIME_VALID = 1`，可进控制 |
| RMS ≫ 2 ms | 只能 `time_source = 2`、置 0 —— 此时要么跟视觉谈放宽 `valid_for_ms`，要么查模块是否支持 PPS 外部同步 |

⚠️ **`native_rate_hz` 的计数必须在 ISR 里做，不能在 `Decode()` 里做** —— 队列深度 1 + 覆盖写 + 5 ms 轮询，在 `Decode()` 里数出来的上限被压到 200 Hz，会把模块的真实输出率测错。

### B 实验：单轴 / 参考系标定

三个要点：

1. **轴识别不需要外部基准** —— 只看「哪个角在动、往哪边动」；只有量级绝对值才需要基准（手机水平仪 ±0.5° 够用）
2. **欧拉角是耦合的**，每步都要先把干扰轴归零（绕 Z 要水平、绕 Y 要 `roll≈0`、绕 X 要 `pitch≈0`）
3. 🔴 **「开摩擦轮 / 底盘电机，看 yaw 是否跳」这一条基本能一票定死 6 轴还是 9 轴** —— 3508 堵转几十安、电机磁场就在旁边，9 轴的「绝对航向」在车上会乱跳。结论通常��� `heading_source = 1`、`reference_frame = 1`（LOCAL_INIT），正对上 V2 §5.1 那句「六轴且无外部航向参考时，应声明 LOCAL_INIT」

⚠️ **轴互换只能保留在 MCU 一处**（现在在 `imu.cpp`）⇒ 上位机**不得再换一次**（V2 §5.1）。单轴实验万一发现互换是错的，**只改 MCU 侧**。

## 六、沉淀的经验

1. **凡「编辑器报错 vs 编译报错」不一致，先分清来源** —— 带具体数值（如 `SizeTag<36>`）的报错基本是 IntelliSense 前端算出来的，终端构建输出才是真值。当时 `TxPacket` 报 36 字节，真机 GCC 实编是 32。
2. **定长帧协议在两次改帧长后必然崩** —— 变长帧 + type 分流是唯一的根治办法，因为「帧长」不再是需要两端同时同步的全局常量。
3. **「重复累加过期误差」是自瞄类控制的经典 bug** —— 只要控制循环的周期与命令到达周期不同（这里是 5 ms vs 10 Hz），就必须有「新命令」判据。根治方向不是加判据，而是**把语义从增量改成绝对目标 + 每周期重算**。
4. **1 MHz 定时器绝不能开中断** —— TIM2 在本工程已被 `HAL_TIM_Base_MspInit` 绑上了 NVIC 使能，所以要绕开 HAL 直配寄存器。
5. **伪随机的时间戳要诚实标注** —— 首版用「MCU 收到报文的时刻」就明确写 `time_source = 2` + `SAMPLE_TIME_VALID = 0`，不伪称是采样时刻。协议给了「未知」的合法编码，就用它，别假装。
6. **HAL 依赖要实测确认** —— 「取 UID」这种看起来是标准操作的事，本工程的 HAL 版本根本没暴露。编译一次比推理十次可靠。

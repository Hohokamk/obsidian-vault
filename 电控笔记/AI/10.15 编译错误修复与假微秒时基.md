# 10.15 编译错误修复与假微秒时基

**简介**：这一轮修掉两个编译错误，但真正的收获是顺着第二个错误挖出一条隐藏得极深的设计缺陷 —— `xuc.h` 里那个叫 `NowUs()` 的函数**根本不是微秒时基**。它返回 `xTaskGetTickCount() * 1000`，而 `xTaskGetTickCount()` 本身就是 1 ms 粒度，乘 1000 只是把毫秒数值放大一千倍，分辨率纹丝不动。而这个假 µs 时基恰好被用在三处最需要精度的地方：样本新鲜度判定 `age_us`、`AimReady()`、`AimAgeMs()`。V2 的误差预算是 2 ms，一个 1 ms 量化的时间源等于凭空吃掉一半预算。已统一到 `TIM::NowUs()`（TIM2 @1 MHz，真 1 µs）。同时发现自己上一轮只编了「探针」、**从没编过真正的 `imu.cpp`**，因此漏掉一个 const 编译错误——本文也记下了正确的验证方法。

---

## 一、两个编译错误

### 1. `imu.h` 的 const（我上一轮改出来的）

```cpp
// imu.cpp:162  Decode0x91() 里
const uint8_t* p = rxData + 6;
//            ↓
timestamp = U4(p + 8);   // error: invalid conversion from 'const uint8_t*' to 'uint8_t*'
```

10 处同类错误。修法是**改 `U4`/`R4` 的签名，不改调用点**：

```cpp
static uint32_t U4(const uint8_t* p) { uint32_t u; memcpy(&u, p, 4); return u; }
static float    R4(const uint8_t* p) { float    r; memcpy(&r, p, 4); return r; }
```

**这两个函数本来就只 memcpy 出来读、不写，给 const 才是正确语义。** 原来非 const 是历史遗留。

⚠️ 关键：**不要为了"能编过"而把调用点的 `const` 去掉**。那等于把只读缓冲伪装成可写，编译器不再帮你拦错误 —— 比编译失败危险得多。

### 2. `xuc.h` 的 `NowUs()` 缺 `task.h`

```cpp
uint32_t NowUs() { return (uint32_t)xTaskGetTickCount() * 1000u; }
//                   ^^^^^^^^^^^^^^^^^^^^^^^^^ not declared in this scope
```

`xuc.h` 只 include 了 `FreeRTOS.h`，而 `xTaskGetTickCount` 声明在 `task.h` 里。加一行 `#include "task.h"` 就能编过 —— **但函数本身是错的，不只是缺 include。** 见第二节。

## 二、🔴 核心：`x * 1000` 不等于把 x 变成高精度

```cpp
uint32_t NowUs() { return (uint32_t)xTaskGetTickCount() * 1000u; }
```

```
xTaskGetTickCount()  →  毫秒，自增周期 1 ms
  × 1000             →  数值放大 1000 倍
                       分辨率仍然是 1 ms  ← 什么都没变
```

**时间源的真实分辨率 = 底层计数器的自增周期。** tick 是 1 ms 就永远是 1 ms，换任何乘法都改不了。要 µs 就必须有 1 MHz 的硬件计数器（本项目里就是 TIM2）。

这个函数名叫 `NowUs`，极具误导性 —— 谁都不会怀疑它偷偷只有 1 ms 精度。

### 它被用在了哪三处

| 位置            | 用途                                   |
| ------------- | ------------------------------------ |
| `HandleAim()` | `age_us = now_us - ref_time`，判样本是否过期 |
| `AimReady()`  | 控制许可：样本有没有过期                         |
| `AimAgeMs()`  | 上报样本年龄给上位机                           |

**三处全是 V2 里对时间最敏感的地方。** 而 V2 的误差预算就是 2 ms。

---

## 三、🔴 同一份协议里混了两套时基

修好编译后必须追问：这个值从哪来、和别的时间量能不能相减？

| 字段 | 来源 | 分辨率 |
|---|---|---|
| `sample_time_us`（上行） | `usart.cpp` ISR 的 `TIM::NowUs()` | **1 µs** ✓ |
| `age_us`（下行判新鲜度） | `xuc.h::NowUs()` = tick×1000 | **1 ms** ✗ |

`age_us = now_us - ref_time`，而 `ref_time` 是上位机**原样回传我们上行那个 µs 值**（`PushRef()` 存的就是发出去的 `t_us`）。

> 一个 1 ms 时基，减一个 1 µs 时基 —— 差出来的数**没有物理意义**。

⇒ 统一到 `TIM::NowUs()`。**同一协议内所有时间量必须同一时基，否则相减即无意义。**

## 四、🔴 `t_us` 的"降级兜底"会污染 A 实验

```cpp
// ❌ 原实现
const uint32_t t_us = (frame_time_us != 0u) ? frame_time_us : NowUs();
// ✅ 现在
const uint32_t t_us = frame_time_us;
```

两个来源：
- `frame_time_us` = ISR 打的**到达时刻**（真 µs）
- `NowUs()` = **任务调用时刻**（`Encode()` 每 20 ms 跑一次）

兜底让 `t_us` 有时是前者、有时是后者。上位机拿这批数据做**线性回归求恒定延迟**时，混进来的组帧时刻会变成一个**假的截距**，而 `Encode()` 的 20 ms 周期抖动正好落在残差里 —— 直接把残差 RMS 撑爆。

**这正是 A 实验要量的东西，被自己的兜底毁掉。**

⇒ **时基没就绪就该如实报 0。** TIM2 未使能时 `frame_time_us` 恒 0，上位机看到恒 0 就知道微秒时基没就绪 —— 这个机制本来就有注释说明，不需要兜底。

## 五、🔴 我的疏漏：探针编译通过 ≠ 固件编译通过

上一轮我说"ARM GCC 零警告通过"，其实**编的是探针（摘录版逻辑），不是真正的 `imu.cpp`**。探针里没有 `const uint8_t* p = rxData + 6`，所以 const 错误根本没机会暴露。

### 正确做法：用工程自带的响应文件

工程里有 VisualGDB 生成的编译参数：

```
VisualGDB/Debug/imu.gcc.rsp
VisualGDB/Debug/xuc.gcc.rsp
...（每个 TU 一个）
```

里面是全部真实参数 —— 8 条 CMSIS/HAL `-I` 路径、`-DSTM32F405xx`、`-mcpu=cortex-m4 -mfloat-abi=soft -mfpu=fpv4-sp-d16`：

```bash
# 编单个 TU
arm-none-eabi-g++.exe @VisualGDB/Debug/imu.gcc.rsp

# 全 TU 全编
for f in VisualGDB/Debug/*.gcc.rsp; do
    arm-none-eabi-g++.exe @$f 2>&1 | grep -c "error:"
done
```

⚠️ **rsp 里已带 `-MD -MP -MF` 和 `-o`，追加 `-o` 会报 `too many filenames`** —— 不要改它，原样跑。

**探针 vs 真 TU 的分工**：探针能验的是算法逻辑（CRC、边界、字段偏移），验不了的是 include 路径、类型匹配、真实宏定义、编译器严格程度。**两者都要做，但真 TU 编译是最终裁决。**

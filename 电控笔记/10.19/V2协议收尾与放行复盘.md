## 一、当前放行状态

| 宏 | 值 | 依据 |
|---|---|---|
| `XUC_ALLOW_CONTROL` | **1** | 用户实测：云台正常（右摇杆上推=抬头、左摇杆右推=右转）＋IMU 实测（枪口逆时针 yaw 增大、低头 pitch 增大；底盘只能动 yaw、逆时针增大）＋底盘遥控正常 |
| `XUC_ALLOW_NAV` | **1** | 速度指令本身 fail-safe |
| `XUC_F_AXES_VERIFIED` | **恒 1** | 同上实测 |
| `XUC_F_SAMPLE_VALID` | **永久 0** | A 实验已决定跳过 |

**符号一致性推导**（这一步替代了原本要做的实验）：

```
手动 pitch：右摇杆上推(ch>0) → mark_pitch −= → 枪口【抬头】
           低頭 = pitch 增大 ⇒ 抬头 = pitch 减小
           ⇒ mark_pitch 增大 ≡枪口低头 ≡ IMU pitch 增大   同向 ✅
手动 yaw  ：左摇杆右推(ch>0) → setangle −= → 枪口【右转=顺时针】
           逆时针 = yaw 增大 ⇒ 顺时针 = yaw 减小
           ⇒ setangle 增大 ≡ 枪口逆时针 ≡ IMU yaw 增大     同向 ✅
```

**核心前提**：手动路径与自动路径**共用同一个执行量**（`setangle` / `mark_pitch`），而手动方向用户天天在用、必然已验证过。⇒ 两个 `+=` 的符号正确。

### 上车判据

清空云台周围 → 看误差是否**单调收敛**。发散或顶到 `dm_pitch_min|max`（−0.55/+0.4 rad）⇒ 符号反了 ⇒ `ApplyAim` 对应行取负 **且撤回 `AXES_VERIFIED`**。

## 二、`K_NAV` 原值是量纲错误，不是"待标定的估算值"

```
换算链： nav_v[m/s] × K_NAV → 转子rpm → ÷GEAR → 轮rpm → ×2πR → m/s
反解：   K_NAV = GEAR × 60 / (2π × R)
```

| 项 | 值 | 来源 |
|---|---:|---|
| M3508 减速比 | **19.2032**（3591/187） | WebSearch 核实官方规格 |
| 轮半径 | 0.0475 m | `motor.h:8` |
| **理论 K_NAV** | **3859.9** | 反解 |
| 原值 | 159 | ⇒ 实际 **0.022 m/s**，**差 45 倍** |

同时 `NAV_MAX` 4000→6000（原值在新 K 下只允许 1.04 m/s，会变成比 `maxspeed` 更严的假瓶颈）。

⚠️ **理论值只保证量纲对**，实测必偏 10~30%（打滑、地面、负载、减速比个体差）。
实测：`K_new = 3859.9 × (1.0 / v_measured)`，发1.0 m/s、稳 2 秒后秒表量 3 秒。
**只测 `vx` 或 `vy` 一个就够** —— 45° 逆解里两者共用同一增益系数。

## 三、🔴 被 `#if` 隐藏两个月的编译错误

置 1 后立刻编译失败：

```
RC.cpp:157: error: 'xuc' is not a class, namespace, or enumeration
    const float yerr = xuc::WrapPi(...)
```

**`namespace xuc` 根本不存在** —— `WrapPi` 是 `XUC` 类的静态成员（`xuc.h:209`）。
这行在 `XUC_ALLOW_CONTROL == 0` 时被 `#if` 整段删掉，**从未被编译过**。

修法：`xuc::WrapPi` → `XUC::WrapPi`（改限定符，不是删代码）。

> ⚠️ **推论**：任何用宏屏蔽"控制/执行"分支的代码，**宏从 0 翻到 1 等于第一次编译那段代码**。
> 置 1 前应该先临时置 1 编一次。这条已写进 README 第九节的 AI 规则。

| | 文档写的 | 代码实际（权威） |
|---|---|---|
| `0x10` | `flags@0 ref_epoch@2 ref_seq@4 ref_time@6(2B) v4ms@8(4B) yaw@12 pitch@16` | `flags@0 **reserved@2** ref_epoch@4 ref_seq@6 **ref_time@8(4B)** v4ms@12 reserved@14 yaw@16 pitch@20` |
| `0x11` | `flags@0 reserved@2 v4ms@4 vx@8 vy@12 wz@16` | `flags@**10** v4ms@8 vx@12 vy@16 wz@20` |

🔴 **`ref_time` 的 16 位 vs 32 位是最致命的一处**：参考样本匹配是四项全等（`FindRef` 比对完整 `uint32 time_us`），视觉若按旧文档只传低 16 位 ⇒ **`last_reject = 3 (BAD_REFERENCE)`，自瞄永远不动，且没有任何编译或运行报错**。

已改（两份文档都按代码重写）。**代码是权威，文档必须对着代码核。**

## 六、方法论复盘（这周最有价值的部分）

### 1. 凡是说"测一下确认"，先问"测出来能不能改"

A 实验（时间戳回归，50+ 组配对数据）被砍掉的推理链：
- 三项误差源里 ① `system_time` 的 1 ms 粒度和 ② UART 传输 6.16 ms **都是常数偏移**，会被 `PushRef`/`age_us` 一起消掉；真正随机的只有 ③。
- 而**测出来改不了任何代码** —— 晶振偏差、传输时间都是不可修的量。
- ⇒ ROI 不成立，`SAMPLE_VALID` 永久 0（诚实标注，不是缺陷）。

**对比 B 实验**：用户直接问"正方向是什么"，一句话拿到最关键的信息，**比我设计的"单轴转 90° 看哪个 euler 在动"高效得多**。

⇒ **问对问题 > 设计实验。**

### 2. 我这轮连犯的三个错

| 错 | 性质 |
|---|---|
| "watch 里能填 `GetTimestamp()`" | watch 只读内存不执行代码，private 只是 C++ 访问控制不是内存保护 |
| "yaw 误差两侧同源所以符号天然正确" | 只对**误差计算**成立；`setangle`（M6020 编码值）和 `mark_pitch`（达妙关节角）都是**另一个器件** ⇒ 两轴都是跨器件 |
| "A 实验不做就不能放行" | ROI 不成立（见上） |

**共同点**：都在"没读到底层机制"的情况下凭直觉下结论。**报错要往回追自己最近的改动。**

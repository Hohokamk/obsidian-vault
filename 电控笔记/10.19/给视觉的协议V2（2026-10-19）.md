# 🔴 视觉侧必读 · 上位机 ↔ 电控通信协议 V2（2026-10-19）

**给视觉/上位机同学的行动清单。** 本文只讲**你要改什么**，完整字段表在电控仓库的 `docs_通信协议.md`。

> 物理层：**UART4 @ 921600 8N1**｜全小端｜无隐式 padding
> 电控端 STM32F405，两个开关**已全部放行**（`ALLOW_CONTROL = 1`、`ALLOW_NAV = 1`）

---

## 一、你现在必须改的六件事

| # | 改什么 | 不改的后果 |
|---|---|---|
| **1** | 帧格式从定长帧换成 **变长帧 + type 分流** | 完全收不到，反馈 `crc_err` 持续涨 |
| **2** | 角度单位从**度改成弧度** | 全系统差 **57.3 倍** |
| **3** | `ref_time` 必须回传**完整 32 位** | `last_reject = 3 (BAD_REFERENCE)`，自瞄永远不动 |
| **4** | `vx/vy` 必须是**车体系**，不是像素坐标 | 底盘走歪，且**不会报错** |
| **5** | `0x10` 发的是**误差**，不是绝对角度 | 云台朝反方向收敛，一路顶限位 |
| **6** | 🔴 **摩擦轮/开火必须按 §4.2 的时序发** | **摩擦轮在转但打不出弹，无任何报错** |

**旧协议不能与 V2 自动混猜** —— `magic` 从旧格式换成 `A6 6A`，切换要两边同时做。

> ⚠️ **第 6 条是最容易踩的**，因为它的失败模式是"看起来在工作但没输出"。建议联调时先单独验证开火链路。

## 二、帧结构

```text
 0      2    magic         A6 6A
 2      1    version       02
 3      1    type          消息类型
 4      2    payload_len   负载字节数
 6      2    seq           序号，【每帧递增，uint16 回绕】
 8      4    boot_id       会话标识，见 §5
12      N    payload
12+N    2    CRC16         低字节在前
```

**总长 = 14 + N**

**CRC-16/MCRF4XX**：init `0xFFFF`、反射多项式 `0x8408`、低字节先发、**覆盖 `[0 .. 12+N-1]`**（即帧头+ 全部 payload，CRC 字段自己不参与）。
自检：`MCRF4XX("123456789") = 0x6F91`，线上字节是 `91 6F`。

## 三、消息表

| type | 名称 | 方向 | 负载 | 频率 | 状态 |
|---|---|---|---:|---|---|
| `0x01` | GIMBAL_IMU | 上行 | 32 | 50 Hz | ✅ |
| `0x02` | CHASSIS_IMU | 上行 | 20 | 50 Hz | ✅ |
| `0x81` | LINK_STATUS | 上行 | 12 | 50 Hz | ✅ |
| `0x10` | AIM_COMMAND | 下行 | 24 | — | ✅ **已放行** |
| `0x11` | NAV_COMMAND | 下行 | 24 | — | ✅ **已放行** |

上行三帧由电控拼成**一段连续缓冲一次发出**（共 106 B，线上 1.15 ms）。**你必须能处理粘包/连续三帧**，不要假设"一次 recv 收到一帧"。

## 四、下行字段（你要构造的）

### 4.1 `0x10` AIM_COMMAND（24 B）

🔴 **偏移以本文为准。** 电控旧文档这里整体错位，且把 `flags` 写成了 @0 —— 代码里 `flags` 其实在 **@14**。以 `xuc.cpp::HandleAim()` 的实参为唯一权威：

```text
 0      4    reserved      填 0
 4      2    ref_epoch     填 1（必须 == 电控 epoch）
 6      2    ref_seq       回传你收到的 0x01 帧的 seq
 8      4    ref_time      回传你收到的 0x01 的 sample_time_us 【32 位完整】
12      2    valid_for_ms  1~150，推荐 100
14      1    flags         bit0 控制许可 / bit1 目标有效 / bit2 摩擦轮 / bit3 开火
15      1    reserved      填 0
16      4    yaw_error     rad
20      4    pitch_error   rad
```

⚠️ **`flags` 在偏移 14，不在 0。** 载荷前 14 字节全是 `reserved` 和参考三元组。

**三个必须理解的点：**
**① 发的是误差，不是绝对角度。** 电控收到后自己重建绝对目标：
```cpp
aim_yaw_target = WrapPi(参考样本.yaw + yaw_error);
```
⇒ 误差算错，方向就错。**重复发同一条命令无害**（误差归零即自然停），但**发绝对角度当误差用会让云台飞出去**。

**② `ref_time` 是 32 位。** 电控的参考样本匹配是四项全等：
```
boot_id + epoch + seq + time_us(完整32位)
```
只传低 16 位一定匹配不上。

**③ `ref_epoch/ref_seq/ref_time` 必须是同一份上行数据里的三元组**，不要混用不同帧的字段。缓存 48 条，按 50 Hz 算覆盖 **960 ms**。

### 4.2 🔴 摩擦轮与开火时序（必须遵守）

**这是最容易踩错的地方 —— 时序错了会"摩擦轮在转但打不出弹"，而且没有任何报错。**

**你要这样发：**

```
1. 先发  FRICTION_EN=1, FIRE_REQ=0     ← 只开摩擦轮
2. 等 800 ms                            ← 见下方"要等多久"
3. 发  FIRE_REQ 从 0 改成 1             ← 上升沿 = 单发一次
4. 下一次单发前，必须先发一帧 FIRE_REQ=0，再发 FIRE_REQ=1
5. FIRE_REQ 连续保持 1 超过 300 ms → 进入连发，间隔 125 ms
```

**要点解释：**

| 规则 | 原因 |
|---|---|
| 必须先发一帧 `FIRE_REQ=0` | 拨弹轮只在 `0→1` **上升沿**动作。不回 0，下一次 `1` 没有上升沿 ⇒ 不发弹 |
| 要等 800 ms | 摩擦轮目标 5000 rpm，到速阈值 4000 rpm（80%），实测加速需 300~500 ms |
| 上升沿不会"缓存" | **转速没到时发的上升沿会被直接丢弃**，转速到了也不会补发 ⇒ 这发子弹就没了 |

**电控侧只在全部满足时才允许拨弹：**

- `CONTROL_EN=1`
- `AIM_VALID=1`
- `FRICTION_EN=1`
- **两个**摩擦轮**各自**达到 4000 rpm（不是看平均，是两个都要到）
- 两个摩擦轮转速差 `≤ 300 rpm`（电控内部判定，**你看不到这个值**）

⚠️ **两个摩擦轮转速差你无法观测** —— 如果超了 300 rpm，你的表现是"摩擦轮明明在转但打不出弹"，且**看不到任何提示**。遇到这种情况让电控侧看 `ctrl.shooter.friction_speed_diff`。

### 4.3 `0x11` NAV_COMMAND（24 B）

🔴 **偏移同样以本文为准**（`xuc.cpp::HandleNav()`，注意 `flags` 在 **@10**）：

```text
 0      8    reserved      填 0
 8      2    valid_for_ms  1~150，推荐 100
10      1    flags         bit0 = NAV_ENABLE，其余位必须 0
11      1    reserved      填 0
12      4    vx    m/s，车体系正前方
16      4    vy    m/s，车体系正左方
20      4    wz    rad/s（★首版未使用，恒 0）
```

**`NAV_ENABLE = 0` 时三个速度必须全零**，否则整帧被拒。这是**停止指令**的正规发法。

## 五、坐标系：必须是车体系

**`vx` / `vy` 一律是车体系** —— 以底盘朝向为基准：

| 轴 | 正方向 |
|---|---|
| `+X`（`vx`） | 底盘**正前方** |
| `+Y`（`vy`） | 底盘**正左方** |
| `+Z` | 满足右手系 ⇒ **向上** |

**三条禁止项：**

1. ❌ **不要发图像坐标系的 `u`/`v` 像素。** 相机看到的是世界系；车体一转向，同一个 `u` 对应的车体方向就变了。
2. ❌ **不要发四个轮子的转速。** 45° 麦轮逆解由电控做：
   ```
   w1 = -vx - vy + ωz     (左前)
   w2 = +vx - vy + ωz     (右前)
   w3 = +vx + vy + ωz     (右后)
   w4 = -vx + vy + ωz     (左后)
   ```
3. ❌ **不要自己做底盘转向。** 比赛是「固定轨迹走到固定点」，`wz` 首版不被消费，**发了也不起作用**。

**为什么这么定**：电控的 `ApplyNav()` 做的是一对一映射
```cpp
speedx = nav_vx × K_NAV;   speedy = nav_vy × K_NAV;
```
然后直接进上面的逆解 —— 它假设输入就是车体系。发错坐标系的话，**车照样动，只是走歪，不会有任何报错**。

## 六、上行字段（你收到的）

### `0x01` GIMBAL_IMU（32 B）—— 枪口 IMU

```text
 0      1    imu_id = 1
 1      1    flags   bit0 姿态有效 / bit1 gyro 有效 / bit2 样本有效 / bit3 轴已标定
 2      2    epoch   恒 1
 4      4    sample_time_us   见 §7
 8      4    roll    rad
12      4    pitch   rad
16      4    yaw     rad
20      4    gyro roll    rad/s
24      4    gyro pitch   rad/s
28      4    gyro yaw     rad/s
```

### `0x02` CHASSIS_IMU（20 B）—— 身体 IMU

```text
 0      1    imu_id = 2
 1      1    flags   bit1 恒 0（无 gyro）
 2      2    epoch
 4      4    sample_time_us   与 0x01 同源
 8      4    roll    rad
12      4    pitch   rad
16      4    yaw     rad
```

### `0x81` LINK_STATUS（12 B）—— 你的调试主入口

```text
 0      4    host_session   恒 0（无会话机制）
 4      2    aim_last_seq   最近接受的 0x10 序号
 6      1    state   位标志，见下
 7      1    last_reject  ★★ 排查下行被拒的第一入口
 8      2    aim_age_ms    参考样本年龄，0xFFFF = 无有效样本
10      2    reserved
```

`state` 位：`0x02` aim_fresh｜`0x04` gimbal_allow｜`0x08` friction_allow｜`0x10` fire_allow｜`0x20` nav_fresh｜`0x40` nav_allow

**当前状态：`gimbal_allow`/`nav_allow` 都应为 1**（两个开关已放行）。

### `last_reject` 码表 —— 你的错误一定在这里

| 值 | 名称 | 你该怎么查 |
|---:|---|---|
| 0 | OK | 通过 |
| 1 | BAD_SESSION | `boot_id` 不匹配 → 见 §7 |
| 3 | **BAD_REFERENCE** | `ref_time` 只传了 16 位，或三元组混了不同帧 |
| 4 | STALE | 参考样本太旧 → 发得太慢，或 `valid_for_ms` 太小 |
| 5 | INVALID_VALUE | `reserved` 字段没填 0 / flags 有未知位 / `valid_for_ms` 越界 / 角度是 NaN |
| 6 | NOT_ALLOWED | 电控不在 AUTO 模式（**看遥控器档位**） |
| 8 | DUPLICATE_OR_OLD | `seq` 没递增，或重复发了同一帧 |
| 7/ 9 | UNSUPPORTED / LOCAL_FAULT | type 不支持 / 电控本地故障 |

## 七、`boot_id`：每次会话必读一次

`boot_id` 是电控本次上电生成的 32 位值，**跨上电大概率不同、不持久化**。

**你要做的**：
1. 收到任意上行帧 → 取 `boot_id`
2. 存起来
3. 之后每条下行命令的帧头里都填这个值

**不填的后果**：`last_reject = 1 (BAD_SESSION)`，所有命令被拒。电控重启后 `boot_id` 会变，**你需要重新读取**。

---

## 八、`sample_time_us`：不能用来做外推

🔴 **这是一个必须知道的限制。**

`0x01/0x02` 里的 `sample_time_us` 是**电控收到 IMU 报文并打包的时刻**，不是 IMU 的真实采样时刻。二者的映射关系**没有标定**。

对应地，`flags` 的 **bit2（`SAMPLE_VALID`）恒为 0**。

**所以：姿态外推请你自己用 `gyro` 积分，不要相信上报的时间戳。**

```text
预测角度 = 收到的姿态 + 你自己积分的 gyro × 你的外推时长
```

> 电控侧已决定跳过时间戳标定实验 —— 误差源（晶振偏差、UART 传输时间）都是不可修且会被消掉的常数偏移，投入产出不成立。所以这个 bit 是**永久 0**，不是"还没做"。

**`flags` bit3（`AXES_VERIFIED`）当前恒为 1** —— IMU 轴向已由实测确认（枪口 IMU 逆时针 yaw 增大、低头 pitch 增大）。

## 十、上电自检清单

按顺序做，每步都能独立判断成败：

```
□ 1. 能收到 0x81，且 last_reject == 0
      （收到任何帧 = magic/CRC/version 都对）
□ 2. 从上行帧里取出 boot_id 并记住
□ 3. 发 0x10，flags 只开 bit0（控制许可），yaw/pitch 误差填 0，
      ref 三元组用刚收到的那帧 ⇒ last_reject 应仍为 0
□ 4. 0x81 的 state 里 gimbal_allow 应为 1
□ 5. 发 0x11，vx=0.3, vy=0, NAV_ENABLE=1 ⇒ last_reject 应为 0，
      且机器人应以约 0.3 m/s 前进
□ 6. 停止：NAV_ENABLE=0 且三速度全零 ⇒ 底盘立即停
□ 7. 故意填错 ref_time 的高 16 位 ⇒ 应复现 last_reject == 3
□ 8. 🔴 开火链路：先只发 FRICTION_EN=1 等 800 ms，确认摩擦轮转起来，
      再发 FIRE_REQ 上升沿 ⇒ 应能听到/看到发射
□ 9. 🔴 反向验证：摩擦轮刚启动 100 ms 就发 FIRE_REQ 上升沿 ⇒ 应打不出弹
      （这条验证了"到速判据真的在起作用"，比第 8 条更重要）
```

**任何一步的 `last_reject` 不为 0，直接按码表定位，不要猜。**

## 十一、已知限制（电控侧主动声明）

| 项 | 状态 | 你该怎么应对 |
|---|---|---|
| `sample_time_us` 未标定 | 永久 | 自己用 gyro 积分外推 |
| `boot_id` 跨上电变化 | 设计如此 | 每次重连重读 |
| `nav_wz` 未消费 | 首版 | 转向由电控策略层决定 |
| 🔴 摩擦轮到速状态不上报 | 设计如此 | 自己留足启动等待（§4.2），**无法直接观测** |
| `K_NAV` 未标定 | 🔴 **重要** | 发 1.0 m/s 可能不等于走 1.0 m/s。**第一次联调请实测标定**，方法见下 |

### `K_NAV` 标定方法（重要）

当前 `K_NAV` 是**理论值** `3859.9`（换算链：`m/s × K → 转子rpm → ÷19.2 → 轮rpm → ×2πR`），实测会有 10~30% 偏差。

**测法**：
1. 让电控发 `vx = 1.0`（`vy=0`）
2. **等速度稳定 2 秒**（起步有打滑，立刻开始量会偏低）
3. 秒表量 **3 秒**的实际直线位移
4. `K_new = 3859.9 × (1.0 / v_measured)`

⚠️ **只测 `vx` 或 `vy` 其中一个就够** —— 45° 逆解里两者共用同一个增益系数。

## 附：与旧协议的主要差异速查

| 项 | 旧协议 | V2 |
|---|---|---|
| 帧长 | 定长 | 变长 + type |
| 帧头 | 无 magic | `A6 6A` + version |
| CRC | 旧算法 | **MCRF4XX**（覆盖帧头+payload） |
| 角度单位 | 度 | **rad** |
| 自瞄语义 | 绝对角度 | **误差** |
| 参考样本 | 无 | 四元组强校验 |
| 停止指令 | 特殊帧 | `flags=0` / `NAV_ENABLE=0` |

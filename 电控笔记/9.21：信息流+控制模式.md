**完整准确版**

```
【输入】
CAN 中断 → can1.data / can2.data / jointidata   （电机反馈）
UART 中断 → 队列 → RC::Decode() / IMU::Decode()  （遥控和姿态）

【目标生成：ControlTask，5ms】
RC / IMU
  ├→ 底盘：speedx/speedy/speedz → Mecanum_Resolve → 四个 setspeed
  ├→ 云台：mark_yaw/mark_pitch → yaw/pitch setangle
  └→ 发射：openRub/auto_shoot → 摩擦轮 setspeed、拨弹 setspeed、推杆 GPIO

【闭环计算：MotorUpdateTask，2ms】
canX.data 反馈
  → SPD：setcurrent = PID(setspeed - curspeed)
  → POS：setangle → 位置环 → setspeed → 速度环 → setcurrent
  → current = 限幅(setcurrent)
  → 写进 canX.temp_data / can2.jointpdata

【发送：CanTransimtTask，1ms】
temp_data → CAN::Transmit(0x200 / 0x1FF) → 电调
jointpdata → CAN::Transmit(0x100 + ID) → 达妙
```
RC 和 IMU 在 ControlTask 里生成目标值，目标值写进 Motor 的 setspeed/setangle；MotorUpdateTask 拿 CAN 反馈和这个目标跑 PID，算出 current 并打包进 temp_data；CanTransimtTask 再把它发出去。

## 五、这些模式之间的组合关系
它们不是互斥的，实际是分层的：

```
安全层   : RESET / 失联 / 超功率 / 热量超限
发射层   : 单发 / 连发 / 射频 / 卡弹处理
云台层   : 世界角保持 / 手动 / 自瞄
底盘层   : 车体 / 云台 / 世界 / 小陀螺 / 跟随 / 锁定
```

优先级通常是：

```
RESET / 失联
  > 功率和热量保护
  > 发射安全锁
  > 自瞄覆盖云台手动
  > 底盘运动模式
```

比如“小陀螺 + 自瞄 + 连发 + 热量限制”就是一个完整的整车组合，但它是四个层的叠加，不是一个单独的模式。

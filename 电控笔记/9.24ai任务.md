## 主线就一条：`Motor::Ontimer()` 是双职责函数

这是理解整个电机链的钥匙，也是我建议你第一个动的地方。看签名：

```cpp
void Motor::Ontimer(uint8_t idata[][8], uint8_t* odata);  // idata: 收 odata: 发
```

它一个函数干两件事—— `idata` 解析 CAN 反馈（角度/转速/电流/温度），`odata` 回填要发出去的电流值。而 PID 输出**就该写在它内部**（`SPD` / `POS` / `ACE` 三个分支，现在全是空的）。

所以：**"给底盘写速度环"这件事，落点不在 control.cpp，在 motor.cpp。** control.cpp 的 `Update()` 只负责算*目标值*（`setspeed`），真正的*控制律*在 `Ontimer()` 里。这个分工定下来，后面所有电机代码的位置都不用纠结了。

配套的三个事实，不用改、但必须记住：
- **装配**：`can2_motor` = 底盘 M 3508 ×4 (ID 1~4)；`can1_motor` = 摩擦轮 M 3508 ×2 (ID 2,3) + 拨盘 M 2006 (ID 7) + 云台 M 6020 (ID 5)。每个都标了 `function_type`，`ctrl.Init()` 就是按这个分派的。
- **发送分组**：`can.temp_data[0..7]` → 0 x 200 帧(ID 1~4)，`[8..15]` → 0 x 1 ff 帧(ID 5~8)。这个和上面的 ID 分配是对得上的，属于已经写对的部分。
- **CAN 波特率是 1 Mbps，算对了**（42 MHz / 6 / 7 TQ）。只是采样点落在 42.9%，偏低（常规取 75% 附近），暂时不影响功能。

## 但在写控制之前——有 4 处会直接把你拦住

按严重程度排：

1. ** `CONTROL::Init()` 必然崩溃。** 三处问题叠在一起：`supply_motor[num4]->spinning`（num 4=0，指针是空）、`supply` 分支漏了 `break`、末尾 `pantile_motor[1]->setangle` 解引用空指针。而且它在 `main()` 里被调用**两次**，第一次传的是 can 2 那批（全是 chassis，一个 pantile 都没有）——第 30 行就直接撞了。这个必须先修，否则你写什么都跑不起来。

2. **达妙电机接收链路是断的。** `HTmotor.h` 声明 `extern DMMOTOR DMmotor[1]`，`STM32F405.cpp` 定义的是 `[2]` ——声明和定义不一致。更要命的是 `State_Decode()` 里 `uint8_t id = ID - 0x01`，而 `DMmotor[0].ID = 0x09` → 索引到 `jointidata[8]`，可数组只有 `[6][8]`，**越界**。同时 `jointpdata` 的发送 ID 用的是 `id + 0x100`（0 x 101），跟 0 x 09 也对不上。

3. ** ·DMmotor[1].Kp / .Kd ` 在 ` MotorUpdateTask ` 里被引用**，而 PID 参数却写在 ` DMmotor[1] `（Yaw，SPEED 模式）上——用 Yaw 的参数去控 Pitch。这是 README §8 提到过但没修的那个越界，实际是"语义也错了"，不只是越界。

4. ** `MotorUpdateTask` 和 `CanTransimtTask` 的 `xlastWakeTime` 声在 `while` 循环体内**，导致 `vTaskDelayUntil()` 退化成了 `vTaskDelay()`。你把 CanTx 设成 1 ms 是想让"三态轮转"正好 3 ms 一轮，但现在每轮循环都重新取基准，漂移会一直累积。两行代码，挪出去就好。

另外几处不影响跑、但影响正确性的：`control.h` 里 `mode` 没初始化（遥控器一断信号就是不定值）；`RC::Decode()` 的 `if (sizeof(m_frame) < 18)` 恒为真（数组声明就是 100 字节），长度校验等于没有；`MotorUpdateTask` 里 `State_Decode(can2, ...)` 是**按值**把整个 CAN 对象拷了一份，应改成 `CAN&`。

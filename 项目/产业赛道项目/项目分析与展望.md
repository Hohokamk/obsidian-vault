## 一、项目概述

### 1.1 核心痛点

当前中小制造企业面临的数字化转型困境：

- **成本门槛高**：传统 MES 系统 10-100 万元，实施周期 3-12 个月
- **功能过重**：大型系统功能繁杂，小微企业用不上也用不起
- **数据孤岛**：纸质台账、人工登记，无法实时掌握产线状态
- **响应滞后**：设备故障、产量异常无法及时发现和处理

### 1.2 解决方案

```
┌─────────────────────────────────────────┐
│           前端展示层 (Vue 3)             │
│   ECharts 可视化 · 响应式布局 · 多端适配  │
└──────────────────┬──────────────────────┘
                   │ HTTP/WebSocket
┌──────────────────┴──────────────────────┐
│          后端服务层 (FastAPI)             │
│   数据清洗 · 业务逻辑 · 告警引擎 · API   │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────┴──────────────────────┐
│         数据传输层 (MQTT/EMQX)           │
│        轻量级消息队列 · 发布/订阅         │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────┴──────────────────────┐
│          数据采集层 (ESP32)               │
│     传感器 · Modbus协议 · 即插即用        │
└─────────────────────────────────────────┘
```

### 1.3 核心功能

| 功能模块 | 说明 | 价值 |
|---------|------|------|
| 产量统计 | 实时产量监控、班次统计、趋势分析 | 告别纸质台账，数据实时可见 |
| 设备状态 | 在线/离线/告警/维护状态监控 | 设备状态一目了然 |
| 异常告警 | 温度、振动、产量异常自动推送 | 减少停机损失 30-50% |
| 历史回溯 | 历史数据查询、报表导出 | 支持管理决策和问题追溯 |
| OEE 分析 | 设备综合效率计算 | 量化生产效率 |

## 二、整体框架解读

### 2.1 技术架构

#### 前端技术栈

```
Vue 3 + Composition API
├── Vite          # 构建工具，极速热更新
├── Element Plus  # UI 组件库
├── ECharts 5     # 数据可视化图表
├── Pinia         # 状态管理
├── Vue Router    # 路由管理
└── Axios         # HTTP 请求
```

**关键页面：**
- `Dashboard.vue` - 主看板（统计卡片 + 折线图 + 饼图 + 告警表）
- `DeviceList.vue` - 设备管理列表
- `AlarmList.vue` - 告警中心

#### 后端技术栈

```
Python FastAPI
├── SQLAlchemy    # ORM 框架
├── Pydantic      # 数据验证
├── Paho MQTT     # MQTT 客户端
├── Uvicorn       # ASGI 服务器
└── SQLite/PG     # 数据库
```

**核心模块：**
- `app/api/` - RESTful API 路由
- `app/models/` - 数据模型定义
- `app/mqtt/` - MQTT 消息处理
- `app/core/` - 配置和数据库

#### 数据流设计

```
设备传感器
    | (模拟量/数字量)
ESP32 采集模块
    | (MQTT publish)
factory/{id}/device/{code}/data
    |
EMQX Broker
    | (MQTT subscribe)
FastAPI MQTT Client
    | (数据清洗 + 告警检查)
数据库存储
    | (API 查询)
前端 ECharts 渲染
```

### 2.3 数据库设计

```sql
-- 设备信息表
devices
├── id, device_code, device_name
├── device_type, factory_id, production_line

├── id, device_code, factory_id

production_summary
├── id, factory_id, production_line
├── summary_date, shift
├── total_production, qualified_count, defect_count
└── running_time, alarm_count, oee
```

## 五、风险与应对

### 5.1 主要风险

> [!danger] 市场风险
> - 客户付费意愿低
> - 大厂下沉竞争
> - 获客成本高

> [!danger] 技术风险
> - 设备协议碎片化
> - 现场环境复杂
> - 数据安全合规

> [!danger] 运营风险
> - 客户成功支持
> - 硬件供应链管理
> - 团队能力瓶颈

### 5.2 应对策略

1. **差异化定位**：不做全功能 MES，只做最核心的数据监控
2. **轻资产运营**：硬件外包生产，专注软件和平台
3. **生态合作**：与设备厂商、集成商建立分成机制
4. **数据驱动**：基于客户数据持续优化产品

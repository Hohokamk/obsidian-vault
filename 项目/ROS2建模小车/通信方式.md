DMA:系统级的数据准备方式/数据搬运机制

你现在学 STM 32 下位机通信，这几个概念确实很容易混在一起。尤其是 UART、DMA、I²C、SPI、CAN 并不是五种完全同类的东西：前面四个常用于数据传输机制或接口，其中 DMA 严格来说不是通信协议，而是一种数据搬运机制。

我先给你一个核心认识：

- UART、I²C、SPI、CAN：解决设备之间如何传输数据的问题，但各自的规则不同。
    
- DMA：解决数据如何在外设和内存之间高效搬运的问题，可以配合 UART、SPI、I²C 等使用。
    

## 一、先看整体区别

|名称|核心特点|常见用途|
|---|---|---|
|UART|简单的串行通信，常用 TX/RX 两根信号线|STM 32 与电脑、蓝牙模块、GPS、IMU 通信|
|DMA|硬件自动搬运数据，减少 CPU 参与|串口连续接收、SPI 高速数据传输|
|I²C|两根信号线，可挂接多个设备，通过地址区分|传感器、EEPROM、RTC|
|SPI|时钟同步，通常速度较高，主从关系明确|屏幕、Flash、高速 ADC|
|CAN|面向多节点的总线，具有仲裁和错误处理机制|汽车电子、机器人电机控制器、工业设备|

## 二、它们分别是怎么工作的？

### 1. UART：简单直接的串口通信

STM 32

TX → RX

RX ← TX

另一个设备

UART 通常不需要额外时钟线，通信双方提前约定波特率、数据位、校验位等参数，就可以收发数据。

例如 STM 32 向 JY 62 IMU 发送请求，或者接收 IMU 发来的姿态数据。

优点： 简单、易调试、硬件成本低。

缺点： 通常是点对点连接；如果要连接多个设备，往往需要额外接口或设计更复杂的总线方案。UART 本身也不负责规定完整的应用层数据包格式。

### 2. DMA：不是通信协议，而是自动搬运工

假设 UART 收到 1000 个字节。

如果完全依靠 CPU 逐个处理每个字节，CPU 就需要频繁响应接收事件。使用 DMA 后，可以让硬件把数据直接搬运到内存缓冲区。

UART 外设

收到数据

DMA 控制器

自动搬运，不需要 CPU 逐字节搬运

内存缓冲区 rxData[]

CPU 再读取并解析数据包

这里最关键的是：DMA 不决定数据通过什么线路传输，它只负责数据搬运。

所以你之前看到的 STM 32 代码里，UART、DMA、接收中断、缓冲区可以同时出现，它们并不冲突，而是在协同工作。

优点： 减少 CPU 负担，适合大量或连续数据。

缺点： 缓冲区管理、接收长度、缓存一致性（某些 MCU）、中断和数据同步等问题会让程序更复杂。DMA 也不会自动帮你解析协议或保证数据完整。

### 3. I²C：两根线连接多个低速设备

STM 32 主机

SCL 时钟

SDA 数据

传感器

地址 0 x 68

EEPROM

地址 0 x 50

时钟芯片

另一个地址

I²C 使用两根信号线：

- SCL：时钟线，通常由主机提供时钟。
    
- SDA：数据线，传输实际的数据。
    

主机先指定设备地址，再进行读写操作。同一条 I²C 总线上可以连接多个设备，只要地址配置合理，且满足总线的电气要求。

优点： 引脚少、连接方便，适合多个低速外围设备。

缺点： 通常不如 SPI 快；线路和上拉电阻设计有要求；设备地址冲突时需要调整地址或使用额外方案。

典型场景是 STM 32 读取 I²C 温度传感器，或者访问 EEPROM 保存的配置参数。

### 4. SPI：速度较高的同步串行通信

STM 32 主机

MOSI

主机 → 从机

MISO

从机 → 主机

SCLK

时钟

CS / NSS

选择从设备

典型 SPI 接口使用四类信号，具体实现可能不同。

SPI 由时钟同步数据传输。主机可以一边发送数据，一边接收数据；连接多个从设备时，通常通过各自的片选信号来选择通信对象。

优点： 通常速度快、传输效率高，适合大量数据。

缺点： 占用的引脚通常更多；多个设备可能需要多个片选信号；通信时序需要正确配置。

例如，STM 32 读取 SPI Flash，或者快速更新屏幕显示。

### 5. CAN：为多个控制节点设计的总线

CAN 和前面几种接口有一个明显区别：它非常重视多个设备共同使用一条总线时，如何协调通信以及处理错误。

CAN 总线

CAN_H / CAN_L 两根差分信号线

电机控制器

传感器节点

主控制器

CAN 上的设备不是简单地指定某个设备的 IP 地址或串口号，而是通过报文标识符（ID）区分消息的类型和优先级。多个节点都可以尝试发送，发生竞争时，CAN 会通过仲裁机制决定谁先发送。

优点： 多节点通信能力强，具有硬件仲裁、错误检测和故障处理机制，适合电磁干扰较多的工业与汽车环境。

缺点： 通信协议和调试相对复杂；需要 CAN 控制器和适当的物理层收发器；传统经典 CAN 的单帧数据长度最多为 8 字节，CAN FD 则支持更长的数据帧。

例如，机器人主控通过 CAN 给多个电机控制器下发速度命令，同时读取各个节点的状态。

## 六、把它们放在一起比较

下面是一个实用的选型总结。实际速度取决于芯片、外设和具体配置，不存在适用于所有场景的固定速度排名。

|维度|UART|DMA|I²C|SPI|CAN|
|---|---|---|---|---|---|
|是否为通信协议/接口|是，串行接口|否，数据搬运机制|是|是|是|
|典型信号线|TX、RX|不需要专用通信线|SCL、SDA|SCLK、MOSI、MISO、CS|CAN_H、CAN_L（经收发器）|
|多设备支持|通常点对点|取决于配合的外设|支持多设备|支持多从设备|支持多节点|
|典型优势|简单|减少 CPU 负担|省引脚|高吞吐量|总线仲裁、错误检测|
|典型用途|模块通信|大量数据搬运|低速传感器|Flash、屏幕|多节点控制|

对于你现在的学习阶段，我建议先把 UART、DMA 和接收缓冲区弄明白，因为你已经接触过 STM 32 与 IMU 的串口通信。然后学习 I²C 和 SPI，最后再深入 CAN 的多节点通信、仲裁和报文机制。

最重要的不是死记优缺点，而是建立这个判断方法：先看设备支持什么接口，再看数据量、实时性、设备数量和抗干扰要求，最后选择合适的通信方式。

## 动工顺序

1. 先向黄圣乔要 `husky@31ff2ea` 的分支、commit 或 patch，确认它基于哪个 main 版本。
2. 把本地 `main` 更新到远端最新 `4fb778e`；当前工作区有未提交文件，建议用干净 worktree 而不是直接覆盖。
3. 在干净 worktree 上从最新 `main` 建公共库分支，例如 `codex/legal-corpus-db`。
4. 复核 `LegalAgent_MVP_v2_Design/docs/03-数据模型与一致性.md` 和 `02-模块实施规格.md`，确定法源表是否沿用现有 PostgreSQL/Drizzle 模式。
5. 和朱皓宇确认 schema：稳定 ID、版本、原文、元数据、发布状态、来源和只读查询接口。
6. 和黄圣乔确认数据清单：法律、案例、字段、格式、数量、来源和历史版本。
7. 先导入最小样例集，再实现公共库服务；不要等全量数据才建库。
8. 公共库分支稳定后，再分别分出 `codex/legal-corpus-maintenance` 和 `codex/legal-corpus-platform`。

## 边界约束

1. 采集维护系统不依赖 main 分支的任何业务模块，只通过公共库的写入接口发布校验后的版本。
2. 公共法源资料库只暴露只读查询接口，不给平台或 Agent 写入能力。
3. 平台检索与展示只消费公共库，不直接访问采集任务、原始文件或维护内部状态。
4. 数据库检索尽量复用权威开源库，代码量保持最小，测试重点放在端到端和三个已知 bug 的回归。

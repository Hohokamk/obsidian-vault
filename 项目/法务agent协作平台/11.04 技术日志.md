### 黄的法源初版 Schema 复用核对

本次按用户问题读取 Husky 提交 `31ff2ea6` 的历史源码，确认多数 Schema 规则已经实现，可以作为拆分后的共同基线。以下为源码核对结果，没有执行数据库、采集或接口运行验证；未修改仓库代码或已有工作区改动。

- `migration.ts`：法规和案例共用 `la_corpus_documents`，以 `corpus=law|cases` 区分；`la_corpus_revisions` 保存版本，目录以 `current_revision_id` 指定当前发布版。
- `metadata.ts`：文档 ID 为 `lc_ + SHA-256(corpus:sourceId)`，版本 ID 为 `lcr_ + SHA-256(documentId:sha256)`；法规来源 ID 取 `bbbs`，案例取 `case_id`。hash 覆盖 Markdown 全部原始字节，采集时间等 front matter 改变也会产生不同版本。
- `store.ts`：原文字节写入不可变 BlobStore，PostgreSQL 保存 metadata JSONB、hash、object_ref 和大小；读取固定版本时复验字节数与 hash。共用表、ID 和存储规则可直接沿用。
- 初版写入链路：采集器写维护工作区 Markdown，`maintenance/worker.ts` 调用 `importer.ts` 的 `reconcile()`，再调用 `LegalCorpusStore.put()`；资料包导入由 `importBundle()` 走同一 put。没有独立 HTTP 写入接口。
- 初版耦合点：运维 CLI `tools/ops/legal-corpus.ts` 调用主应用 `bootstrap.ts` 的 `createServices()`；维护 Worker 与 Store 共享数据库，put 在有 jobId 时还会核查 `la_corpus_jobs`。但 Store 构造器本身只要求 Pool 和 BlobStore，已有可拆分基础，不需要重写整套存储。
- `controller.ts` 已提供当前目录、历史版本列表、固定版本原文和统计，只读接口可复用；初版 stats 的 search 为 `NOT_ENABLED`，不能把后来加入的关键词检索或 Agent tool 归为该初版功能。
- 历史版本限制：已知旧 hash 重放不会移动指针；首次遇到任何 hash 都可能成为当前版，因此第一次补录一个旧版本仍可能回滚。建议增加显式发布/历史补录意图，而非据入库顺序判定新旧。该问题本轮仅由历史源码确认逻辑，未重新运行回归。

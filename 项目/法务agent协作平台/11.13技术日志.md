## 问题与排查

**MC4 本地失败现象与证据**：失败时可访问性快照里报告正文已经渲染完（`region "成果正文"` → `heading "庭审复盘报告"` → `article` 内含完整复盘正文），`combobox "已保存报告版本"` 的选项文本是 `报告 1 · 固定版本 revision_...`，但第 116 行那个 `<Tag color="success">已保存 · 固定版本 {revisionId}</Tag>` 没有出现，也没有 `ErrorNotice`。

**推断（未验证）**：`SavedReport` 的 `verified` 查询是报告出现后才发起的独立异步请求；第 152 行只等到 `hearing.status==='COMPLETED' && reportRefs.length===1` 就立刻断言第 116 行的 Tag，本机比 CI runner 慢，查询未在 5 s 内返回时页面仍停在 `<Spin/>`，于是断言超时。若成立，这是测试固有的竞态，与本次 PR 的改动无关，但在慢机器上不稳定。

**审计中途发现并已消失的问题**：审计开始时工作树有 46 项未提交改动，当时 `npm run typecheck --workspace @legalagent/server` 失败：

```
test/legal-corpus.test.ts(234,21): error TS2339: Property 'closeAllConnections' does not exist on type 'Express'.
```

把该文件换回 HEAD 版本后同一命令通过，确认错误来自当时未提交的改动：第 166 行把 `app.getHttpAdapter().getInstance()` 断言成 `ReturnType<typeof express>`（Express 应用对象），而未提交改动在其上调用了只属于 `http.Server` 的 `closeAllConnections()`。并行会话随后提交并修正，现已通过。`NestFactory` 下正确入口是 `app.getHttpServer()`（`AbstractHttpAdapter.getHttpServer()` 返回 `initHttpServer()` 里 `http.createServer()` 的实例）。

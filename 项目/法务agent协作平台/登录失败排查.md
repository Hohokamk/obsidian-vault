# 登录失败排查：Better Auth Invalid Origin

## 时间
2026-10-29

## 现象

`dev`、`worker`、web 三个服务全部启动，Docker 容器正常运行，输入 `demo-credentials.json` 中的账号密码登录时，前端提示"暂时无法完成登录"。

## 排查过程

### 1. 检查基础服务状态

```bash
docker ps                    # 容器在跑
ss -tlnp | grep 3310         # API 在监听
ss -tlnp | grep 5173         # Web 在监听
ps aux | grep node           # dev + worker + vite 三个进程都在
```

三个服务均正常。

### 2. 查看 dev 服务器日志

关键报错：

```
ERROR [Better Auth]: Invalid origin: http://127.0.0.1:5173
{"route":"/api/auth/*splat","httpStatus":403}
```

## 根本原因

Better Auth 默认只信任 `baseURL`（`http://127.0.0.1:3310`）这个来源。

前端 Vite 开发服务器跑在 `http://127.0.0.1:5173`，通过 Vite proxy 把 `/api` 请求转发到后端。虽然流量到达了后端，但 `Origin` 请求头仍然是 `http://127.0.0.1:5173`。Better Auth 检查到请求来源不在信任列表内，直接拒绝，返回 403。

## 修复

编辑 `apps/server/src/auth.ts`，在 Better Auth 配置中加入 `trustedOrigins`：

```typescript
const options = {
    database: pool, secret: config.authSecret, baseURL: config.baseUrl,
    trustedOrigins: [config.baseUrl, 'http://127.0.0.1:5173'],   // ← 加这一行
    user: { modelName: 'la_auth_user' }, session: { modelName: 'la_auth_session', cookieCache: { enabled: false } },
    ...
};
```

重启 dev 服务后登录恢复正常。

## 正确的本地启动顺序

```bash
npm run dev:setup            # 首次或 Docker 容器停了之后必须跑
npm run dev                  # 终端 1：API
npm run worker               # 终端 2：Worker
npm run dev --workspace @legalagent/web   # 终端 3：Web
```

登录账号查看：

```bash
cat .local/demo-credentials.json
```

## 注意事项

- `dev:setup` 会启动 PostgreSQL 容器并做数据库迁移，如果容器已停，必须先重新跑一次
- `.env.local` 和 `.local/dev-state.json` 是 `dev:setup` 生成的，不需要手动创建
- 项目在 WSL (`/home/wgqq/projects/LegalAgent`) 中，不要改 Windows 上的副本

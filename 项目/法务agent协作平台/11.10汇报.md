### 1. 公共法源仓库（与朱皓宇协作）

我的工作：
1. schema 确认（敲定数据表的结构），数据盘点（对齐数据），导入数据快照进数据库 7804（数据已经完整）
2. 法源库的固定版本、只读边界、可追溯引用
```
法源库的存储是“PostgreSQL + BlobStore”双写结构：
库里有四张表：
`la_corpus_documents` 存资料目录（`corpus + source_id` 唯一）
`la_corpus_revisions` 存不可变版本（原文哈希、对象引用、元数据、检索文本）
`la_corpus_jobs` 和 `la_corpus_schedules` 存维护任务和调度
```
所有 ID 都是内容寻址、服务端生成：`documentId = lc_ + SHA-256(corpus:sourceId)`，`revisionId = lcr_ + SHA-256(documentId:sha256)`，对象路径跟着哈希走。所以同一份资料在任何机器、重复导入、重建数据库后 ID 都稳定，重复写入靠 `(document_id, sha256)` 唯一约束天然幂等。

使用方法：
1. 在律所知识库中直接搜索
2. 使用案件助手的 law_search 接口

状态读取：
```
npm run corpus:ops -- status    # 资料量、检索模式、时效标记
npm run corpus:ops -- health    # 采集端健康，OK/WARNING/CRITICAL
npm run corpus:ops -- jobs      # 维护任务列表
```

### 2. 采集维护系统   ：已经解耦


使用方式：
1. 网页前端查看采集记录
2. 终端命令

资源来源：写死了
* 国家法律法规数据库 `flk.npc.gov.cn` 抓法律
* 人民法院案例库 `rmfyalk.court.gov.cn` 抓案例


1.采集命令：

```
# 自检与看状态
npm run corpus:ops -- doctor
npm run corpus:ops -- health
npm run corpus:ops -- status
npm run corpus:ops -- jobs
```
  2.维护命令：

```
# 1. 自检与看状态（都不联网）
npm run corpus:ops -- doctor
npm run corpus:ops -- health
npm run corpus:ops -- status
npm run corpus:ops -- jobs

# 2. 案例采集前必须先人工登录，在弹出的专用浏览器里登录后关闭窗口
npm run corpus:ops -- login

# 3. 入队一个网络任务，--key 是幂等键，同键重复入队不会重复执行
npm run corpus:ops -- enqueue --kind LAW_SCAN --max-pages 5 --max-updates 20 --key law-scan-20261110
npm run corpus:ops -- enqueue --kind CASE_CHECK --key case-check-20261110

# 4. 执行：once 只领一个任务，corpus:worker 常驻循环领取
npm run corpus:ops -- once
npm run corpus:worker

# 5. 看结果，失败时看 .local/legal-corpus/state/jobs/<jobId>/ 下的 report.json 与 stdout/stderr
npm run corpus:ops -- job --id lcj_任务ID
```

整条流程是：**环境自检 → 看健康/语料状态 → 人工登录 → 入队法规扫描和案例检查 → 执行**。
法规扫描基本成功（18 条只是重复文件被跳过）；**案例检查失败在 `AUTH_REQUIRED`，需要重新执行 `login` 登录后再跑**。

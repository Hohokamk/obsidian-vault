## 2. STM32CubeG4的正确下载方法

不要使用GitHub网页“Download ZIP”，因为官方仓库使用子模块，ZIP可能缺少完整组件。

推荐：

```bash
git clone --recursive --depth 1 --branch v1.6.3 \
  https://github.com/STMicroelectronics/STM32CubeG4.git
```

验证：

```bash
cd STM32CubeG4
git describe --tags --always
git submodule status
```

预期：

- 标签显示`v1.6.3`；
- 子模块前没有`-`；
- `Projects/NUCLEO-G474RE/Examples/SPI`存在。

## 3. Python环境

建议使用Python 3.12：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r starter_code/requirements.txt
pytest starter_code/code/tests -q
```

创建锁文件：

```bash
pip freeze > requirements-lock.txt
```

`.venv`不能提交Git，它应能随时删除并重建。

## 4. KiCad版本

执行：

```bash
kicad-cli version
```

将输出写入：

```text
tools/version.txt
```

项目使用KiCad 10.0.x时，所有成员都应统一到10.0主版本；小版本不同可能导致命令参数和文件保存变化，因此正式下单前应由同一冻结环境生成最终制板包。

## 5. KiBot版本

KiBot 1.9.x已增加KiCad 10支持，但原生variants仍有实验性说明。本项目建议：

- ERC/DRC/Gerber/钻孔：优先`kicad-cli`；
- BOM、装配图、网页报告、CI打包：使用KiBot；
- 不把KiCad 10原生variant作为首版必须功能；
- 使用`kibot --version`记录版本；
- 使用容器时固定镜像标签，不用`latest`。

## 6. 硬件版本

建议：

```text
HW-P0：面包板8路
HW-P1：洞洞板16路
HW-A0：64路第一版PCB
HW-A1：64路修正版
HW-S0：256路系统第一版
```

每块板丝印包含：

- 项目缩写；
- 版本；
- 日期；
- 模块ID；
- 连接器方向；
- 1脚标记；
- 测试点名称。

## 7. 固件版本

采用语义版本：

```text
FW-0.1.0：GPIO/轮询
FW-0.2.0：SPI DMA
FW-0.3.0：协议和双缓冲
FW-0.4.0：64路
FW-1.0.0：256路核心冻结
```

固件应能查询：

- 固件版本；
- Git短提交号；
- 通道数；
- 模块数；
- SPI频率；
- 配置CRC；
- 错误计数。

## 8. 一致性检查

每次实验开始前打印：

```text
HW-A0
FW-0.4.1 / commit abc1234
CFG-0.3 / CRC 0x12345678
Host commit def5678
Python 3.12.x
KiCad 10.0.x
```

没有版本信息的数据，不能进入正式结题统计。

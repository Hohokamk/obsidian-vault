## 1. 搜索基本概念

### 1.1 形式化描述：五要素 ⭐必考

以求"城市 A 到城市 K 行驶时间最短路线"为例：

| 要素 | 定义 | 本例中是什么 |
|---|---|---|
| **状态** state | 对搜索算法和搜索环境**当前所处情形**的描述信息 | 算法当前所在的城市 |
| **动作** action | 从一个状态转移到另一个状态所采取的行为 | 乘一趟列车从当前城市到下一城市 |
| **状态转移** state transition | 选择动作后状态发生的相应变化 | 在 A 乘上去 D 的列车 → 状态 A 转移到 D |
| **路径 / 代价** | 状态序列 / 累计代价 | A→D→K 的行驶时间之和 |
| **目标测试** | 判断当前状态是否为目标状态 | 是否到达城市 K |

**关键设计原则（课件强调）**：**状态要剔除与求解无关的细节。**
> 城市例子里，"每个城市的人口情况"不影响下一步决策，所以被剔除；只有"算法当前位于哪个城市"起作用。

**另一个重要性质（课件强调）**：本课程讨论的所有问题中，**任何状态下可选择的动作都是离散的**，而非连续。

### 1.2 搜索过程 = 搜索树的构建

- **根节点** = 初始状态
- **扩展**：从节点长出后继节点（= 应用所有可行动作）
- **实线结点** = 已被扩展；**虚线结点** = 在**边缘集合（frontier）** 中，待扩展
- 两种基本遍历（课件给了 C 与 Python 两份代码）：
  - **DFS 深度优先**：一路走到底再回溯
  - **BFS 广度优先**：一层一层铺开

### 1.3 搜索算法的四个评测标准 ⭐必考

| 标准 | 含义 |
|---|---|
| **完备性** | 当问题**存在解**时，算法能否保证**找到一个解**（这个解可能不是最优解） |
| **最优性** | 算法能否保证**找到的第一个解就是最优解** |
| **时间复杂度** | 找到一个搜索路径所需时间 |
| **空间复杂度** | 算法运行时所需的内存空间 |

> ⚠️ **最容易混的一点**：完备性 ≠ 最优性。BFS 是完备的（有解必找到），在单步代价相同时才最优。贪婪搜索通常不最优。

### 1.4 通用搜索框架（PPT 是图片，这里补全）

```
frontier ← { 初始状态 }
explored ← { }                      # 已扩展集合，防止重复

loop:
    if frontier 为空: return 失败
    n ← 从 frontier 中取出一个节点    # ★ 唯一的自由度就在这里
    if n 通过目标测试: return 解
    explored ← explored ∪ {n}
    for each 后继节点 m of n:
        if m 不在 explored 且不在 frontier:
            frontier ← frontier ∪ {m}
```

> **记住这句话**：所有搜索算法的差别，**只在"从 frontier 里取哪一个"这一步**。
>
> | 算法 | 取哪个 |
> |---|---|
> | BFS | 最浅的（队列） |
> | DFS | 最深的（栈） |
> | 贪婪最佳优先 | h(n) 最小的 |
> | A* | f(n) = g(n) + h(n) 最小的 |

### 1.5 搜索的其他应用（容易被忽略）

课件举了两个例子说明搜索的普遍性：

- **围棋落子的选择**（AlphaGo）——每步在合法落子中选一个
- **大语言模型的生成**——每步从**词汇表**中选择一个词来生成

> 后一个例子值得留意：**大模型逐词生成，本质上也是搜索**。这是把经典 AI 和现代 AI 串起来的一个点。

## 2. 贪婪最佳优先搜索与 A* 搜索

### 2.1 两个函数，必须分清 ⭐

| 函数 | 含义 | 是否"真实" |
|---|---|---|
| **启发函数 h(n)** | 从节点 n 到**目标**的**估计**代价 | **估计**（如直线距离） |
| **评价函数 f(n)** | 决定**扩展顺序**的依据 | —— |

**两个算法的差别只有一行**：

| 算法 | 评价函数 | 它在乎什么 |
|---|---|---|
| **贪婪最佳优先搜索** | `f(n) = h(n)` | 只看"**离目标多远**"，完全不管已走多远 |
| **A\* 搜索** | `f(n) = g(n) + h(n)` | g = 从**起点**到 n 的**实际**代价，h = 到目标的估计代价 |

> 课件把贪婪搜索归入"**有信息（informed）搜索**"或"**启发式（heuristic）搜索**"。
>
> **记忆**：`g` 是 **g**one（已走过的实际路），`h` 是 **h**euristic（猜的）。

### 2.2 贪婪搜索为什么会失败（P21）

因为它**完全忽略已付出的代价**——只看"下一步看起来离目标近"，于是：

- 可能走进一条"看着近、实际贵"的路
- **不最优**（课件的图显示，贪婪找到的不是真正的最短路线）
- 在图上可能来回震荡

### 2.3 A\* 的两个关键性质 ⭐⭐ 全章最高频考点

#### 可容性（admissible）

$$h(n) \le h^*(n)$$

**启发函数永远不会高估真实代价**（h\* 是真实最优代价）。

- 直觉：h 是一个**乐观**的估计
- 例：两点间的**直线距离**永远 ≤ 实际路程 → 直线距离是可容启发函数

#### 一致性（consistency，又称单调性）

$$h(n) \le c(n, n') + h(n')$$

即"三角不等式"：从 n 走一步到 n′ 之后再估计，不会比直接在 n 估计更便宜。

- 等价理解：**沿任何路径前进，h 值不会下降超过一步的实际代价**

#### 两者的关系（P27，必考）

> **一致性是一个比可容性更严格的性质：满足一致性 ⇒ 必然满足可容性。反之不成立。**

#### A\* 的完备性（P28）

同时满足以下三条时，A\* **完备**：

1. 搜索树中分支数量有限（每个节点的后继节点数量有限）
2. **单步代价的下界是一个正数**
3. 启发函数有下界

#### A\* 的最优性（P29）

> **如果启发函数是可容的，那么 A\* 算法满足最优性。**

这是全章最经典的一条定理，**必须能默写**。

> 记忆链：**h 乐观（可容）→ A\* 不会错过最优解 → 最优性成立**。

## 3. Minimax 搜索与 alpha-beta 剪枝

### 3.1 对抗搜索（adversarial search / 博弈搜索）

两个智能体同处一个竞争环境，**目标相反**：一方想最大化自身利益，另一方想最小化对手利益。

课件题词：
> 狭路相逢勇者胜 / 勇者相逢智者胜 / 智者相逢德者胜 / 德者相逢道者胜

### 3.2 Minimax 的若干定义（P31 是图片，这里补全）

| 概念 | 含义 |
|---|---|
| **终局效用** `Utility(s)` | 对**终止状态**打分（如胜 = +1、负 = −1、平 = 0） |
| **MAX 节点** | 轮到"**我**"行动，取子节点的**最大值** |
| **MIN 节点** | 轮到"**对手**"行动，取子节点的**最小值** |
| **Minimax 值** | 双方都采取最优策略时，当前状态能**保证**得到的效用 |

**名字由来（课件 P32 原话）**：
> "玩家 1 总是选择能够**最大化**终局得分的搜索树分支，而玩家 0 总是选择能够**最小化**终局得分的搜索树分支，**最小最大**算法的名字即由此而来。"

### 3.3 Minimax 算法流程（P33 是图片）

```python
def minimax(state, depth, is_max):
    if 是终止状态(state) or depth == 0:
        return 评估函数(state)          # 到深度上限就用评估函数代替
    if is_max:
        return max(minimax(s, depth - 1, False) for s in 后继(state))
    else:
        return min(minimax(s, depth - 1, True) for s in 后继(state))
```

**复杂度**：`O(b^m)`（b = 每层分支数，m = 搜索深度）→ 这就是"组合爆炸"的来源。

### 3.4 alpha-beta 剪枝

**定义（课件 P34 原话）**：
> "Alpha-Beta 剪枝搜索算法在 Minimax 算法中**可减少被搜索的结点数**，即在**保证得到与原 Minimax 算法同样的搜索结果**时，剪去了不影响最终结果的搜索分枝。"

**两个变量的含义**：

| 变量 | 含义 |
|---|---|
| **α** | MAX 节点目前已知的**最好**选择——即 MAX 能保证拿到的**下界** |
| **β** | MIN 节点目前已知的**最好**选择——即 MIN 能保证压到的**上界** |

**剪枝条件：当 α ≥ β 时，停止扩展当前节点的剩余子节点。**

**为什么叫 alpha 和 beta**（P37 是图片）：
- α 沿 MAX 层向下传递，β 沿 MIN 层向下传递
- 一旦出现 `α ≥ β`，说明"这个分支对上层已经毫无价值"——因为上层要么已经能拿到更好的，要么已经能压得更低

**两类剪枝**：

| 名称 | 发生在 | 条件 |
|---|---|---|
| **alpha 剪枝** | **MIN** 节点的后代（P35） | 某子节点值 ≤ α → 剪掉该 MIN 节点的剩余子节点 |
| **beta 剪枝** | **MAX** 节点的后代（P36） | 某子节点值 ≥ β → 剪掉该 MAX 节点的剩余子节点 |

> **剪枝效果**：最好情况下把复杂度从 `O(b^m)` 降到 `O(b^(m/2))`——**同样的时间可以搜索两倍的深度**。

### 3.5 延伸阅读：两个著名的"困"（P57，很好的开放题素材）

**① 组合爆炸之难 —— 香农之数**

- 1950 年香农估算国际象棋：第 1 步 20 种落子 → 第 2 步 400 种 → **第 6 步达 1.19 亿种**
- 国际象棋落子总数约 **10^120**，而宇宙原子总数才 **10^82**
- 深蓝平均每秒能判断 **1 亿个棋局**，仍无法在规定时间内算完
- 深蓝的解法：采用 1971 年图灵奖得主 **John McCarthy 发明的 alpha-beta 剪枝**

**② 地平线问题之困（horizon problem）**

- 2016 年 3 月 AlphaGo 以 **4:1** 战胜李世石
- 第四局第 78 手，李世石下出"**上帝之落子**"，扭转乾坤
- AlphaGo 无法应对的原因：**搜索算法固有存在的地平线问题**——搜索算法看不到"地平线以下"的景象
- 课件结论："**计算机暴力搜索计算**"与"**人类直觉顿悟**"之间的差异，突破地平线之困依靠搜索之能还相距甚远

## 4. 蒙特卡洛树搜索（MCTS）⭐ 实训核心

### 4.1 为什么需要 MCTS（P50）

复杂问题下搜索树巨大到无法完全探索。前面两种优化（启发式扩展顺序 + alpha-beta 剪枝）都是为了**高效地扩展搜索树**。

如果把目标**降为"近似最优解"**，问题就变成：
> 算法从根节点开始，每一步的动作是**选择**（在非叶子节点）或**扩展**（在叶子节点）一个孩子节点；用执行该动作后收获的**奖励**来判断动作优劣。

由于用**蒙特卡洛采样**来估计节点价值，所以叫**蒙特卡洛树搜索**。

### 4.2 核心动机：探索 vs 利用（P43）

课件的赌博机实验：
> 贪心算法对编号 4 的赌博机"情有独钟"，很少去摇其他机器。于是对 4 号的估计越来越准，但**其他机器的估计一直不准**；而这些不准确的估计又反过来让智能体错误地认为 5 号不如 4 号。

**困境**：**探索（exploration）与利用（exploitation）相互对立**。

- 纯利用：拿已有估计指导行动——但估计往往不能反映**未被充分探索**的动作
- 解法：给贪心算法加一个"**能改变其惯性的内在动力**"，让它去访问尚未被充分访问过的空间

> 这个"内在动力"的数学形式，就是 UCB1 的探索项。

### 4.3 UCB1 算法

**策略（课件 P46 原话）**：
> "为每个动作的奖励期望计算一个**估计范围**，优先采用**估计范围上限**较高的动作。动作 1 的奖励期望取值的不确定度虽然最大，但因为其**均值太小**，所以 UCB1 不优先考虑探索动作 1。动作 2 和 3 的奖励期望均值相同，但动作 2 的不确定度更大，于是因为**置信上限更大**，动作 2 被优先考虑。"

**UCB1 公式（PPT 是图片，这里补全）**：

$$UCB1(i) = \underbrace{\bar{X}_i}_{\text{利用}} + c\underbrace{\sqrt{\frac{2\ln N}{n_i}}}_{\text{探索}}$$

| 符号 | 含义 |
|---|---|
| $\bar{X}_i$ | 动作 i 的**平均奖励** |
| $n_i$ | 动作 i 被选择的**次数** |
| $N$ | **总**选择次数 |
| $c$ | 探索常数（理论值 $\sqrt{2}$，可调） |

**看懂这个公式的关键**：
- 第一项是"**利用**"——过去表现好的，分数高
- 第二项是"**探索**"——$n_i$ **越小**（访问越少），这一项**越大** → **自动鼓励去试冷门的动作**
- 两项相加取最大 → 在"贪心"和"好奇心"之间自动平衡

**未访问过的节点**：$n_i = 0$ 时该项为无穷大 → 保证所有节点至少被访问一次。

**霍夫丁不等式（P48）**：
> 衡量"随机变量均值与期望偏差"的不等式，由 **Wassily Hoeffding 于 1963 年**提出。核心作用是：**在不依赖随机变量具体分布的情况下**，用"样本量"和"取值范围"来量化"**样本均值偏离总体期望的概率上限**"。

$$P\left(|\bar{X} - \mathbb{E}[X]| \ge \varepsilon\right) \le 2\exp(-2n\varepsilon^2)$$

> UCB1 的置信区间就是从这里推出来的：取 $\varepsilon = \sqrt{2\ln N / n_i}$ 即得。**这就是"探索项"的数学出处**——样本量 n 越少，ε 越大，置信上限越高。

### 4.4 MCTS 四要素 ⭐⭐ 必考、必会写

| 阶段 | 英文 | 做什么 | 用什么策略 |
|---|---|---|---|
| **选择** | selection | 从根节点开始**向下递归选择**子节点，直到到达叶子节点或**尚未被完全扩展**的节点 L。过程中记录每个节点的被选择次数与奖励均值 | **UCB1** |
| **扩展** | expansion | 若 L **不是终止节点**，随机扩展它的一个**未被扩展过**的后继节点 M | 随机 |
| **模拟** | simulation | 从 M 出发模拟到终止节点（下图 (c)） | **简单策略，通常随机** |
| **反向传播** | back propagation | 用模拟结果（终局代价或分数）**回溯更新** M 及其以上所有节点的奖励均值和被访问次数 | —— |

> **最容易记混的一点**：**"选择"用 UCB1，"模拟"用随机策略**——两者策略不同，课件特意强调了。

### 4.5 实现细节：MIN / MAX 层的符号处理 ⚠️ 最容易写错

课件 P53 的算例：
- 随机扩展 L 的子节点 C，**总分数和访问次数均初始化为 0**
- 随机模拟到终局，**终局得分 = 3**
- 更新后：**C 节点 = −3 / 1 次；L 节点 = 13 / 2 次；根节点 = −18 / 3 次**

**符号规则（课件原话）**：
> "在更新时，会将 **MIN 层结点现有总分加上终局得分，MAX 层结点现有总分减去终局得分**。这是因为在对抗搜索中，玩家 MIN 总是期望**最小化**终局得分，因此在 MIN 层选择其子结点时，其目标并非选取奖励最大化的子结点，而是选择奖励**最小化**的结点。**为了统一使用 UCB1 算法求解**，算法将 MIN 层的子结点（即 MAX 层结点）的总分记为**其相反数**。"

> **白话**：UCB1 只会挑最大值，但 MIN 层要挑最小值。**所以把 MIN 层节点的分数取负号**，这样"最小化"就等价于"最大化负数"了。

**另一个细节**：为了让算法下次访问到 L 时**必然扩展**其余未扩展的子节点，这些节点的 UCB 值被标记为 **+∞**。

### 4.6 实验：黑白棋（Mini AlphaGo）⭐ 实训原题

#### 游戏规则（课件原文整理）

- 棋盘 **8×8**，双面黑白棋子
- 开局：**黑棋位于 e4 和 d5，白棋位于 d4 和 e5**
- **黑方先行**，双方交替下棋
- 一步**合法棋步** = 在**一个空格**新落下一子，**并且翻转对手一个或多个棋子**
- 新落下的棋子与棋盘上已有同色棋子间，**对方被夹住的所有棋子都要翻转**（横向、纵向、对角线均可）
- 夹住的位置上**必须全部是对手的棋子，不能有空格**
- 一步棋可以在**数个方向同时翻棋**；**任何被夹住的棋子都必须翻转，棋手无权选择不翻**
- **除非至少翻转对手一个棋子，否则不能落子**
- 如果一方**没有合法棋步**（下到哪里都不能翻转），这一轮**只能弃权**，由对手继续落子，直到他有合法棋步
- **如果一方至少有一步合法棋步，就必须落子，不得弃权**
- 棋局持续到**棋盘填满**或**双方都无合法棋步**
- **某一方落子时间超过 1 分钟，判该方失败**

## 5. 本章小结与难点清单

### 一句话总结

> 搜索 = **把问题变成状态空间，把求解变成在搜索树上找路径**。所有算法优化都在权衡两件事：**优先扩展谁、放弃扩展谁。**

### 六个容易丢分的点

1. **完备性 ≠ 最优性**——完备只管"有没有解"，最优才管"解好不好"。
2. **贪婪 vs A\***：差别只在评价函数——`f = h` vs `f = g + h`。g 是**实际**走过的，h 是**估计**剩下的。
3. **可容性 vs 一致性**：`h(n) ≤ h*(n)` vs `h(n) ≤ c(n,n') + h(n')`；**一致性更强，一致性 ⇒ 可容**，反之不成立。
4. **α 和 β 的方向**：α 是 MAX 的下界，β 是 MIN 的上界；`α ≥ β` 就剪枝。
5. **MCTS 四阶段别混淆策略**：**选择用 UCB1，模拟用随机**。
6. **MCTS 中 MIN 层分数要取负号**，否则没法统一用 UCB1。

### 实训推进建议

Mini AlphaGo 的骨架就五块：

```
1. 棋盘表示 + 合法走法生成（含"夹住翻转"的实现）
2. 落子后的翻转与胜负判定
3. MCTS 主循环：选择(UCB1) → 扩展 → 模拟(随机) → 反向传播(含 MIN 层取负)
4. 时间控制：每步设一个时间预算（如 1 秒），在预算内尽量多迭代
5. 图形界面：tkinter 即可（标准库，不违反"不用现成包"的要求）
```

**最容易卡住的两处**：
- **合法走法生成**中的"夹住"判定（八个方向遍历、必须整段是对手棋子）
- **MCTS 的 MIN 层符号处理**（上面 4.5 节）

**建议**：先用纯 Minimax + alpha-beta 写一版能跑通的（简单、好调试），再加 MCTS。这样你会有两套对照，报告也好写。

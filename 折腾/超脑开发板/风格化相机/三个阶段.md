**1. 混合架构方案（扩散模型）：适合追求画面上限的“小电脑”**

- **优势：** 真正的生成式大模型，理解能力极深。不仅能做风格变换，还能根据文本在画面中凭空增减元素（例如加一副赛博朋克墨镜）。
    
- **代价：** 算力严重超标。虽然 LCM/Turbo 将步数压缩到了 1~4 步，但 RK 3588 的 NPU 专为定点 CNN 设计，对 Transformer 中的 Attention 矩阵计算和高频显存搬运并不擅长，导致快门按下后有明显的“转圈等待感”。
    

**2. 意图理解路由方案（SLM + 预设 CNN）：适合商业级体验的离线产品**

- **优势：** 速度最快、稳定性最高。利用端侧小语言模型（如 Qwen 2.5-0.5 B）来包容用户的自然语言输入，实际画画的工作交给 NPU 最拿手的纯 CNN 跑，几乎可以做到“咔嚓”按下一秒内出图。
    
- **代价：** 本质是“高级多选一”。如果用户输入一个非常偏门的新词（比如“莫奈画的火星沙漠”），模型只能强行将它归类为“印象派油画”，无法产生完全贴合新词的个性化纹理。
    

**3. CLIP-Styler 类架构：平衡自由度与嵌入式算力的最佳折中**

- **优势：** 兼顾了前两者的长处。由于引入了 CLIP 的跨模态文本特征向量，它能真正接收开放式的风格文本（不需要提前为每种风格单训一个模型）；同时去掉了扩散模型繁琐的迭代去噪过程，只需一次前向传递。
    
- **代价：** 仅能改变纹理、色彩与表面材质，不能对画面内容做大幅度的形状扭曲或语义替换（即原图里是一张脸，生成图必定精准保留该五官结构，只是变成黏土质感或青铜材质）。



方案：
### Phase 1：骨架搭建与极简闭环（用 OpenCV 跑通软硬件链路）

**目标：** 不碰复杂的模型转换，1~2 天内跑通“拍照 $\rightarrow$ 处理 $\rightarrow$ 屏幕展示”的全流程，验证硬件稳定性。

- **开发内容：**
    
    1. 使用 Python `cv2.VideoCapture` 调通 USB 摄像头实时预览。
        
    2. 绑定一个键盘按键（或板载 GPIO 轻触微动）作为物理快门：按下瞬间截取当前帧。
        
    3. 挂载 3~4 个 OpenCV 内置的极速滤镜算法做测试：
        
        - 素描风：`cv2.pencilSketch`
            
        - 漫画轮廓：边缘检测 Canny + 双边滤波 Bilateral Filter
            
        - 油画质感：`cv2.xphoto.oilPainting`
            
    4. 使用全屏窗口将处理结果推流到 HDMI 屏幕，附带 3 秒倒计时与拍照闪烁动效。
        
- **里程碑结果：** 做出一个能在屏幕上即时拍照、按数字键切换 OpenCV 滤镜的基础拍照机。
    

### Phase 2：意图理解路由方案（SLM + 预编译多风格 CNN）

**目标：** 引入大语言模型（SLM）接管交互，实现“自然语言输入 $\rightarrow$ 毫秒级 NPU 艺术重绘”。

- **技术拆解与落地步骤：**
    
    1. **部署端侧文本大脑：**
        
        - 在板子上用 `llama.cpp` 部署 **Qwen 2.5-0.5 B-Instruct (Q 4 _K_M)**。
            
        - 设计结构化 System Prompt，约束其只能输出预设的风格代号：
            
            > _“你是一个相机指令路由器。根据用户的描述，必须只输出以下代号之一：[VAN_GOGH, UKIYOE, CYBERPUNK, SKETCH, ANIME]。”_
            
    2. **准备 RKNN 风格网络：**
        
        - 采用经典的 **Fast Neural Style Transfer** 或 **CycleGAN**。
            
        - 寻找开源的预训练 ONNX 权重（涵盖梵高星空、浮世绘神奈川冲浪里、波普艺术等），利用 PC 上的 `rknn-toolkit2` 将其量化导出为 `.rknn` 格式并复制到板子上。
            
    3. **逻辑总控：**
        
        - 用户按住快门并输入文字（或说话）：“我想拍出浮世绘的感觉”。
            
        - Qwen 2.5 在 200 ms 内解析出 `UKIYOE` 标签。
            
        - Python 主程序直接调用 `rknn.load_rknn('ukiyoe.rknn')`，在 NPU 上推导当前画面（耗时约 50~100 ms）。
            
- **里程碑结果：** 实现了“你说什么风格，相机一秒内就变出对应名画笔触”的完整离线智能交互。
    

### Phase 3：CLIP 引导的任意风格迁移（摆脱写死预设，迈向开放式 Prompt）

**目标：** 不再局限于提前训练好的几种固定风格，让相机支持自由输入冷门艺术词汇。

- **技术架构（CLIP-Styler 机制）：**
    
    1. **文本语义提取：** 采用轻量级的 **CLIP ViT-B/32 文本端**。输入用户任意的 Prompt（如“赛博朋克霓虹雨夜”、“青铜器锈迹质感”），提取出 512 维的文本语义向量。
        
    2. **AdaIN（自适应实例归一化）前馈网络：**
        
        - 使用一个通用的前馈编码-解码卷积网络。
            
        - 网络的中间层利用 AdaIN，将图像的均值和方差强制对齐到 CLIP 文本向量所对应的艺术特征分布上。
            
    3. **部署优化：**
        
        - CLIP 文本端走 CPU 或 NPU，图像前馈网络走 NPU。
            
        - 单次推导无需迭代，在板子上 1~2 秒即可完成渲染。
            
- **里程碑结果：** 任意输入未曾预置的词汇，画面依然能精准渲染出对应的色彩基调与表面质感。
    

### Phase 4：硬件与产品化封装（把它变成真正的“便携相机”）

**目标：** 脱离键盘和连线束缚，包装成可握持的完整极客玩具。

- **外设功能融合：**
    
    - **语音交互：** 接入板载麦克风，前置一个轻量离线语音唤醒/识别（如 Sherpa-NCNN），按住快门直接说话，松开即出图。
        
    - **按键与状态反馈：** 利用板载 GPIO 接两颗双色 LED（绿色表示待机，呼吸闪烁表示推理中，常亮表示出图完成）。
        
    - **相册留存：** 每次出图自动打上时间水印，存入板载目录，并启动一个简易的本地 Web 服务器（如 Flask），手机连上板子热点扫码即可直接把照片下载到手机相册。

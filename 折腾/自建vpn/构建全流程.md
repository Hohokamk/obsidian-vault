## 最终架构（当前运行状态）

```
[手机 / 电脑 客户端]
      │
      ├─ 走 443 ──► Cloudflare CDN（komod.dpdns.org）──► VPS :443  VLESS-WS-TLS（主力，隐藏真实 IP）
      │
      └─ 走 8080 ──────────────────────────────────────► VPS :8080  VLESS-Reality（抗封锁，直连备用）
```

| 节点 | 端口 | 协议 | 伪装 | 用途 |
|---|---|---|---|---|
| VLESS-WS-TLS | 443 | 走 Cloudflare CDN 反代 | 域名 komod.dpdns.org | 主力伪装 + 隐藏真实 IP + 防失联 |
| VLESS-Reality | 8080 | 直连 VPS | itunes.apple.com（RAW/Reality） | 高抗封锁，直连备用 |

**关键信息**：
- VPS：`95.182.91.188`（美西 / Fremont 硅谷），Debian 12，1GB 内存 + 2GB Swap，单核，10GB 盘
- 3X-UI 面板：端口 `55321`，Base Path `/VJ8Pu0PKvx4rLnmOIO/`，登录凭据见 [[heihei]]
- 域名：`komod.dpdns.org`（托管在 Cloudflare，橙色云朵开启）
- 证书：Cloudflare **15 年源服务器证书**（`/root/cert/cf.crt` + `/root/cert/cf.key`），SSL 模式 **Full**
- 还开了一个 2096 端口的空监听（Go 空监听，可忽略）

## 一、需求与选型

- **目标**：自建代理，稳定过谷歌/OpenAI 风控，能访问 Gemini / ChatGPT 及大部分网站
- **核心思路**：抗封锁协议（VLESS-Reality / Hysteria2）+ Cloudflare WARP 出站分流（解决 AI 服务风控）
- **选型建议**：
  - 节点优先：美国（硅谷/洛杉矶）、日本（东京）、新加坡
  - 系统优先 **Debian 12**（1GB 小内存最省），Ubuntu 22.04 也可以（需挂 Swap）
  - 1GB 内存建议加 2GB Swap 防 OOM

## 二、VPS 购买（HostVDS）

- HostVDS 按小时计费，可随时销毁退费；当时只剩巴黎 / 里加 / 香港，最终**抢到美西（硅谷）** `95.182.91.188`
- 套餐先选**免费档**（Limited 50 Mbps / 500GB），后续可在控制台随时升级带宽，按小时折算
- 创建时：SSH 密钥留空（用 root 初始密码登录）、主机名随意、IP 选 **IPv4**（不要单选 IPv6）

## 三、服务器基础优化

```bash
# SSH 连接
ssh root@95.182.91.188

# 1. 开启 BBR
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p
sysctl net.ipv4.tcp_congestion_control   # 应输出 = bbr

# 2. 增加 2GB 虚拟内存（1GB 内存必做）
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 四、3X-UI 面板安装（含排坑）

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

安装选项：
- Database：**1 (SQLite)**（轻量，个人用首选）
- 自定义配置：输入 `y` → 设置用户名 / 密码 / 端口（用了 **55321**）
- SSL certificate：**4 (Skip SSL)**（面板走 http 即可，代理加密由协议层负责）
- **Bind the panel to 127.0.0.1 only?** → 输入 **n**（否则面板无法公网访问）

> ⚠️ **排坑记录**
> - **安装中断**：重跑脚本即可，3X-UI 脚本幂等，自动覆盖不冲突
> - **打不开面板（404）**：新版 3X-UI 会生成随机 **Base Path**，必须访问完整路径：
>   `http://95.182.91.188:55321/VJ8Pu0PKvx4rLnmOIO/`
>   可用 `x-ui` 菜单里的 `Reset Web Base Path` 改成 `/admin/` 或清空为根目录
> - **登录失败**：默认 admin/admin 无效时，用 `x-ui` 菜单重置用户名密码（重设时 2FA 相关选 `y` 清除）

## 五、VLESS-Reality 节点配置

面板 → 入站列表 → 添加入站：

| 配置项 | 值 |
|---|---|
| 协议 | vless |
| 端口 | 8080 |
| 传输 | **RAW**（新版 3X-UI 里 TCP 叫 RAW） |
| 安全 | reality |
| uTLS | chrome |
| Dest | `itunes.apple.com:443` |
| SNI | `itunes.apple.com`（不带端口，可删掉面板自动扫出来的多余域名） |
| Flow | `xtls-rprx-vision`（在客户端 Client 里设置，不是高级配置 JSON） |
| 密钥 | 点"获取新密钥"自动生成公私钥 + Short ID |
| 嗅探 | 开启（http / tls） |
| 高级配置 | 全部保持默认（Proxy Protocol / HTTP 混淆等都不开） |

> ⚠️ **导出链接空白**：把「分享地址策略」从「入站监听地址」改为**自定义**，填入公网 IP `95.182.91.188`，再添加客户端（UUID）即可导出有效 `vless://` 链接。

**入站 vs 客户端（理解）**：
- 入站 = 服务器的"大门与安保系统"（端口 + 协议伪装）
- 客户端 = 专属会员卡（UUID），需**关联入站**才能生成完整链接

## 六、客户端连接与排障

| 问题 | 原因 | 解决 |
|---|---|---|
| 手机连不上，日志 `REALITY: received real certificate` | 手机 v2rayNG 内核版本过旧，Reality 握手指纹不兼容 | **升级 v2rayNG 到最新版**（问题即解决） |
| 手机能 Ping 通但真连接 -1 | 同上 / 测速 URL 被墙 | 更新版本；改测速 URL 为 `https://www.google.com/generate_204` |
| 手机连上后国内网也不通 | 路由模式选了全局，Reality 又握手失败把整机流量堵死 | 路由模式改「绕过局域网及大陆地址」，国内 DNS 填 223.5.5.5 |
| 速度只有 500KB/s ~ 5Mbps | **线路问题**：走电信 163 普通骨干网（无 CN2 GIA/9929 优化），晚高峰丢包 → TCP 降速 | 这是物理瓶颈非配置错误；对策：加开 Hysteria2（UDP）或换优化线路 |

**线路诊断**（验证是普通 163 线路）：
```bash
curl https://raw.githubusercontent.com/zhanghanyun/backtrace/main/install.sh -sSf | sh
# 结果出现 202.97.x.x (AS4134) = 电信163普通线路；59.43.x.x = CN2 GIA 精品线
```

**关于 Cloudflare 能否提速**：❌ 不能。免费 CDN 对国内直连反而绕路 + 晚高峰 QoS 更严重，且**不支持 Reality**（只能用 WS），只能用于"防 IP 被墙"，不能解决线路差。

## 七、Cloudflare CDN 反代（备用防失联节点）

> 目标：隐藏 VPS 真实 IP，且 VPS IP 万一被墙仍可通过 CDN 连接。协议必须改为 VLESS + WebSocket + TLS。

### 7.1 域名 + DNS 托管
1. **买域名**（推荐 Cloudflare Registrar 或 Namecheap/Namesilo 买便宜的 .top/.xyz，首年 $1-3，支持支付宝）
2. 域名接入 Cloudflare：Cloudflare「Add a site」→ 免费版 → 拿到两组 Nameserver → 回注册商后台把 NS 改成 Cloudflare 的（5~15 分钟生效，状态变 Active）
3. Cloudflare DNS → Records 添加：
   - Type：`A`，Name：`node`（或 `@` 表示根域名），IPv4：`95.182.91.188`
   - **Proxy status 必须开橙色云朵（Proxied）**——这才让流量走 CDN

### 7.2 3X-UI 新建 VLESS-WS 入站
| 配置项 | 值 |
|---|---|
| 协议 | vless |
| 端口 | `8080`（Cloudflare 支持的 HTTP 端口：80/8080/8880/2052/2082/2086/2095） |
| 传输 | `ws` |
| 路径 | 自定义，如 `/api-stream`（"暗号门牌"，未授权的探测请求被拦） |
| 安全 | `none`（TLS 由 Cloudflare 前端负责） |
| 客户端 | 可复用现有 UUID（两个入站同 UUID 无冲突），记得关联入站 |

### 7.3 客户端参数（关键，必须手动改）
3X-UI 导出的链接默认指向 VPS 真实 IP + 8080，**不会自动走 Cloudflare**，需"换头"：
- 地址：VPS IP → 域名（如 `node.komod.dpdns.org`）
- 端口：8080 → **443**
- 传输安全：开启 **TLS**，SNI / Host 都填域名

### 7.4 Cloudflare 侧设置
- **SSL/TLS 模式**：当前用 Origin 证书 + 443 TLS 后应为 **Full / Full Strict**；若入站还是 8080+none 则必须 **Flexible**（区别见下一节）
- 开 **WebSockets**（Network）
- 关「始终使用 HTTPS」重定向（SSL/TLS → 边缘证书），避免干扰 WS 升级握手
- 关 Rocket Loader / Auto Minify（Speed → Optimization）

> 💡 走不走 CDN 的决定因素是**地址填域名还是填 IP**，不是端口。连域名的 8080 照样经过 Cloudflare；地址填 VPS 真实 IP 才是直连跳过了 CDN。

## 八、15 年证书 + 443 全链路 TLS 升级

> 目的：让导出的订阅链接原生自带 443 + TLS，客户端无需手动改参数，且实现端到端加密。

1. **生成证书**：Cloudflare → SSL/TLS → 源服务器 → 创建证书（15 年有效期，RSA 2048）。**私钥只显示一次，先保存好**
2. **存入 VPS**：
   ```bash
   mkdir -p /root/cert
   nano /root/cert/cf.crt   # 粘贴源证书 (-----BEGIN CERTIFICATE-----)
   nano /root/cert/cf.key   # 粘贴私钥   (-----BEGIN PRIVATE KEY-----)
   chmod 644 /root/cert/cf.crt
   chmod 600 /root/cert/cf.key
   ```
3. **3X-UI 入站改**：端口 `443`、安全 `tls`、证书路径填上面两个文件、SNI 填域名、传输保持 ws + Host 域名
4. **Cloudflare**：SSL/TLS 模式切到 **Full / Full Strict**
5. 协议层解密/加密保持 `none`（VLESS 不做应用层加密，交给 TLS）

> ⚠️ **验证结果**：443 的 WS 升级返回 `101 Switching Protocols` ✅、8080 Reality 透传正常 ✅、服务端配置正确。
> 若客户端**直连 VPS IP** 时会因为 Origin 证书不是公共 CA 而报证书错 → 勾选 `allowInsecure: true`，或改成走域名 + 橙色云朵（此时看到的是 Cloudflare 的公共证书，无需跳过验证）。
